# 政策智能服务 v1.3：改进点与检查清单

日期：2026-09-03。对应 [PRD v1.3](Otto-政策智能服务-PRD-v1.3-修订版.md)。本次纳入仓库交付；提交与推送结果以 Git 记录为准。未部署生产服务器、未发布安装包。

## 推送前复查补丁

- 修复推荐队列：已经解读的已截止、参考类等不可诊断政策不再占用单轮 8 项模型工作名额，避免挡住后面的有效政策。
- 修复截止时间竞态：模型返回后再次校验申报窗口和效力，跨过截止时间的结果不保存为新诊断。
- 修复旧规则升级残留：重新解读不继承未被新版原文核验的旧日期、常年受理、效力变更及金额规则。
- 修复客户端与服务端时间分类不一致：倒置日期、无效日期、未来废止与既有失效时间、截止日最后一秒等边界增加一致性回归。
- 增加分析中删除诊断的并发测试，确认旧回答不会把已删除记录重新写回。以上均先增加回归测试，再修复实际失败用例；删除并发原有实现已通过，无需改动。

## 先检查这 7 处

| 到哪里检查 | 这次的变化 | 应看到的结果 |
| --- | --- | --- |
| 右侧“政策智能服务”→ 企业资料、来源覆盖、类型 | 保留全国企业适用及可扩展分类，不退回北京/昌平和固定五类 | 注册地按省/市/区县匹配；未接入来源明确提示，不能套用其他城市 |
| 政策卡片 → 条件与材料 → 排除条款与例外 | 新增独立排除核验，支持适用对象、例外和指定申报路径 | 显示原文；未知不是不符合；一条路径被排除不影响其他满足的 OR 路径 |
| 诊断摘要及三个列表标签 | 分清本批次“不满足”“未知”和未来准备 | 不能把收入不足等必需条件失败放进“提前准备”；未知显示待补充/待核实 |
| 政策详情 → 文件效力、申报窗口；顶部变更提示 | 效力和申报时间分开，原文/规则/资料变化使旧诊断过期 | 无有效期不显示永久有效；已废止/截止/失效不能继续诊断；旧诊断保留并提醒重新核验 |
| 诊断 → 支持内容/金额 | 有原文确定计算式时才估算，显示公式和依据 | 支持定额及比例/封顶；“最高金额”不当固定补助；资格或基数未知时不估算 |
| 详情 → 申报反馈与判断纠错 | 可保存、更新、删除本人申报结果与纠错线索 | 勾选确认后才保存；“名额不足”不会改资格规则；纠错显示待核实，不声称已安排人工 |
| 对话栏 → “有哪些政策”→“诊断第1项”→“同意诊断” | 对话共用排除结果、依据、提醒与字段类型 | 按题回答“是”“否”“不确定”；否是明确事实，不确定保持未知；与右侧读取同一诊断 |

## 建议按这个顺序验收

1. 先升级测试企业服务器与 Electron 客户端。新客户端要求服务器声明 `policy_intelligence_v3`；旧服务端会明确提示升级，不静默使用旧判断规则。新服务端仍保留 v2 能力标识供旧客户端识别。
2. 使用测试企业管理员开启服务并补齐所在地等基础信息。普通成员只浏览公共政策，不读取管理员的诊断、反馈或材料准备状态。
3. 在**隔离测试库**放入已核验的政策样例，勿把虚构样例写入生产公共库。至少覆盖：排除有例外、两个可选路径、收入门槛失败、资料未知、无有效期、已废止六种情况。
4. 做一次诊断，切换到对话继续回答，再回模块检查结果。答案默认仅本企业本账号留存；不要为测试输入真实敏感数据。
5. 记录“未通过 → 名额或额度不足”，保存并刷新；换同企业另一个管理员和另一企业账号，都不应看到这条个人反馈。删除后旧窗口的重复提交应报版本变化。
6. 修改测试政策的原文或结构化规则但保留同一政策 ID，刷新模块应出现旧诊断失效提示。更新资料同样使旧结果失效。

“部分条件失败”不能保证未来可补齐；本期提前准备仅表示已满足核验条件、等待明确批次开放，不承诺未来批次一定存在。

## 服务端实际变化

- `policyEligibility.ts`：有界排除规则、三态事实、适用范围/例外、最小模型输入、规则指纹、金额公式校验与估算。无动态执行代码。
- `policyModel.ts`：要求独立检查排除条款，在同一次语义分析中完成反向核验；不固定追加三次模型调用。引用、链接、日期、数字及比较方向均校验。别的文件被废止、征求意见稿或未来生效时间不能误作当前立即废止。
- `policyService.ts`：规则升级使缓存失效；旧解读可按新版重解；公共解读跨账号互斥。已确认排除/硬条件失败，以及待补全局排除事实时不调用诊断模型。无关备注和财务字段不发送给模型。
- `policyService.ts`：反馈按企业与账号加密隔离；并发版本校验、删除墓碑防旧请求复活；不接收客户端注入的政策归属/版本字段；反馈不触发模型或改写公共规则。
- `policySources.ts`：每源每轮最多 12 个新列表详情，加最多 4 个符合复查条件的历史条目。临近截止 14 天内且距离上次采集至少 12 小时、已有诊断且超过 1 天、其他历史超过 7 天时进入候选；已有诊断优先，其余按最久未查排序。有限预算轮询，**不保证每个历史文件恰好 7 天内完成复查**。
- 原文更新保存 `snapshot:<policyId>:<version>:<hash>`，保留最近 20 个正文版本；不含企业资料。不是完整网页/PDF 归档，也不是逐年批次关联图谱。
- 仍使用服务端 03:00/18:30 公共采集及每企业分析额度；不恢复客户端启动/退出重复抓取。

## 尚未交付，检查时不要误以为已有

- 真实付费模型效果评测、真实 PostgreSQL 集群故障/容量验收、线上部署和新版安装包。
- 全国省市区县网站全量适配、复杂附件解析、跨网页自动确认所有修订/废止关系、母文与多年度批次关联。
