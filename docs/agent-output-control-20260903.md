# Otto 输出控制与评测准备（2026-09-03）

后续跨轮修复与最新验证见 [跨轮任务与验收继承](agent-turn-continuation-20260903.md)。下文保留前序阶段的边界与实测记录，不应将历史界面测试终态当作最新的跨轮验收行为。

本轮只修改本地代码；不提交、不推送、不部署服务器，不读取现有用户模型密钥。保留同工作区其他任务的改动。

## 实际改动

1. `TurnDirectiveLedger` 将固定运行规则与当前验收状态分开。固定规则首次发送；未变化的状态不重复发送，变化时只补发对应部分。根据模型当前保留的用户角色文本核对指令；历史被压缩或替换时补发当前规则、状态和当前任务图，不恢复过期计划。该缓存不参与授权或验收，原生检查仍执行。
2. 可调用工具的轮次从第一个文本片段起就缓存模型正文，不发布 `chat_chunk`，也不把流式草稿写入可重载的会话历史。程序完成原生收口检查后才发布正式正文。仅明确 `toolFree=true` 且无需验收/计划的纯文本轮次保留流式输出。该发布边界不再依赖初始意图分类；不新增提示词或付费模型调用。
3. 有工具调用的中间说明明确标记为未验收，保留有内容的发现、链接；独立的笼统完成宣告不再展示。取消和异常路径同样不会原样发布尚未通过检查的草稿。原有工具卡与权限确认仍可实时使用。
4. `OttoChat.getUserTextHistory()` 提供只含用户角色文本的新数组，避免为去重检查深拷贝图片、工具输出等整段历史。不改变原有 `getHistory()` 行为。
5. 评测保留固定模型、数据与重复编号校验，并拒绝模型配置指纹缺失的比较。新增输入/输出 tokens、首次可见正文、验收前文本 chunk 数、耗时、用户介入和费用的前后差值；差值为逐任务配对平均值（after - before）。任一对应测量缺失，该指标差值为 `null`，不伪装成零成本/零等待。

## 明确边界

- 这是输出发布时机和执行可靠性修复，不是一个新的推理模型，也不证明测试断言充分。
- 不靠关键词去猜每句话是否真实。“验收前文本 chunk 数”只是暴露量指标，不是语义上的错误宣告次数。
- 简短指令被归为 `answer` 时，现在也不会在后续工具调用到来前发布草稿。不过这不等于已解决指令的语义理解或上一轮目标继承，也不能证明最终回答中的每条完成断言真实。
- 默认可调用工具的普通会话正文也会更晚出现；明确禁用工具的纯文本轮次仍流式。`firstVisibleTextMs` 应计入这个代价；它不是模型服务端 TTFT。工具事件与权限确认不受正文缓冲影响。
- 上下文检查负责补发原指令，不代表能验证压缩摘要的语义理解。
