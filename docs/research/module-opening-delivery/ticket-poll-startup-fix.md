# 本地启动请求风暴修复

2026-09-09，启动测试 App 时发现本地企业服务器超时。10 秒请求计数中 GET /enterprise/tickets 达到 7420 次。

原因：App 的工单会话通知 effect 依赖 useOttoStore 每次渲染新建的 actions 容器。界面后台状态更新导致 effect 重建，立即重新请求，绕过原有 8 秒轮询间隔。

修复：只依赖已通过 useCallback 稳定的 postLocalChatMessage 回调。保留会话切换、权限变化、通知投递和原轮询间隔。测试 mock 也改为每次返回新的 actions 容器，以符合真实 hook 行为。

验证：新增重复渲染回归先红（期望 1 次调用，实际 2 次）后绿；相关测试 23 项通过，完整桌面 219 文件、1691 项通过。renderer 类型、变更文件 lint、doctor、差异检查与 renderer 编译通过。实际 App 保留原数据重启后，连续观察的 10 秒窗口工单请求为 2–3 次，IPC 返回管理员身份及 mapConfigured=true。未声称长期稳定性验收。

App 已登录本地开发超级管理员，全部八项组织功能授权保持开启；未更改权限逻辑。保留用户当前分支已有 444d13ad 提交，修复仅本地提交，不推送，不打安装包。
