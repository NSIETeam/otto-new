# 智能招聘：统一分析复用、历史与 Token 记录

日期：2026-09-08。接续证据口径修正和自动保存；本轮是桌面分析链路的下一步，不是生产服务器持续招聘调度的完成声明。

## 本轮实现

- 手动简历、面试/实战、来源导入及对话分析继续使用同一主进程分析入口。相同账号、岗位、完整材料、企业上下文、规则版本和模型配置的并发请求合并；短期缓存命中返回原始结果，不新增模型调用。
- 每次请求重新读取当前模型设置。模型、路由、凭据、规则或输入变化后不能绕过检查复用。候选人内部 ID 不再发送给模型，不影响相同分析输入的复用；这不等于将不同人的档案自动合并。
- 缓存仅在当前桌面主进程内：最多 32 个结果、10 分钟有效期，最多同时执行 2 次分析。到期主动清理；会话变化及受保护接口的授权失效会清理。失败不进入成功缓存，账号切换后的迟到结果不写回。缓存不是跨设备或重启后的持久分析库。
- 规则版本为 `otto-recruitment-semantic-v3.2`。结果携带主进程生成的运行 ID、请求 ID、输入口径指纹、执行/复用标记和厂商返回的输入/输出 Token。模型 JSON 无权生成这些字段。凭据及私有缓存键不返回客户端。
- 工作台统一写入候选人时保存完整结果与当时的岗位、脱敏简历、面试及实战文字快照；来源重新读取、手动重新分析和对话更新均经过此处。旧结果转为待处理/失败状态时保留历史；复用同一次结果不生成重复版本。
- 每个候选人最多 20 个分析版本。达到上限在既有候选人的新分析前提示整理；底层再次校验，不静默删掉旧版。共享档案仍受原有单候选人 1 MB / 单岗位 6 MB 限制，大材料可能提前触发保存错误；本地修改保留，不假装已经共享。支持导出完整档案与历史，导出副本需用户自行保管/删除。本轮不提供自动裁剪历史或自动恢复外部导出。
- “分析历史与用量”默认收起。可查看各版完整结果和原文、前后摘要、证据状态变化及重算原因。变化说明来自输入和规则记录的比较，不额外调用模型，不宣称新版本更准确。
- 用量按实际运行 ID 去重，展示已知输入/输出计数；未返回的用量以及缺少新元数据的旧记录显示未知，不计作免费。失败、未写回的请求、转写、跨工作台/跨设备聚合、缓存命中定价及货币账单尚不在本地统计范围。没有声称“免费重试”或虚构费用。
- 人工逐项核实的绑定忽略本次请求/复用元数据：同一份分析再次展示，不使已有人工记录无故失效；材料、岗位或判断变化仍需要重新复核。

## 验收路径

1. 在智能招聘中输入岗位要求，授权并上传合成测试简历，打开“分析历史与用量”，核对本版材料、规则及厂商用量。
2. 短期内按原要求重新分析，应提示复用，不增加独立运行数。通过另一入口提交相同输入也走此规则；同名不同资料不能合并档案。
3. 修改岗位、企业标准、面试或实战内容，重新分析：新版本独立保存，旧文字和旧结果可回查。更换启用模型/模型配置后也必须重新检查，来源导入不能提前绕过主进程。
4. 模拟模型失败：原有历史保留，不能显示新的成功结果；失败 Token 不冒充 0。撤销授权或切换账号期间的旧结果不可写入新账号。
5. 在明确开启共享自动保存后完成以上步骤，由另一授权同事加载档案，历史应随候选人一起恢复。未开启共享时不静默上传；导出时明确个人信息和副本保留边界。
6. 已保存的人工证据核实记录在复用同一结果后仍有效，真正修改材料后显示旧核实记录待复核。

## 验证与边界

- `npx vitest run recruitment workable --reporter=dot`：25 个测试文件、160 项通过，覆盖缓存并发/到期/失败/隔离、模型及凭据变化、版本保留、未知用量、来源合同、共享恢复和 UI 交互。
- 桌面端 `npm run typecheck`、`npm run lint`、`npm run build` 通过；构建包含 main、preload 单文件校验与 renderer。
- 仓库 `doctor`、`git diff --check`、`code-map:check` 通过。

使用合成材料及模拟模型/授权连接器进行回归，不调用真实招聘平台或付费模型。这些测试只能证明受测代码行为，不能证明招聘判断的准确率、HR 节约时间或真实 Workable 账号已验收。

本轮尚未部署或推送。服务端定期收件、真实来源持续入档、模型预算账本/失败用量结算、真实 PostgreSQL 跨实例以及 Workable 企业账号联调继续列为后续工作；不会将桌面缓存定时清理说成“服务器自动招聘”。
