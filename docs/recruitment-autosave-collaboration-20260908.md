# 智能招聘：自动保存与候选人级协作

日期：2026-09-08。接续 `recruitment-evidence-comparison-20260908.md` 的证据表述和比较口径修正，本轮集中解决保存与多人协作，不宣称全部招聘路线已经交付。

## 本轮已实现

- 企业有效成员可以创建自己的共享岗位，创建者管理本岗位的协作者及删除操作；企业管理员仍可管理本企业岗位。普通协作者只能读取、更新被授权岗位，不能管理授权。旧岗位没有创建者字段时仍沿用原权限，不自动给历史更新者提权。
- 先明确候选人材料的共享范围，再点击“保存并开启自动保存”。本岗位后续候选人材料、分析、人工记录、进展及岗位要求变更会在约 800 毫秒防抖后保存。
- 自动保存由 App 持有，关闭招聘面板不会停止；对话与右侧工作台仍使用同一份账号隔离的 store。切换账号、加载另一个岗位、重置工作台、改变共享范围后需重新确认。
- 新服务器返回共享范围、岗位要求和每位候选人的版本标识。客户端只提交相对于上次确认版本发生变化的候选人；旧服务器保留手动整岗保存，不悄悄降级为自动整岗覆盖。
- 服务端对不同候选人进行乐观合并；同一候选人发生重叠修改、岗位要求或共享范围变更时拒绝过期写入。删除也是单候选人变更，不能凭旧版本复活已删除材料。
- 保存期间继续输入的本地改动不会被响应覆盖；没有变化的候选人保留对象引用，避免一次保存确认取消正在进行的来源分析。若响应中的远端变更与新输入冲突，不推进本地基准版本，不丢弃本地材料。
- 开启后每 30 秒检查一次同事更新，仅在本地已保存且没有请求进行时读取。没有更新只返回版本状态，不反复下载整份档案。同步本身不调用模型、不发送邀请、不回写外部 ATS。
- 断网、权限变化和冲突暂停自动保存，不无限重试。面板关闭时仍显示错误提醒。可导出本地材料用于人工核对，再加载服务器版本；导出包含个人信息，需要用户妥善保管。当前不提供该 JSON 副本的一键恢复或逐字段冲突编辑器。
- 本地到期清理会明确提交删除变更。模型写回前核对岗位与候选人版本；同事补充材料后，迟到的旧分析不能覆盖新内容。已经发出的模型请求可能仍计费，本轮未建立统一分析账本。

## 技术边界

候选人级更新是 API 与合并逻辑上的隔离。底层仍使用现有整岗位加密文档及 CAS 存储，并未迁移成每个候选人独立数据库行。不同候选人写入遇到 CAS 竞争最多内部重试 8 次；超出返回可见冲突，用户可重试。不承诺无限并发。

首次共享授权仅保存在本次客户端运行中；关闭整个 Otto 后停止保存，重新启动需要加载岗位并再次确认。没有离线持久化队列，也没有崩溃恢复承诺；退出前应确认已保存。暂停不能撤回已经发往服务器的请求。

删除的是服务器当前材料；其他人已导出的文件及服务器备份仍遵守各自保留策略。共享档案仍以结构化文档和提取正文为主，本轮未新增原始 PDF/视频托管。

## 验收步骤

1. 使用非管理员企业账号创建岗位、导入测试材料。未勾选共享确认前，保存按钮不可用，候选人不会因为打开模块而自动上传。
2. 确认共享范围并开启自动保存，修改候选人进展，观察待保存、保存中、已保存状态。关闭招聘面板后继续通过对话修改，重新打开检查保存状态。
3. 创建者选择本企业同事授权。第二位同事加载同一个岗位并开启自动保存。两人分别修改不同候选人，应保留双方修改；无更新的检查不增加岗位版本。
4. 两人基于同一版本修改同一候选人：后提交者应看到冲突和暂停提示，本地内容仍在。导出本地材料供核对后，显式确认替换才能加载服务器版本。
5. 在保存请求期间继续输入：响应只能确认已提交部分，新输入应继续显示待保存，随后进入下一批保存。
6. 撤销协作者、停用账号、改变共享范围、切换账号或加载其他岗位：旧请求不得写入新工作台，不应继续后台重试或扩大共享范围。
7. 删除或到期清除候选人，再保存并加载；该记录应移除，其他候选人保留。旧写入不得复活它。
8. 模型分析期间模拟同事更新该候选人材料：旧结果不写回，并提示使用最新内容重新分析。

## 验证记录

- 服务端招聘模块、企业 HTTP、集群路由回归：25 个测试文件，373 项通过。
- 上述实际 HTTP 测试另行复跑，覆盖新增的成员建岗、增量修改、跨企业拒绝及“无变化”响应；使用本地隔离数据库与测试账号，并非线上客户验收。
- 桌面端 `vitest run recruitment workable`：23 个文件，146 项通过，包括自动保存、增量合并、关闭面板后的保存、暂停、重试、删除及模型迟到写回防护。
- 模拟 20 个不同候选人同时写入，超过内部重试窗口的请求返回 409 后重试，最终 20 份修改均保留。仅用于正确性回归，不是生产容量压测数据。
- 桌面及服务端类型检查、两端 ESLint、两端构建通过；桌面构建包含 main、preload 单文件验证及 renderer 生产构建。
- `code-map`、`code-map:check`、`git diff --check` 通过。

这些测试验证代码行为，不证明招聘判断准确率，也不证明真实企业使用节省了多少时间。
