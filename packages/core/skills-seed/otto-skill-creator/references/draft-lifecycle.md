# Otto Skill 草稿、安装与专家孵化

本文件说明自动发现和主动需求共用的受控状态机。只有实现或诊断候选闭环时读取。

## 状态机

```text
主动需求 / 重复工作证据
          ↓
隔离草稿 ~/.otto-user/skill-drafts/pending/<candidate-id>/
          ↓
结构校验 → 静态测试 → 权限/风险分析 → .otto-skill 打包
          ↓
桌面“Skill 草稿与候选”人工确认
          ↓
内容哈希复核 → 个人目录原子安装 → 专家 Profile 孵化
          ↓
首次 use_skill：依赖预检 → 单独执行授权
```

任何校验失败都停在草稿态。拒绝候选不得安装；草稿内容在确认前改变时，原确认失效。

## 草稿清单必须展示

- 来源：用户主动需求或后台自动发现；
- 目标 Skill 名称以及新建/增强模式；
- 将新增或更新的每个相对文件；
- 脚本文件列表；
- 推断的文件、网络、环境变量、外部进程和 Otto 工具权限；
- 安全风险与静态测试结果；
- 验证错误、警告和 `.otto-skill` 包位置。

脚本静态测试只检查结构、文本、JSON 和明显风险，不运行脚本、不导入脚本模块。真实行为测试必须由用户另行批准，并在隔离目录中运行。

## 安装边界

- 自动安装目标固定为 `~/.otto-user/skills/`；候选字段不能改变根目录。
- 名称与 `packages/core/skills-seed/` 中的内置 Skill 相同，或目标含 `.otto-builtin-skill.json`，直接拒绝。
- 新建候选遇到同名个人 Skill 时拒绝覆盖；只有证据明确的 `enhance` 候选可以再次确认更新。
- 安装前再次运行验证并比较草稿内容哈希。
- 使用临时目录准备完整结果，再原子换入目标；失败时恢复原目录。
- 安装只复制文件。依赖下载、脚本执行、账号登录、网络上传和专家运行都不是安装的一部分。

## 专家孵化

安装成功后复用 `generateProfilePipeline` 生成个人专家 `profile.json`。Profile 只根据 SKILL.md 生成名称、简介和系统指令；它不能在孵化阶段运行 Skill 脚本。若 LLM 不可用，使用只读模板回退，不影响已确认 Skill。
