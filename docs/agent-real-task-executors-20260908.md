# 六类真实任务执行器：实现与验收边界

本轮只改评测设施，不修改生产运行时、授权策略、服务器配置或用户数据。阶段 0、阶段 6 和 `stage7-experiment-20260908-003` 快照不被覆盖。执行顺序是代码修复 → 文件交付 → 纠偏/重启 → GUI/企业流程。

## 实际接入点

| 类别                      | 实际产品链路                                                                  | 独立判据                                                         | 当前边界                                                                        |
| ------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 登录重试、UTC 时间        | `CoreSessionRuntime` → 原生 `read_file/write_file/replace` → 实际临时文件     | 控制器目录中的隐藏测试、真实 Node 子进程、修复前后哈希和支付回归 | 模型脚本只验证设施；不是 AI 修复成功率                                          |
| PPT、PPT+PDF              | 同一运行时 → 原生 `generate_document` 及原约束门控                            | 文件解析、页数/内容、当前哈希、损坏副本负向检查                  | 若门控阻止生成则记录失败，不绕过；解析不等于点击/原版式预览                     |
| 停改后端、PPT 改 PDF      | 在实际工具回执触发 `runtime.steer`，记录应用事件与其后执行中的工具            | 前后文件哈希、时间线、实际本地 HTTP 收件端计数                   | 收件端不是去重服务；缺少纠偏已应用事件不能通过                                  |
| 已收到回执/结果未知后重启 | 两个独立 OS 进程、稳定产品 sessionId、`FileTurnRecoveryStore`、真实 HTTP 请求 | 中断前原始持久化记录、PID/退出、收件端计数、原生复用/核对事件    | 前置失败不算重启成功；`继续。`与复杂追加指令不能互相替代                        |
| 消息读完后返回、移除项目  | `ProductDesktopDriver` 操作真实 Electron 页面，点击实际导航/会话/项目菜单     | 截图、独立只读数据库查询、文件/历史会话保留、持久化偏好          | 驱动已写，完整隔离桌面构建/登录/E2EE 数据准备和启动器未接通，当前标记 `not_run` |
| 工单回复、企业资料权限    | 真实企业 HTTP Server + 独立 SQLite + 临时签名测试许可证 + 隔离租户            | 实际 API 状态/响应、独立 DB 查询、跨租户拒绝                     | API 测试不冒充用户点击；报修双客服回复仍有产品失败，消息展示待 GUI              |

## 防止评测“假通过”

- `EvidenceJournal` 在模型工作目录外保存证据，逐个 `wx` 写入，SHA-256 绑定；重复、篡改、越界和无关检查被拒绝。
- 观察缺失为 `null`，不能把“没记录到错误”当成通过；产品 `completed` 与独立判据分开存。
- 原生工具名和实现类、用户输入、实际执行参数、确认记录、运行事件都有留存。
- 隐藏测试在工作目录以外的控制器目录中。脚本模型仅发出固定目录内的读取和修改，只开放固定公开检查工具；无 shell 任意执行、下载依赖或执行候选项目脚本权限。但原生 `read_file` 支持读取外部文件，目录分离本身不是安全隔离，因此任意真实模型入口暂时硬阻止，等待接通受限进程。
- Node 子进程权限限制、VM 禁止 require/process/动态代码生成、执行超时一起使用；不宣称 VM 本身是抵御所有恶意代码的安全沙箱。
- 新 Vitest 配置 **不继承现有会 mock `fs.appendFileSync` 的 setup**，不使用 `vi.mock` 替换运行时/DB/API/窗口桥接。
- GUI 预检需要源指纹一致的 main/preload/renderer 文件哈希；当前混合时间的本地 `dist` 不予接受。驱动禁止接入非隔离 profile。
- 正文检查读取真实富消息中的文本片段；空正文是未知，而非“不裸露路径通过”。
- 重启恢复按原生工具结果判断复用回执，按原生错误码或原生 `turn-reconciliation-required` 待确认通知判断需要核对，不靠模型说“请核对”判通过。
- 外部应用监测必须覆盖全窗口生命周期，并同时观察 OS 进程启动与外部打开请求（已运行 WPS 可能不产生新进程）。这部分尚未实现，不能因截图在 Otto 里就判通过。

## 如何复现

先封存当前完整已跟踪和未提交源码，不只保存 HEAD：

```powershell
node scripts/agent-eval-baseline.mjs freeze D:/otto/agent-baselines/<新的快照目录>
node scripts/run-agent-real-tasks.mjs D:/otto/agent-baselines/<新的快照目录> D:/otto/otto-push-20260901
```

第二个命令仅为**脚本模型设施运行**，不会调用付费模型；可在结尾指定 caseId 子集。它从快照恢复到新的运行目录，以源码别名使用真实产品模块，复用第三方依赖时核对锁文件和包元数据，报告这一依赖证据的局限，不用于版本前后因果比较。

每次结果输出到 `<快照>/real-task-runs/infrastructure-*/results`，含输入协议、源码/实验指纹、每项证据、完整报告和报告哈希。运行中源码或依赖元数据改变会在报告中标出；不得据此发布。收集器的 Vitest 通过/退出码 0 只代表成功收集，不代表业务通过。GUI 缺失和执行异常各自形成终态记录。

局部设施检查：

```powershell
node node_modules/vitest/vitest.mjs run --config scripts/agent-real-tasks.vitest.config.mjs
node node_modules/typescript/bin/tsc --noEmit -p packages/evals/tsconfig.json
```

`continuity.scenario.test.ts` 包含真正需要达到崩溃点的恢复正向断言，产品未达到检查点时应报红，不得降低为“脚本结束即通过”。

## 已观察到的问题（不是已经修复）

1. “不要打开外部软件”的文件任务会被现有约束门控阻止调用 `generate_document`。测试必须保留这条原约束与失败，不得放开执行权限换取绿灯。
2. 物业报修普通 `respond` 操作返回 400，要求“回复并转交工程部”；原合同中的两名客服分别普通回复没有成功。
3. 已出现恢复记录写入的 Windows `EPERM`，导致未发送请求就结束；这不构成重启试验。已另有结果未知的真实中断试验观测到只发送一次。
4. `继续。`与“继续上次任务。不要重复发送……”进入的恢复路径不同；支持简短恢复不代表长指令纠偏也通过。

## 本阶段尚不能宣告全部完成

必须继续接通：与源码一致的隔离完整 Electron 构建/启动、真实 E2EE 消息/会话种子、GUI 三类入口的运行、全生命周期外部打开监测、真实模型的批量授权/预算/进程控制入口。

`executeRuntimeTask` 保留固定模型预检和共享预算准入设计，但原生外部读取未受限之前，由 `requireRealModelConfinement` 硬阻止付费/任意模型执行，不能用环境变量或虚假的隔离声明绕过。本轮未提供、未使用模型凭据。统一运行器和重启进程入口仅接受回环脚本模型。企业 API 独立结果、设施测试数、GUI 驱动代码均不能计入固定模型前后成绩。

第一次设施运行 `stage7-real-executors-20260908-001` 的未知结果重启评分器只认错误事件，遗漏了实际原生待确认通知，产生假阴性。修正后必须新建快照与结果，不覆盖该原记录；只承认原生通知，不放宽为模型正文匹配。

完成这些并修复实际失败后，才能进入固定模型 A/B、人工复核和小范围灰度。当前 `productionReleaseAllowed=false`。
