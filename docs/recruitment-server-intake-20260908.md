# 智能招聘：服务端持续接收与待处理箱

同日后续：已有受控后台分析及独立授权的[结果自动正式入档](recruitment-auto-archive-20260908.md)。本文“只进待处理箱、需手动保存”的描述是接收功能单独开启时的边界，不再代表同时开启分析和自动入档后的流程。

日期：2026-09-08。本轮接续证据/比较口径、自动保存、统一分析版本与用量记录，完成“服务端定时接收 → 共享待处理箱 → 桌面全文分析”第一版。不是全部招聘渠道或后台付费分析的完成声明。

## 用户能检查到的变化

1. 智能招聘原入口不变。保存或加载共享岗位后，打开“后台接收简历”。岗位创建者和企业管理员可明确确认后台读取、保存期限和共享范围后开启；协作者可以处理已共享材料，但不能替负责人开启任务。
2. 首批仅支持经过真实账号验收、当前操作者本人已授权到该岗位的 Workable 企业人才库。没有授权或仍待验收时，服务器拒绝开启，不显示虚假的可用状态。
3. 可选择每 30 分钟、1 小时、6 小时或每天接收，单轮最多 5/10/20 份，待处理保存 7/30/90 天。显示开启/暂停、下次计划时间、待处理数量及最近 10 轮运行结果。默认关闭。
4. 开启后由企业服务器执行，不依赖桌面窗口或员工电脑持续运行。资料进入岗位的加密待处理箱，不自动变成“已分析候选人”，也不自动评分、淘汰、录用或联系候选人。
5. 完整正文和部分材料分别显示。用户确认分析授权后点击“导入工作台并分析”，先重新核查服务器岗位权限与期限，再复用原有全文分析/历史/Token 记录流程。部分材料仅入档，不调用模型。模块和对话可以继续处理同一候选人档案。
6. 导入不会自动删除待处理副本。先通过已开启的自动保存或“保存当前岗位”确认档案共享成功，再明确移除待处理副本；移除不会删除已导入的候选人或历史记录。没有开启自动保存时，仍需手动保存分析结果。当前后台任务不替用户完成这一步。

## 工程与权限边界

- SQLite 与 PostgreSQL 主机的正式启动路径注册 `enterprise.recruitment-material-intake`，与临时缓存清理分开。健康检查 canary 不执行任务，停服取消接收并等待已有工作退出。
- 任务参数、游标、租约、运行记录与去重标记持久化；任务重启能继续。按企业/岗位扫描加密元数据，单轮扫描最多 50 个岗位、执行最多 2 个到期任务；不是无限并发队列。多租户规模增大后需压测调度延迟并改造索引队列。界面计划时间不是严格开始时间保证。
- 单任务 2 分钟截止、3 分钟租约，岗位 CAS 提交与租约 ID 防止并发重复读取/旧实例覆盖。持续读取前后复查账号、岗位所有权、共享范围、岗位要求、许可证和来源授权；暂停、删除、重新配置优先于迟到结果。资料入档时合并最新岗位，而非覆盖同事候选人修改。
- 检索游标按任务保存，不继承其他岗位的通用来源游标。达到来源最后一页后，下轮从首页重新检查。要发现正文变化仍可能重新读取来源，不能把去重宣传成“没有任何上游请求”。
- 去重使用来源记录、正文、完整度和原文件摘要，不使用姓名，也不被每轮获取时间干扰。新正文独立保留，不静默覆盖旧待处理版本。去重标记最长到对应保留期，移除/到期后不是永久屏蔽该候选人；以后重新检索可能再次接收。
- 每岗位最多 100 份待处理资料，500 个限期去重标记；候选人档案与待处理箱共用约 5.9 MB 的服务端序列化容量门槛。容量、授权、限流或读取失败时显示暂停/部分成功，不假报全量完成。单岗位资料量大时应后续改用独立材料对象存储。
- 当前保存的是提取正文、来源及附件摘要，不是原始 PDF 二进制托管。活动库中的到期待处理正文由后台清理，读取接口也过滤到期副本；备份、人工导出、已导入正式候选人的各自保留策略不因此自动改变。
- 后台不调用付费模型。用户点击完整材料分析时仍走既有模型计费/复用边界；来源平台本身的 API 或订阅费用不包含在“没有后台模型 Token”中。本轮没有自动分析预算账本、招聘邮箱、投递页、邀请发送、回复同步或 ATS 回写。
- 后台错误与审计只写固定状态和关联 ID，不记录私有简历 URL、OAuth 凭据或原始上游异常。

## 兼容及发布要求

- 新增能力标识 `recruitment_intake_v1`；桌面在配置/移除操作前检查服务器能力。旧服务器保持手动招聘可用，不能伪装成支持后台接收。
- 既有岗位的加密候选人数组仍可读取。有待处理箱的新数据使用同一加密列的版本兼容载荷封装；**旧服务器不能读取此新封装**。部署须先升级全部读写实例，再让用户开启本功能；不要在新旧服务混跑时启用，也不要直接回退旧二进制。需要回退时先暂停、备份、人工确认并迁移新载荷。本轮没有执行迁移或生产部署。
- 未修改许可证策略、未替客户授权、未设置真实账号验收环境变量。必须由真实企业账号完成授权、检索、正文获取、入档、分析及撤销联调，才可判为该账号可交付。
- PostgreSQL SQL 合同测试使用 SQLite 执行器验证参数和存取逻辑，不是实际 PostgreSQL 多实例/故障切换验收。

## 验收检查表

1. 未保存岗位、未确认后台共享、非管理协作者、旧服务器、未验收 Workable 均不能开启。
2. 合成/授权测试材料通过来源接收后在待处理箱可见：来源、完整度、期限、数量及本轮状态一致，不出现“已经验证能力”。
3. 关闭桌面，仅保留测试服务器运行；任务仍接收。重新登录并加载共享岗位/刷新待处理箱可以查看，再导入已有分析。
4. 同内容重复同步不重复入箱；改正文保留新版本。多实例同时抢占同一岗位只执行一次；暂停或删除期间返回的旧结果不可写回。
5. 账号禁用、许可证失效、岗位要求或共享范围变化后停止读取。其他企业及未授权同事不可访问；恢复前重新确认配置。
6. 部分/无法读取资料不伪造全文分析；来源失败、容量满时保留可用的已授权资料并明确暂停。后台记录无原文和凭据。
7. 过期副本在暂停情况下也清理；导入与移除独立。保存失败或工作台切换不丢失待处理材料，不覆盖本地修改。

测试使用合成材料、模拟模型/来源和隔离本地数据库，未调用真实招聘平台、未发送邀请。代码与行为测试不能证明招聘判断准确率或 HR 实际节省时间；真实账号、真实数据库并发和质量评测仍待验收。

## 本轮验证结果

- 服务端招聘模块：24 个测试文件、235 项通过，包含 25 个并发工作器争抢同一岗位、任务重启/翻页、关闭服务器后恢复、用户暂停、删除、权限/许可证变化、到期清理及加密存取。
- 集群 HTTP 合同：41 项通过；这是模拟仓库测试，不是实际 PostgreSQL 部署验收。
- 本地 HTTP 与常驻任务：新增端到端接收及相关生命周期定向回归 8 项通过（同文件其余 99 项未在该定向命令中执行）；此前完整 HTTP 文件 106 项通过。
- 桌面招聘、对话、共享档案、分析和企业客户端：26 个文件、244 项通过。
- 两个包的类型检查和完整构建通过，桌面包含 main、preload 单文件校验与 renderer；仓库 lint、doctor、diff 检查和 code-map 检查通过。

本轮代码仍在本地 `internal` 工作区，未提交/推送或部署；没有将混杂的其他未提交改动一起发布。
