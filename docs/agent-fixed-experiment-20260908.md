## 实验目录与身份

使用 `scripts/prepare-agent-live-pair.mjs` 的 `--common-dependencies` 模式，新目录包含：

```text
experiment/
  preparation.json + preparation.sha256   实验身份、条件、阻断项
  evaluator/                              完整当前评测器工作树快照
  before/                                 旧版源码 + 明确记录的依赖声明覆盖
  after/                                  新版源码 + 相同依赖声明
  dependencies/
    manifest.json + manifest.sha256       每个依赖文件的字节数和 SHA-256
    payload/                              私有依赖文件、Node 二进制及包清单
```

- 原始源码哈希、原始 manifest 哈希、依赖参照版本、每个覆盖文件的新旧哈希单独保留在 derivation 中。旧版副本业务代码不替换成新版业务代码。
- 当前评测器同样捕获完整工作树，包括未提交/未跟踪源码；忽略生成物、用户数据和凭据文件，沿用阶段 0 规则。捕获期间发生修改则拒绝封存；失败目录保留，不能当成有效实验。
- 实验哈希绑定双方实际源码指纹、共同依赖字节指纹、完整评测器指纹、数据集、评分规则、模型/端点/计价/费用声明、执行上限、重复次数和交错运行顺序。源码、工具或评分变了必须创建新目录；任何旧准备结果不得覆盖。
- 公共模型字段允许未就绪时为 `null`，这不是已固定真实模型。密钥不写入 manifest，原始端点只保存哈希；后续模型或费用发生变化，也必须新建实验身份。

## 实际依赖固定方式

依赖是独立物理副本，不是指向当前工作树的 node_modules 联接。复制中核对内容哈希、拒绝未知链接；只排除 npm 明确声明的本项目 workspace 链接，并记录必须由运行器绑定到对应冻结 TS 源码。依赖树、嵌套依赖、Node 二进制都登记字节哈希。

这比仅记录 package.json 版本更严格，但不是一台虚拟机：操作系统、系统组件和外部服务不被打包；原本未安装的可选依赖不会自动补齐。没有执行 npm install、安装脚本或原生重编译。依赖副本仅供本地受控实验，不推入 Git，也不作为安装包内容。

`verifyPair()` 核查双方、原始快照、评测器和依赖字节及本机运行条件。`assertPairReady()` 额外拒绝尚未具备真实运行条件或模型/费用发生变化的实验。两者不是对恶意同权限进程的防篡改沙箱，也不是操作系统级不可写锁；实际执行器下一步还需接入开始/结束校验及结果身份绑定。
