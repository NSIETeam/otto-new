# 对话式园区办事：语义理解、多事项与异常恢复

更新日期：2026-09-08。此文描述本轮本地代码，不代表已经发布或完成真实企业环境验收。

## 用户能看到的变化

- 复杂表达经当前配置的大模型提取事项与字段，例如中文数量、明确的相对日期时间、口语故障描述。常用模块名称、确认/取消、明确的“字段：内容”由本地直接处理。
- 一句话最多识别四项事务。申请逐项准备，完整后展示摘要，再由用户单独确认。确认当前报修不会同时确认下一项电卡或会议室申请。
- 申请未完成时可以穿插查询公告、统计、合作线索、我的申请、园区待办；查询不再被当作报修描述。
- 可说“查看办事清单”“继续办理”“取消后续事项”。后续事项不覆盖当前草稿；准备失败后可以继续，无需重新理解同一待办。
- 追问保留原需求和最多两次补充，可直接回答“下午”等短句；这些上下文同样加密保存并在 30 分钟后过期。切换话题不会把追问当成授权，草稿变化后旧追问停止。达到长度或轮数上限时明确提示重新描述。
- 可说“取消后续第2项”（或中文序号）只移除该项，不取消当前草稿或已提交工单。“取消追问”只放弃尚未理解完成的需求。
- 当前草稿的业务字段可作为有限上下文供模型理解“再加两个人”等增量纠正；不附带账号身份、资源 ID 或价格。此类计算仍需用户核对摘要。
- 账户、企业服务器及会话范围隔离；当前草稿和后续待办通过现有 Electron 加密草稿库恢复，保留期为 30 分钟。切换账号、会话或停用能力后，未完成的理解结果不能继续修改或提交。

示例检查路径：

1. 输入“顶灯一直闪，不着急；再给电卡充两百度”。
2. 检查报修类别、故障和紧急程度摘要，确认未发生真实提交；电卡显示为后续待办。
3. 输入“查看园区公告”，检查原报修草稿未被改写。
4. 确认报修后，查看返回的工单信息和下一项电卡摘要；此时电卡仍未提交。
5. 再次明确确认，才提交电卡申请。

例子是人工验收输入，不是声称已经用真实模型、真实企业工单完成的演示。

## 安全与恢复

- 模型只能返回白名单意图、字段及对应原话片段，不能返回提交、取消、执行工具或免确认授权。整份输出通过校验后才采用，含不确定问题时先追问，不执行其中一部分。
- 字段使用右侧表单的同一 Schema，校验选项、数字范围、真实日期、时间及车牌格式。模型无权改公司、账号联系方式、房间档案、资源 ID、价格或资源可用性；基础档案缺失时仍需完善企业资料。
- 模型提供的字段仍可能理解错误；原话引用只证明来源，不证明理解一定正确。真实操作前须核对摘要。语义规划路径不采用旧报修路径的“直接提交”标记。
- 同时有多个草稿时，“确认”“可以提交”“取消”等通用指令不猜目标，需在草稿卡片选择具体事项；不支持一句“全部提交”。
- 提交前先加密保存原请求。发生超时或断网后，可能已被服务器接收的请求保持原内容、原幂等键；不能改字段后混作同一请求重发。用户可查看“我的申请”核对，或明确确认后按原请求重试。
- 此时“取消”仅停止本地重试，不能宣称撤销了服务器工单。没有接收人信息时不伪造派送成功。
- 会议室提交前可用性复核失败会保留草稿并明确告知，不再抛出未处理异常。真实资源冲突、权限和许可证仍由服务器最终校验。
- 会议室资源、容量或计费信息变化后，显示新摘要，必须再次确认；旧确认不会授权变化后的预约。每次确认只做一次最终资源复核。
- 理解超时或断网时保留尚未执行的原话，可明确回复“继续办理”重试理解（这一步会调用模型），不会自动重试或直接提交。相对日期保留原需求的时间基准；撤销、确认与模型引用的文字严格分开。
- 草稿 ID 使用独立随机 ID，避免相同毫秒连续建单时旧卡片的确认误指向新草稿。

## 模型消耗与范围

- 本轮语义升级覆盖物业报修、装修、停车、网络固话、会议室、电卡、车辆访客、满意度调查，以及上述五类查询。
- 普通聊天仅在命中园区相关入口或存在当前园区草稿时可能进入语义判断；招聘、政策、拼车的独立请求继续交由原模块。它们尚未纳入统一多事项队列，跨这些模块的混合办理仍应拆开。
- 复杂表达每轮最多发起一次理解调用，不附加整个聊天历史、企业知识库或账号资料；本轮及追问原话合计最多 6000 字符，当前草稿业务上下文额外限 8000 字符，2048 输出 token，15 秒超时，不自动重试。确认、取消、清单管理和已识别待办的继续准备不增加理解调用；明确单事项字段填写也走本地路径。
- 并发相同理解请求合并；每个会话的办理过程串行。模型费用仍取决于配置，不能理解为零 token 成本或企业统一费用账本已覆盖该功能。
- 模型不可用或格式不合格时不降级猜测真实操作；草稿和待办保留，可继续重试准备或使用右侧表单。原话引用校验不能替代真实口语准确率测试。
