# 阶段 0 补齐：完整源码与可追溯实验登记

本轮只修改本地评测基础设施、生成新的本机快照和实验包。不改产品业务、不启动 Otto、不调用模型、不推送、不部署。源码和模型效果是两个不同的验收层级。

## 本次补齐

1. **完整候选版**：用工作树真实字节重新封存，不复用阶段 6 或较早阶段 7 的候选指纹。纳入所有未提交、非忽略的未跟踪源码；排除凭据、用户状态、构建和缓存。捕获中发生变化就拒绝，不生成可用清单。旧快照不覆盖。
2. **公开配置与执行权限分离**：`liveEvalPreflight().declaration` 保存模型、固定修订、端点哈希、价格、总预算和每例预留。未填项保持 null；即使尚未提供密钥和执行许可，也能固定已填写的公开参数。密钥、原始端点不写入清单。执行前仍须经过原有许可、账户硬上限确认和预算检查。
3. **固定运行清单**：六类、每类至少两项，当前 12 项任务预先登记新旧交错的 24 个位置。每项有实验 ID、源码指纹、case、variant、repeat。重复配置必须实际展开，超过批次上限直接拒绝。清单不作为成绩文件；耗时、费用、用量、独立判分和四类用户交互计数初始均为 null。
4. **防止实验身份错配**：校验计划和身份、任务合同、历史反例登记、逐文件差异及初始运行位置。不接受只改校验和就把初始位置改成“通过”。后续执行必须在新结果文件中保留失败、超时、未运行和缺用量。
5. **完整差异公开**：新旧源码的每个新增、修改、删除及两侧哈希纳入报告。原生工具/策略/注册代码按双方分别绑定，外部评测适配器另绑指纹。由于期间存在其他模块变动，明确这是**完整产品版本比较，不是纯运行时优化的因果实验**。
6. **固定历史风险及盲区**：`stage0-failure-register-v1.json` 登记 10 组历史风险、对应任务和所需独立证据。它不是当前候选的失败结果；另注明 12 项试点尚未充分覆盖引用可信度、隐含语义、超长压缩和自然表达，不能借试点宣称这些阶段已验收。

## 依赖和旧版的含义

沿用已经审查的共同依赖声明方案，在新实验目录创建独立副本，保留原阶段 0 与阶段 6 快照。只有 package 依赖声明和 npm dev 归属的兼容差异允许派生；实际版本、来源、完整性或业务脚本变化不能偷偷归一化。

实际安装依赖和 Node 二进制做独立字节归档，逐文件校验，不用开发树的 node_modules 联接冒充固定环境。OS、外部服务、GUI 登录态和模型服务端实际修订不因此被冻结；版本字符串只表示声明，不能替代提供方实际版本核对。

## 验证命令

在源码根目录执行：

```powershell
node node_modules/vitest/vitest.mjs run --config scripts/agent-stage0-seal.vitest.config.mjs
npm.cmd run typecheck --workspace=packages/evals
node scripts/agent-eval-baseline.mjs freeze D:/otto/agent-baselines/stage0-candidate-NEW
node scripts/prepare-agent-live-pair.mjs D:/otto/agent-baselines/stage0-20260908-003 D:/otto/agent-baselines/stage0-candidate-NEW D:/otto/agent-baselines/stage0-pair-NEW --common-dependencies D:/otto/otto-push-20260901
node scripts/prepare-agent-live-pair.mjs verify D:/otto/agent-baselines/stage0-pair-NEW
```

所有 NEW 目录必须不存在。schema 3 新登记包含 `run-slots.json`；原 schema 2 实验继续只读校验，不原地迁移。清单哈希是误改检测，不是对恶意同权限进程的数字签名或操作系统隔离。

若依赖归档已经成功、但后续源码派生失败，可用 `--sealed-dependencies` 指向该归档目录。入口会重新校验全部依赖字节和环境，报告保留绝对引用及指纹，不删除旧目录、不重新复制同一 GB 级文件集。搬运实验时必须连同该引用和原始快照一起保留。

本轮发现：当前 server 包清单还含业务导出变化，直接从原阶段 0 向当前包清单派生会被拒绝。不能关闭这个检查；应以先前已审查、已固定共同依赖的旧版副本为 before，继续保存其到原阶段 0 的派生来源，不将新版业务导出覆盖给旧版。

## 完成边界

实际目录、指纹和校验结果以本机实验目录的 `preparation.json`、`manifest.json` 和外部验收记录为准。不得把这份设计说明当成已经完成封存的回执。

尚未得到用户选定的固定模型修订、费率、总费用和每例预算，不能替用户填值。账户密钥和调用许可不应写进普通 JSON。本轮不会为了让准备报告变绿而关闭真实模型的隔离拒绝：六类双版本真实执行器、文件读取隔离、完整 GUI 环境仍未达到准入条件。

因此可以完成“当前源码、依赖、评分、任务与缺项的可复核登记”，不能宣称阶段 0 全部验收或阶段 7 已有真实成绩。实际对照开始前还须封存最终配置，并验证具体工具范围、请求参数及提供方版本的一致性；有任何条件改变必须新开实验，不覆盖历史结果。
