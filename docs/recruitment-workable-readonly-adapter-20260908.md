# 智能招聘：Workable 官方 MCP 只读适配第一版

日期：2026-09-08。工作目录：`D:/otto/otto-push-20260901`；分支：`internal`。

后续附件提取进展见 [简历附件读取与分析衔接](recruitment-workable-resume-extraction-20260908.md)。下文保留第一版交付时的范围和测试记录，不能将旧版“未读取附件”的说明视为后续实现状态。

接续共享岗位与跨岗位候选人功能。本轮完成的是首个平台的只读适配层和客户端范围提示，不是六阶段路线全部完成，也不是 Workable 真实账号已经接通。

## 用户可见的变化

1. 候选人来源中心增加 Workable，默认显示“待授权与验收”。发现同名 MCP 或三个工具名称都存在，也不会直接开放招聘数据访问。
2. 企业部署批准后显示“可读取绑定岗位”。对话与右侧模块均说明实际范围：当前绑定的 Workable 岗位、当前返回批次；不是全站人才搜索，也没有按自由文本在平台筛选。岗位匹配分析属于之后的材料分析环节。
3. 已保存共享岗位使用稳定的岗位 ID；对话和模块不再每次检索随机换一个岗位编号。未保存的本地目标有临时编号，不能因此获得企业岗位授权。
4. 切换到另一个同名、同描述的岗位时，旧请求结果也会被丢弃，不进入新岗位工作区。
5. Workable 资料摘要标记为部分材料，现有材料导入桥不会据此调用全文分析模型或声称“完整分析完成”。没有可用正文时要求补充材料。

## 已实现的服务端路径

`企业来源运行时 → Workable 只读适配器 → 岗位与账号授权解析 → 官方 MCP JSON 请求 → 结果规范化 → 既有检索记录及材料读取接口`

- `workableMcpSession.ts`：固定官方端点、初始化和版本协商、工具 Schema 发现、工具分页、读取调用、响应大小限制和错误脱敏。只适配 Workable 文档所述无状态 JSON 传输；不是任意 MCP 服务器通用客户端。
- `workableRecruitmentAdapter.ts`：先核对授权账号，再读取绑定岗位候选人、获取指定候选人资料。使用实时发现的 Schema，只接受已审核的字段映射；未知必填参数、重复工具、歧义映射与不支持的响应格式均明确失败。
- 默认生产注册入口：`createWorkableRecruitmentRegistration`。没有真实验收批准记录时 `productionEnabled=false`。它可通过现有 `createRecruitmentSourceRuntime` 和企业服务器的 `recruitmentSources` 选项组合，不修改运行时内核，也不自动写入部署配置。
- 候选人记录和游标绑定组织、操作账号、Otto 岗位、Workable 账号/岗位及绑定版本。解析器不直接请求平台返回的分页 URL，仅提取经过范围校验的游标。
- 每次网络请求前后重新确认授权；撤销或更改绑定后丢弃在途结果。详情返回其他候选人、或明确显示已调往另一个岗位时拒绝入档。
- 只开放候选人读取；不会调用联系、录用、拒绝、复制到平台岗位、发布职位等写入工具。
- HTTP 凭据只发送至固定官方端点，拒绝重定向，不将令牌、简历签名 URL 或原始上游错误输出到列表、日志或用户消息中。

## 尚未完成，不能对外宣称已接通

- 没有真实 Workable 企业账户授权和联调，测试使用合成数据。工具参数、响应封装及分页契约仍须用真实账号逐项确认；不支持的形状会拒绝而非猜测适配。
- 本轮没有新增企业 OAuth 登录界面、回调端点、令牌刷新调度、加密授权存储或岗位绑定管理界面。`resolveGrant(scope, signal)` 是部署方需要实现的安全授权代理接口：根据当前组织、用户、共享岗位权限取出已授权的凭据与岗位绑定；不得使用全局令牌、普通配置文件或模型给出的账号/岗位。
- 工厂与现有企业运行时的组合已测试，但当前启动配置尚未注入真实授权代理和 Workable 注册项，默认不能向真实平台检索。
- 本轮只读取候选人结构化资料中的姓名、职业概述、个人摘要。不会跟随 `resume_url` 下载附件；原始简历二进制托管、安全下载、PDF/Word 提取、全文分析的真实闭环仍待完成。没有把其他附件接口冒充简历正文。
- 没有实现 Workable 高级搜索三阶段协议；普通招聘目标不直接翻译成未经验证的平台过滤器。
- 没有自动遍历整个企业人才库、持续收件、邮箱/推荐/投递页、多平台写回或候选人触达。
- 当前企业账号中没有已绑定岗位时，应先保存共享岗位并完成授权绑定；不能自动挑第一个 Workable 账号或跨岗位搜索。

## 部署组合约束

注册入口需要的授权数据是 `WorkableOAuthGrant`：组织 ID、操作账号 ID、共享岗位 ID、账号 subdomain、岗位 shortcode、绑定修订号、有效期和访问令牌。网络层只在请求期间使用令牌，不提供持久化功能。

组合顺序：企业加密授权代理与岗位 ACL → `createWorkableRecruitmentRegistration({ resolveGrant })` → `createRecruitmentSourceRuntime({ registrations, authorizeSource, store, audit, auditMaterial })` → 企业服务器 `recruitmentSources`。

生产组合必须使用既有加密持久化来源仓库、组织/岗位权限检查和审计回调，不能照搬测试中的内存仓库或始终允许的授权桩。真实验收完成后才传入 `approval: { realAccountVerified: true, authorizationReference: ... }`；此标记不能代替每次访问时的实际授权检查。
