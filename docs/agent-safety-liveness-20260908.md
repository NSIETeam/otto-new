## 真实链路与测试分层

`scripts/agent-safety-liveness.vitest.config.mjs` 使用源码别名，**不加载伪造 fs 行为的公共测试 setup**。

- 规则测试：正向与反向输入成对，不能只验证拒绝。
- 实际 node:test：真实临时文件、真实测试进程、真实 TAP 回执和当前源码审查。
- 实际运行时：真实 Config → 本机 HTTP scripted provider → CoreSessionRuntime → 学习包装后的原生工具 → 临时工作目录。不是直接调用模拟业务函数。
- 文档用例同时尝试 shell 写入标记；该调用被拒绝，标记文件不存在。生成的 PPTX 内容另由 ZIP 解析器检查。
- 文档用例故意宣称“全部验收通过”，但没有充分的任务合同/内容验收证据；产品保持 `incomplete`，**该保护性测试通过不等于 PPT 整轮任务完成**。
- scripted provider 不是训练模型。没有付费模型调用，不计入真实模型成功率、耗时或成本比较。没有测试 Electron 点击预览、WPS 进程监控或生产企业流程。

运行：

```powershell
node node_modules/vitest/vitest.mjs run --config scripts/agent-safety-liveness.vitest.config.mjs
```

## 尚未闭环，不能通过放宽门禁解决

1. 受控入口目前仅支持新建纯文本 PPTX（最多 40 页，每页正文 2400 字符，文件最大 8 MB）；不覆盖旧文件，不承诺复杂图表/字体/版式质量。父目录需存在。
2. PDF、复杂模板和任意生成/测试脚本需要专门的受控适配器或可核实的隔离执行器。本轮没有把 `test/build/generate` 命令词当成授权，也没有解除真实模型评测的隔离门槛。
3. 原文件交付的内容与视觉验收仍保留。当前模型若只生成文件、没有获得要求的内容验证和预览证据，任务仍不能交付为“全部完成”。下一步应补受控的独立内容验证入口；不能拿生成器自报成功替代它。
4. 静态审查只是弱测试筛查，无法证明完整业务语义；未支持的辅助函数/动态参数化用例保留待审查及原因，不自动取消要求。
5. 修复仍限两批、每批最多四个文件，最多六次方案比较；不会为耗尽预算或新权限需求暗中扩大范围。正确结束应保留成果、具体缺项和阻塞原因。
6. 来源抓取时间与逐字绑定不证明发布者身份、事实正确或最新性。这些限制仍需诚实说明，但无需机械重复。
