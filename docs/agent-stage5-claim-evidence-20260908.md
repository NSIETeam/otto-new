# 阶段 5：结论—证据绑定与语义审查下限

本次仅修改本地源码、运行离线测试和保存完整源码基线。未推送、未部署、未发布安装包、未操作生产数据、未调用付费模型。

## 实现范围

1. **检索链接不再视为已验证事实。** 自动引用仍保留来源入口，但 `verified=false`。研究交付不再凭某个搜索/抓取工具成功放行。人工构造 citation 也不能代替结论审查。
2. **原始来源回执。** Core 的 `web_fetch` 新增 `evidence_only=true`：一次读取一个公开 HTML/文本/JSON，复用原有公开地址和跳转检查，不调用第二个模型。保存文本、SHA-256、原始 URI、抓取时间及截断标记。拒绝凭据型 URL、二进制内容和超过 1 MB 的响应；单份提取文本最多 12000 字符，截断不代表全文覆盖。只有实际原生 WebFetch 实现的元数据可以经执行器进入 Server；MCP 同名工具和结果正文不能冒充。
3. **结论—原文图。** Server `ClaimEvidenceLedger` 将结论绑定工具调用 ID、来源版本、UTF-16 段落偏移、原文片段、数值字段、主体/指标/期间/单位及抓取时间。支持明确归属于来源的原文引述、带不确定性标记的推断和证据不足说明。原文归属检查不是事实真伪认证。
4. **当前交付检查。** `review_answer_evidence` 审查拟交付正文，覆盖全部正文段落；实际正文、请求版本或已读取来源集合变化即失效。缺原文、越界偏移、凭空改写数字/年份/币种、缺链接、漏登记段落、同口径冲突和证据超限不能静默放行。取不到证据时保留成果和具体不确定性。补证可以在原有收尾循环中继续读取原生网页；审批、用户约束、预算均保留，不开第二个执行器。
5. **期间与权威性分开。** 抓取时间不是发布时间，域名也不自动等于官方发布者。请求指定年份时，证据须能对应期间；声称“最新/官方/一手”而缺少可信认证时，正文必须明确尚未核实时效或来源权威性。当前不会自动给网站签发官方身份。
6. **矛盾检查。** 检查全部已读取来源中的同结构数值差异，而非只检查模型挑选的有利引用；对直接的支持/不支持、启用/未启用等相反表述做保守冲突提示。冲突只能明确保留，不能用来源数量投票消除。
7. **测试源码审查。** 既有逐需求、逐场景、执行回执和版本检查之外，增加具名 JS/TS 测试源码 AST 审查。源码必须已经作为原生验证输入被观察，文件版本仍一致。识别空用例、恒真断言、注释中的假断言、被跳过的测试组、不可达/条件分支中的断言、吞异常以及未等待的异步断言。缺源码、无法唯一定位、动态/不支持语法和超限保留 `not_run`，不假装通过。只使用已固定的 Prettier 公共解析器导出，按需加载，不读取项目插件或配置、不执行源码、不安装依赖。
8. **与前几阶段衔接。** 需求清单、反向约束、场景覆盖和任务合同不被替换。测试源码与业务输入一起绑定当前回执；恢复后重新审查当前源码，不恢复“可直接通过”的模型标记。Windows 文件身份按原生版本去重，避免大小写路径被当成两个用例。普通问题不调用证据审查、不增加模型回合，也没有新增内部路由状态 UI。

## 必须保留的边界

- 这是可执行的证据与弱测试检查，不是完整的语义裁判。不能证明模型没有遗漏所有隐含需求，也不能证明某个动态断言一定覆盖用户真正的业务要求。
- 引述可核对；任意同义改写、跨段推理、单位换算、复杂财务口径及计算结论仍需独立验证。推断不会被标成“事实已证实”。来源冲突检测目前是保守的结构/直接反义筛查，不是通用自然语言矛盾判断器。
- 官方身份、原始发布日期和“这是最新版本”没有通用自动认证。当前选择明确未核实，而不是根据 URL、抓取日期或模型自评放行。
- 原始网页证据覆盖公开网页文本。PDF、企业私有知识、生成产物内部的全部主张、GUI 和复杂参数化/辅助函数测试尚无统一语义适配器。混合文件任务不会仅因读了网页而强制将全部产物说明写成研究引述；主动登记的结论仍绑定当前正文。
- 源码审查最多 64 个解析单元，单文件 256 KB；来源最多 24 份、结论最多 64 条、每条最多 8 个证据片段、单片段 2000 字符、正文最多 32000 字符。超限应拆分，不静默删掉未通过项。
- 网页原文不作为可执行权限。恢复后的原文审查结果不直接恢复为通过：需要重新取得原文并绑定当前正文。当前不是跨重启永久网页档案服务。
- 本阶段没有真实模型质量成绩，不能据此声称达到 Codex/Grok，不能据此批准发布。
