## 实现内容

1. **逐项产物清单。** `taskContract.ts` 增加 `artifact` 验收项、`artifactPath` 和测试的 `inputFiles`。已识别的产物要求必须绑定生成回执及具名内容测试；指定两个文件、PPT + PDF、指定 JSON 文件 + PDF 等，缺任何一项均不能交付。不再以任意一个已验证文件代表全部要求。
2. **当前版本证据。** `artifactEvidence.ts` 从真实本地文件读取 SHA-256、规范路径、大小和文件身份；核对读取前后的元数据，限制读取大小。生成前后没有观察到创建/变化的旧文件不能冒充新产物。回执存在原生内存中，模型自报 `verified`、重复 UI 卡片、修改快照副本均不能重新绑定证据。
3. **格式不是扩展名或文件头。** ZIP 检查中央目录、本地头、CRC、解压大小、重名/越界条目；Office 额外解析 XML、主文档类型、内部关系和实际页面引用。PPTX 拒绝缺页、空白页和失效页面关系。PDF 从原生字节解析各页操作流，不打开 WPS 等查看器。JSON 完整解析，XML/SVG 解析，文本检查非空且有效编码。
4. **验证新鲜度。** 测试在实际 dispatch 时记录输入文件版本，执行期间或执行后发生修改、删除、同长度内容替换，都使旧验证失效。进程回执必须对应命令、目录、正常结束状态，以及具名用例和原有场景要求；每项记录 requirementId、合同修订、变更修订、调用 ID 与输入版本。测试启动时尚在写入的文件不能使用旧检查放行。
5. **三个失败门控修复。** 每个调用结束时立即登记失败，下一条尚未启动的串行调用重新过门；无关的同名工具成功或任意文件写入不能解除限制；恢复节点只由同一失败指纹的可信成功回执关闭，不再由任意成功工具组关闭。后台进程启动不是验证完成，不能作为恢复成功。已经并行启动的读取不声称已撤回。
6. **修复不等于复验。** 只有修改了失败验证实际观察的输入，才允许一次受控重测；仍保留既有授权和局部修复次数限制。权限失败和外部结果未知不自动解锁。替代方案、多文件修复范围扩展仍属于阶段 4。
7. **统一完成与部分交付。** 最终正文不能借用早先进展消息证明存在；一个成功操作不能掩盖另一目标的失败。任务合同、约束、有效回执和任务图均通过后才完成，继续检查 `markDelivered()` 返回值。未通过时保留已有说明、引用及真实可读取文件的链接，注明未验收项和停止原因，不整体覆盖为一句统一失败提示。
8. **兼容确认流程。** 证据快照不深拷贝带回调函数的确认对象，原生审批回调仍由原流程执行；补齐了该路径和缺失工具 ID 的回归检查。重复调用 ID 在执行前拒绝，以免混淆回执。

## 明确边界

- 原生证据证明对象、版本和执行，不证明模型理解完整。需求提取仍是有边界的结构规则；具名测试仍可能断言不足，测试报告也不是对恶意测试代码的密码学证明。来源是否支持结论、隐含需求、数字口径及独立语义审查属于阶段 5。
- 格式可解析不等于布局正确或内容优质。原版式渲染、复杂图表/字体、GUI 交互需相应检查；本阶段没有声称能自动证明它们。所有产物要求仍需内容验收，不能仅靠格式绿色通过。
- 文件上限 32 MiB，ZIP 最多 2048 项、累计解压 64 MiB、单项膨胀比不超过 200；ZIP64/加密包保守拒绝。PDF 最多 200 页，使用已有 `pdf-parse` 内附解析器并禁止动态求值，不执行文档脚本；仍为本进程解析，尚无独立进程硬超时隔离，不宣称为恶意文档沙箱。
- 目前支持 ZIP/PPTX/DOCX/XLSX、PDF、JSON、XML/SVG、MD/TXT/CSV 的结构检查。图片、HTML、老 Office 等尚无可靠解码器的格式标记 unsupported，不能自动宣告已验证；不是用户文件损坏。这可能保守阻止某些任务完成，后续增加领域验证器，不能恢复文件头放行作为兜底。
- 证据新鲜度覆盖原生观察和显式声明的输入，不是完整依赖图。已证明无关的只读证据可保留；未知写入或代码变更仍保守使过程验证失效。同内容重新写入可能被判未观察到新产物，不能因此自动冒认新交付。
- 重启后完整证据继承、运行中纠偏仍属阶段 3；旧恢复记录缺少原生版本证据时不自动信任。没有真实模型前后成绩、费用或用户负担改善数据，不给竞品评分。
