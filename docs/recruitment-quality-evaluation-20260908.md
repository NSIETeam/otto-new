# 招聘下一步：可重复的质量评测与材料范围修正

日期：2026-09-08。本轮补第 5 项的**离线评测基础**。没有读取真实简历、调用真实模型、测出 HR 节省时间，也没有把合成样本自检包装成招聘准确率。

## 本轮能检查什么

### 1. 修正了一处实际分析提示词冲突

过去有实战材料但没有面试转写时，提示词仍声称“本次只包含简历”；只有面试、没有简历时，也可能要求联合分析一个不存在的简历。

现在提示词明确列出实际材料：简历、面试转写、实战成果；未提供简历时不再把占位文本当正文发给模型。没有面试就明确说明没有面试，实战引用要求对应实际来源。

分析版本升为 `otto-recruitment-semantic-v3.3`。旧结果仍保留，但不能冒充新版缓存。沿用现有版本保护：后台模型配置的版本变化后会拒绝旧授权下的新分析，需要负责人重新核对模型、岗位及额度；**不会因为升级而自动给旧候选人付费重跑**。

### 2. 新增 10 个公开合成边界样本

覆盖：未写测试经历、明确没有测试经历、可迁移的状态管理经验、仅出现技术名词但实际职责不符、简历自述支持、面试与简历矛盾、实战成果支持、材料中的提示词注入、多条件岗位漏分析，以及补充实战后的证据更新。

其中有两组前后材料对照。判断更新不要求分数一律上升：新材料可能补足支持，也可能暴露矛盾。样本和标注为研发测试设计，尚未经过独立招聘专家评审，不代表真实招聘分布。

### 3. 同时检查模型原始输出和 Otto 处理后的结果

评测直接使用服务端、桌面共用的生产解析器。编造引用即使被解析器丢弃，也会在原始输出检查中留下问题，不能因此宣称模型没有错误。

| 指标 | 具体衡量什么 | 不代表什么 |
| --- | --- | --- |
| `parsedCases` | 全部规定样本中，输出符合生产解析协议的比例 | 判断正确率 |
| `requirementCoverage` | 预先标注的岗位条件被唯一对应的比例 | 材料里有关键词的比例 |
| `rawSupportAccuracy` | 原始状态与标注允许状态一致的比例 | 真实能力已经核实 |
| `supportAccuracy` | Otto 解析后状态与标注允许状态一致的比例 | 对真实人才的行业准确率 |
| `groundedCitations` | 原始引用在材料中出现，且声明的来源/行号相符的比例 | 引用与结论相关、事实属实 |
| `relevantSupport` | 需要证据的条件是否覆盖预先标注的相关片段与来源 | 自动理解任意新材料的逻辑正确性 |
| `absenceFalseNegatives` | “材料没写”的条件中，原始输出却判 `not_met` 的比例，越低越好 | 自动识别所有歧视或偏见 |
| `followUpCoverage` | 需要追问的条件是否给出对应问题 | 问题专业度、可操作性已通过 |
| `materialUpdates` | 前后材料对照中，状态和证据是否同时符合标注 | 分数必须提高 |

条件名按岗位原文或预先审核的别名精确对应，引用按标注片段和来源核对，不靠关键词命中计数。模型自由改写导致无法映射时会提示 `unmapped_requirement`，需人工复核；这不说明候选人能力不足。摘要是否夸大、问题质量、偏见及最终能力核实仍需人工盲审。

少交难样本、漏掉条件、重复报同一条件都不会提高覆盖率。分母保留完整套件；没有引用、用量、费用或人工耗时不能假装是满分、零费用或零耗时。

## 怎样运行

以下从仓库根目录执行。先构建服务端：

```powershell
npm run build --workspace=otto-server
npm run recruitment:eval --workspace=otto-server -- --self-check
```

`--self-check` 仅验证评分器能解析自检参照、发现编造引用和遗漏样本。参照答案直接由标注生成，不是模型回答；报告固定说明 `liveModelExecuted: false` 和 `productionReady: not_determined`。它不能用来汇报“模型准确率 100%”。

生成一次合成样本模板，标准输出为 JSON：

```powershell
npm run --silent recruitment:eval --workspace=otto-server -- --template
```

模板包含生产提示词、提示词哈希、样本指纹和空结果槽；不包含评分答案。仅在获得模型和预算授权后，由评测人员把每份提示词发送给获准模型，原样保存响应到对应 `rawResponse`，填写非敏感的 `runId`、`modelId`、分析版本和可核对的测量数据。不要替模型修答案，不能把评分标注发给模型。记录生成参数、重试次数和人工处理条件，保留原运行日志供复核。

将两次批次保存为本地 JSON 后比较，例如：

```powershell
npm run recruitment:eval --workspace=otto-server -- --input D:/otto/evaluation-results/new.json --baseline D:/otto/evaluation-results/old.json
```

这些路径只是操作示例，本轮未创建上述结果文件。也可仅提供 `--input` 做单批评测。输入必须来自当前固定套件，不能直接把任意真实简历塞进模板；扩充真实授权样本需要另行审核脱敏、材料和标注，并更新套件版本。

命令只读本地文件并输出报告，不读 `.env`、模型凭据或企业数据库，不请求平台、发送消息、调用模型或写结果文件。拒绝 URL/UNC 路径，单文件最多 8 MB，每条原始输出最多 200000 字符，输出报告不回显简历、模型正文或本地路径。

退出码：`0` 仅表示完整输出已评测，不表示质量达标；`2` 表示输入无效、缺样本或输出不能完整解析；`3` 表示完整可比批次中发现指标退步（自检内部失败也为 `3`）。没有统一“生产通过”按钮。

## 版本比较、成本与人工测量

- 两版必须使用同一完整套件、材料和标注；指纹不一致拒绝评测，缺样本拒绝输出可比差值。
- 比较的是导入的原始响应在**当前解析器**下的重放。可以更换模型或分析版本，但这不是自动恢复旧版解析器；若要评价整套旧产品，需要另外冻结旧执行环境。报告同时保留声明的分析版本和实际解析器版本。
- 原始输出及运行元数据由评测人员提供，工具不认证真实执行、提示词哈希、厂商账单或人工操作。结果来源和费用来源不能被视为服务端计费凭证。
- 输入/输出 token、请求次数、人民币成本、模型耗时和 HR 复核秒数分别记录，未知填 `null`。只有全部样本都有该项测量时才给出完整批次总量及版本差值；否则只给已知小计和已知样本数。
- HR 测量应固定任务范围（阅读、比较、准备问题等）、计时起止和人员条件，对模型名称盲审并交叉安排顺序；不能直接用模型返回速度代替 HR 节省的时间。当前字段支持导入测量，**没有自动采集真实 HR 时间**。
- 未设伪装成行业标准的及格线。真实发布阈值应由授权业务样本、招聘人员盲审和错误风险共同确定。

## 当前状态与下一步

本轮只补评测工具和上述提示词修正，没有新增右侧模块，没有更改招聘录用/拒绝权限，没有推送或部署，也没有启用真实企业任务。

本轮验证：服务端招聘 306 项、桌面招聘 191 项、定向 HTTP 2 项，共 **499 项测试通过**（其他被筛选跳过的 HTTP 测试不计入）。评测器自检命令、两端类型检查、服务端构建、桌面渲染构建、改动文件 ESLint、doctor、代码地图和 `git diff --check` 通过。所有涉及模型的回归均为模拟响应，不是实际模型质量或费用验收。

真实 Workable 企业账号、批准模型、小额测试预算和隔离 PostgreSQL 环境仍需准备，参见 [真实账号工具说明](recruitment-real-account-tools-20260908.md)。自动入档和服务器单次费用控制已有代码，不等于真实环境已验收；本地自带模型的所有跨设备入口也仍未完全统一。
