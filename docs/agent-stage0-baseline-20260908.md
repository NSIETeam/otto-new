# 阶段 0：语义执行基线

本阶段只增加离线评测基础设施，冻结现有业务实现，不修改阶段 1–6 的行为。不会推送、部署、读取用户模型配置或启动付费模型请求。

## 固定哪些内容

- 从 Git 已跟踪文件和非忽略的未跟踪文件构建清单，以**工作树实际字节**为准；保留修改、新增、删除状态，不把 HEAD 当作全部源码。
- 包含 Core、Server、Desktop、工具、提示词、Skills、压缩、重规划、UI、锁文件及评分器。每个文件有 SHA-256，整个清单有指纹。
- 排除凭据文件、个人配置、忽略文件和生成依赖/构建目录；发现疑似高可信凭据或符号链接即拒绝，不跟随到用户目录。文件名及内容扫描不是完备的秘密检测，快照仅限本地保存，不能直接发布。
- 快照生成前后检查源码变化；已有目标不覆盖。校验可识别同长度修改、缺失文件、额外注入文件和清单篡改。校验和用于发现意外变更，不是防恶意本地管理员篡改的签名。
- 记录 Node 可执行文件哈希、系统/时区、锁文件哈希及本机已安装依赖的版本和 package.json 哈希。第三方依赖未做完整字节归档，依赖可重建性不能仅凭这份清单宣称已验证。

## 固定评分与反例

`packages/evals/baselines/semantic-stage0-v1.json` 登记 8 类验收合同：

1. PPT 有效且能在 App 内查看，不开 WPS、不暴露裸路径。
2. 指定的每份产物均通过当前版本验证。
3. 同批失败及时生效，无关成功不能清除失败限制。
4. 同一行为在不同模块不能合并，测试不能只靠名称和退出码。
5. 运行中纠偏、超过摘要上限、重启和外部副作用结果未知。
6. 授权范围内新增测试、多文件修复和复验，不降低标准。
7. 数字/日期/来源定位和矛盾证据（保留组）。
8. 简短问题与部分交付的自然表达（保留组）。

6 项开发合同、2 项保留合同；代码库内可读的合同不是真正保密留出集，后续必须增加未用于调优的独立变体。这里是预先登记的验收规则，**不是 8 项真实任务已经通过**，也不冒充完整 GUI 实测。

固定口径：失败、超时均计入分母；缺失成本/用量/观察为 null 或 unknown；一次完成允许内部修复但不允许依赖用户反复纠错；错误完成与未完成比例同时报告。模型、版本、端点、价格、预算、用例及评分器发生变化，不得当作纯运行时收益比较。

## 离线复现

在源码根目录运行（目标必须是不存在的绝对路径，且位于源码根目录之外）：

```powershell
node scripts/agent-eval-baseline.mjs freeze D:\otto\agent-baselines\stage0-UNIQUE
node scripts/agent-eval-baseline.mjs verify D:\otto\agent-baselines\stage0-UNIQUE
node scripts/run-agent-baseline.mjs D:\otto\agent-baselines\stage0-UNIQUE D:\otto\otto-push-20260901
```

`freeze` 只复制源码，不带 `.git`、旧 dist 或用户资料。`run` 会校验快照和依赖元数据，恢复到快照下新建的独立 `runs/offline-*/workspace`，不修改冻结源码。每次运行都有独立配置/缓存/日志和 JSON 测试回执；测试失败原样保留，不在阶段 0 偷改业务实现让基线变绿。

离线测试配置用精确别名将 `otto-core`、`otto-server`、`otto-workflow`、`otto-rpa`、`@otto/native` 指向恢复出的 TypeScript 源码。第三方 node_modules 通过本机目录联接复用，不以另一个工作区的旧构建当成本次源码运行。

测试覆盖现有需求、交付门、重规划、任务图、修复、压缩、评分器，并用本机回环脚本化提供方运行真实 CoreSessionRuntime。它证明执行链可加载/运行，**不证明真实模型质量，不是完整 Electron 启动或 GUI 重启验证**。后两者属于后续真实任务阶段。

## 真实模型条件与预算

只检查专用评测变量是否明确提供，不去读取 Otto 日常账号的密钥：

- `OTTO_EVAL_MODEL`：固定模型标识。
- `OTTO_EVAL_MODEL_REVISION`：提供方固定版本/修订标识，避免仅使用漂移别名。
- `OTTO_EVAL_BASE_URL`：HTTPS 或本机回环，不允许 URL 中带凭据、查询串或片段；清单只存规范化端点指纹。
- `OTTO_EVAL_API_KEY`：不保存、不打印，轮换密钥本身不改变比较条件。
- `OTTO_EVAL_MAX_COST_USD`：明确的正数预算。
- `OTTO_EVAL_INPUT_PER_MILLION` / `OTTO_EVAL_OUTPUT_PER_MILLION`：非负价格；没有价格不能按免费计算。

固定限制初值：每批最多 24 次、单并发、每例 1 次、10 轮、150 秒、2048 输出 tokens；模型请求超时 45 秒。实际 live harness 的代理端、推理 tokens 和费用上限仍需在首次真实调用前核查，并配置提供方账户硬账单上限；本阶段的清单**不是已实现的实时扣费防超支器**。

缺配置时输出 `ready=false`、`status=not_run`，保留离线基线，不自动补模型、不发请求。准备就绪也不等于获得调用授权。首次真实对照前应把最终模型/预算记录成新的比较协议，并让旧快照和新实现共用；不能把已完成的离线回环测试更名为真实模型基线。

## 当前放行边界

准备阶段保留了两次真实失败记录：首份恢复遗漏子包 node_modules，导致依赖加载失败，已补恢复逻辑；第二份运行 84 项中 80 通过、4 失败，原因是脚本提供方的 testCase 遗漏当前合同要求的 expectedOutcome。4 项数据均正确，但禁止要求没有匹配的验收标记，所以原生完成门拒绝交付。这里只补测试夹具的标记，不删除负向要求、不降低判定，也不修改业务实现。首次失败快照和日志不覆盖。

不同源码快照之间存在并行开发产生的招聘模块变化，均作为该时间点的真实源码记录；本次没有修改那些文件。后续效果比较须固定目标实现范围，不将其他模块的并行变化归功于 Agent 升级。
