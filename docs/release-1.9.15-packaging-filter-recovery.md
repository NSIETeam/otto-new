# 1.9.15 packaging filter recovery

Formal run `34438195463`, source `f82fa9b5de826d49d818aa733a8aa464df761102`, failed in `Build desktop release artifacts`. The first arm64 `app.asar` contained 74 compiled test files under `dist/main`; the existing content gate correctly rejected it. Earlier quality gates, 2,107 desktop tests, the unchanged 281-file coverage ratchet, 482 focused tests and 86 legacy-upgrade checks passed. All 12 later installer-acceptance/publication/deployment jobs had zero steps. No new installer was published or server deployed. The two temporary OAuth copies were removed and the normal self-review restriction restored.

The underlying problem was configuration normalization, not a missing filename glob. The pinned electron-builder first divides string filters around custom FileSets, then prepends a later block when merging FileSets with the same source/destination. Placing the server NOTICE and seed Skill mappings between root inclusions and exclusions moved the exclusions before `dist/**/*`, allowing that later inclusion to reselect compiled tests. Directly testing `FileMatcher` without configuration normalization missed this behavior.

The correction moves the two custom mappings after the single contiguous root inclusion/exclusion block. No filter text, required runtime entry, license/Skill mapping, dependency, compiler behavior, installer size limit, content verifier or approval gate is removed or weakened. Compiled tests may remain in a developer's build directory for typechecking; they must not enter the distributable archive.

The regression uses the installed builder's real `doMergeConfigs` and `getMainFileMatchers` for both Mac and Windows. It failed against the original configuration by admitting `account-data-sync.test.js`, then passed after the ordering change. It also checks nested tests/specs, coverage, maps and declarations are excluded, while main/preload/renderer entries and the NOTICE/Skill mappings remain. All 54 tests in the packaging contract, packaged-content and Sharp-packaging suites passed locally. The initial repository-root invocation selected zero tests and is not counted as a red or green test result. These checks do not replace the next formal run's actual installers and native-host acceptance.
