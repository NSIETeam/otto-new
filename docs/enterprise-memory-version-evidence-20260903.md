# 企业记忆：依据、版本比较与受控恢复

本轮为现有企业记忆的增量改进，不改变模块入口，不宣称模型能一次生成完全正确的企业制度。

## 用户可见变化

- 概览回答：记住了什么、有哪些来源记录、哪些内容待确认、哪些存在冲突或已经过期。
- 去掉治理总分、可信度等级和“被 N 次工作验证”的表述。重复观察、人工审核、模型建议不再混为准确率证明。对话查询也使用相同口径。
- 展示学习依据的原文、来源编号、时间和验证标记；验证标记仍需核对，不是系统对整条结论的保证。
- AI 深化展示建议理由、引用编号、未确定事项、建议适用范围与误用风险。新增编辑前/待保存正文并排对比，模型自评分不提高存储的可靠度。
- 历史版本可选择比较。变更原因是当时记录的原因；实际标题、分类、正文是否变化由本地代码判断，不把版本增加当作质量提升。
- 管理者填写恢复依据并显式确认后，服务器从自己的历史快照读取旧内容，另存为新版本。保留当前部门范围与全部历史，清除旧审核状态与有效期，重新确认前暂停成员检索。
- 管理者选择恢复的待确认正文不会被后续自动观察覆盖；新依据继续累积，出现冲突仍须审查。
- 刷新时清除旧依据/版本/AI 建议缓存；修订、恢复、审核携带当前版本，避免旧页面或迟到建议覆盖新修改。

## 真实自动化边界

已核对现有链路：服务端对话结束后产生 `knowledge_activity`，桌面端检查企业知识开关后上传本次观察，企业保留策略做去重、候选积累、来源摘要更新与冲突隔离。此次另外拦截切换企业后迟到的上传检查结果。

自动观察和来源摘要整理并不等于自动进行大模型事实验证。AI 深化仍由管理员点击，使用已有模型配置生成待审核建议，没有新增无限后台迭代。打开概览、比较版本、恢复内容均不调用模型。

模型输入仍有限额（最多 50 条依据，单条截取、正文长度受限）。适用场景是建议，不是运行测试覆盖面；当前累计来源数不是各历史版本的独立验证成绩。旧数据库正文中的历史评分不会被批量改写，新自动生成正文不再附加可靠度百分比。

## 服务端与权限

- 复用 `PATCH /enterprise/knowledge/:id`，新增 `expectedVersion` 和 `restoreVersion`；恢复必须提供当前版本以及 12–400 字的依据。
- `POST /enterprise/knowledge/:id/review` 支持 `expectedVersion`；新桌面端审核和停止使用携带该条件。
- SQLite 在事务内校验企业、当前版本、历史版本、冲突和归档状态，再写新内容和修订记录。
- PostgreSQL 将正文 CAS 更新和审计插入合并为一个 SQL 语句。CAS 失败不写记录，不会用自动重试覆盖最新内容。
- 集群历史归一为内容快照；不含完整正文的旧审计事件不可恢复。仅查询最近 500 个事件，未加载或不完整历史明确拒绝恢复。
- 旧版客户端不提供普通修订的版本条件仍保持兼容；不能因此宣称所有历史客户端都已具备并发保护。
- 集群既有自动观察/证据接口与 SQLite 并不完全等价：本轮补齐的是版本读取、修订与恢复，不宣称迁移了完整企业证据池或集群冲突裁决。

## 检查方法与结果

本轮相关回归共 282 项通过：桌面端 195 项、企业记忆/版本仓储 45 项、既有集群服务器 41 项、实际 HTTP 登录与权限/恢复链路 1 项（该命令其余 99 项未选择执行，不计入通过数）。

- 桌面端：界面/历史确认、AI 输出约束、客户端协议、对话桥、自动上传状态回归。
- 服务端：实际 SQLite 数据库测试与 HTTP 登录鉴权测试，覆盖跨企业、非管理员、旧版本、缺少快照、重复恢复、冲突/归档绕过、恢复后检索隔离和新观察保护。
- 集群：路由与 PostgreSQL SQL 契约测试，覆盖版本冲突、快照归属、审核并发和更新/审计原子 SQL；另运行现有集群服务器回归。
- Server 与 Desktop main/preload/renderer TypeScript、ESLint、renderer production build、代码地图与差异空白检查。
- 使用真实组件的本地虚构数据预览检查浅色/深色主题、AI 建议内容对比以及恢复确认交互。预览未使用真实账号、企业资料或付费模型。

复现预览：仓库根目录运行 `node scripts/preview-enterprise-memory.cjs`，访问 `http://127.0.0.1:4597/`（深色）或 `http://127.0.0.1:4597/?theme=light`（浅色）。构建结果仅保存在进程内存。

不夸大验证范围：本轮未启动真实 PostgreSQL 实例、未执行真实付费模型分析、未对生产企业数据做恢复操作。

仓库级已知问题（非本轮新增）：源码体积检查在过程中从 43 MB 增至约 68 MB，增量来自 `packages/evals/artifacts/probes/output-ui-sandbox/` 的 Electron 缓存/构建文件及评测压缩包，未擅自删除；已有政策展示测试的跨包导入也会触发边界检查。这些不能算作“全仓门禁通过”。

代码仅在本地修改，本轮没有提交或推送。
