# 阶段 4：有限方案比较与受控修复复验

本阶段仅修改本地源码并做离线验证。不推送、不发布安装包、不部署、不操作生产服务，也未调用付费模型。

## 已实现

1. **失败后的有限选择。** `adaptiveExecution.ts` 为失败保存至多三个原生候选：有限的同请求只读重试、检查/修复或压缩、请求输入或结果核对。记录可用性、前置条件、风险、额外调用上限和选择结果；不保存原始错误中的密钥。权限失败和外部结果未知先阻断自动路径。同一失败能力最多两次不同参数的替代尝试；原有整轮重规划预算仍生效。
2. **具体的本地修复方案比较。** 收尾时可调用 `plan_delivery_repair`，提交 1—3 个方案，每个明确列出理由和 1—4 个文件。原生侧按已观察输入、当前文件版本、关联关系、工具是否存在、文件数量和体积比较，优先选择风险较低、范围较小的可执行方案。它只签出额外限制，不产生新的用户授权，也不能提交新的验收条件。
3. **多文件修复与新测试。** 两个修复批次，每批最多四个文件；每个文件最多两次写入，适用于补丁及格式整理。现有文件须失败后重新读取。扩展文件须在当前工作区、已经读取、出现在失败检查输入中，并与本轮已修改文件有直接相对导入、JSON `$ref` 或相邻测试关系。新建文件仅限已修改源码相邻的约定命名测试；父目录必须已存在。不自动创建目录，不开放整个仓库。原有单文件快速修复路径仍保留，消耗同一批次预算。
4. **受限格式化。** `prepare_repair_format` 仅为选定且刚读取的文件生成格式化建议。使用固定的 Otto 服务端依赖 `prettier@3.9.6`，不运行 shell、不加载工作区配置/插件、不下载任何依赖，不自动写入。支持内置 TS/JS、JSON、CSS/SCSS、HTML 解析器；输入不超过 256 KB。建议仍须通过普通 `write_file` 和原生策略/批准/审计写入。未支持语言不自动安装格式化器。
5. **验收与版本不放宽。** 方案绑定请求版本、失败检查 ID 和原生验收定义摘要。新增要求、替换目标或修改验收定义会使旧方案失效，单纯更新有效回执不会改变摘要。写入、批准后和原生执行前再次核对文件及参数指纹。修复/格式化建议不是写入回执；成功修改也不是成功测试。原有逐项用例、文件输入版本、产物校验和任务图交付门继续独立工作。
6. **预算与恢复。** 修复批次数、比较次数和格式化次数写进阶段 3 的同一恢复记录。存储拒绝预算倒退；重启只恢复已消耗额度，不恢复旧方案、文件读取许可或批准。工作区/目标调整不重置预算。发送、部署等操作仍走原有防重放和未知结果核对，修复器没有自动回滚或执行这些操作的入口。

## 防护与边界

- 比较工具和格式化准备工具只在进入收尾后提供给模型，普通问答不增加这些声明、调用或审查轮次；未增加任何面向用户的内部路由状态标签。审计使用现有工具回执与 typed adaptation 元数据，不另建执行循环。
- 文件检查拒绝越界、符号链接、目录联接、硬链接、特殊文件和大于 2 MB 的输入/写入内容。扩展范围排除隐藏文件、依赖/构建目录和包清单、凭据/设置等敏感配置。关联 JSON Schema 可以参与，自动依赖安装、锁文件与编译配置修改不在此快速修复范围内。
- 方案比较不等于独立理解方案的业务正确性。导入关系只是一层静态关联证据，不是完整依赖图；候选理由仍由模型给出。弱测试、隐含需求、测试源码语义降级的独立审查属于阶段 5。这里保持原验收定义及回执要求，不能承诺自动证明每个测试断言都充分。
- 一般失败分类仍部分使用错误文本，比较的是有限的宿主策略，不是全局最优策略搜索器。参数变化次数受限，但不能由此证明所有换参调用语义上互不重复；外部业务幂等仍需要服务端支持。
- 原生文件复核是应用层防护，不是恶意同权限进程下的 OS 文件系统沙箱；不承诺消除系统调用之间全部竞态。没有自动操作用户桌面、执行真正的 GUI 恢复或开启外部 Office。
- 格式化增加固定生产依赖；本轮没有构建安装包，未给出安装包体积或签名/发布结论。包锁保留原有依赖项，仅增加格式化器的生产依赖归属。
