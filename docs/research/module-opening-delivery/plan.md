# 模块打开体验修复执行清单

基线：0c075de0（含新版企业星链图），分支 codex/blue-heron-7f3a9c。
用户最终约束：本地代码修改和 Git 提交；不推送、不打包、不做 App 真机人工视觉验收。
来源：本次讨论的 12 项方案，以及 /Users/yang/Desktop/otto-module-opening-review-2026-09-08.md。

1. 紧凑/标准/复杂窗口分档，简单表单不再共用1180宽窗口，受视口限制，最大化正常。
2. 七类园区表单立即渲染；身份决定能否提交；工单历史不得阻塞填写；晚到默认值不覆盖主动输入（包括主动清空）。
3. 登录工作区拥有共享只读缓存，合并并发读取，限制容量，按服务器/企业/账号生命周期隔离，写操作后失效。
4. 企业记忆、政策、市场、Skill、拼车及星链图保留已读内容，后台刷新不得清空有用内容或覆盖正在编辑的数据。
5. 最小化保留组件和输入；关闭未提交表单需要明确放弃；提交成功不重复提示。
6. 区分首次加载、确实为空、刷新失败、身份缺失；局部错误和重试不遮住表单。
7. 仅对已授权入口做悬停/聚焦预取，限只读操作和画布代码；不自动执行模型、发布、标记已读或定位。
8. 逐模块专属处理：会议室冲突立即刷新资源；星链图保留新版探索、权限失效清理和画布降级；市场沿用持久草稿；Skill保留列表筛选；政策保护资料编辑。
9. 保持招聘共享工作区、Agent激活、自定义模块执行时机、管理模块和添加功能组的正常契约。
10. 多窗口激活、最小化恢复、最大化恢复、视口缩小后位置可见；保留标题和关闭入口。
11. 保持开发账号与服务端权限规则，配置/授权缺失如实显示；不删权限检查或伪造就绪状态。
12. 相关回归测试、桌面全量测试、类型检查、lint、差异与边界检查；报告列明实际通过、基线失败及未实测项。审阅完成再本地提交。

范围限定：不合入远端 internal 的其他业务改动；不改核心运行时或后端业务；不新增草稿持久化框架、付费操作预执行或自动定位。数据缓存仅在登录工作区内存中。
