# 智能招聘：首个真实账号联调清单

日期：2026-09-08。当前状态：**准备完成，真实联调未执行**。本文件不包含密码、令牌或真实简历；不能作为平台已通过验收的证明。

## 先准备这四项

| 项目 | 需要提供或由管理员设置 |
| --- | --- |
| 隔离验收企业 | 测试服务器地址、企业 ID、岗位创建者与另一位授权 HR；再准备一个无权限账号。不能直接用生产全员人才库试跑 |
| 本人 Workable 授权 | 有权访问的企业账号和已发布测试岗位，由本人通过官方浏览器页面登录；不要在聊天中发送密码、验证码或 access token |
| 获准使用的材料 | 建议 2–3 份合成或已获授权且去标识化的测试简历，以及同一人的第二版；明确允许传给所选模型、保存期限与共享人员 |
| 模型与成本许可 | 选定模型供应商/模型标识、数据处理批准、单次试验费用上限。API key 只由运维写入服务端秘密管理；第一轮每日调用上限设为 1，先检查估算 Token 是否足够，不能反复重试未知请求 |

## 分两道门，不伪造“已验收”

1. 在隔离服务器启用 `OTTO_WORKABLE_OAUTH_ENABLED` 后，先验证真实 OAuth、账号/岗位目录、手动选择绑定及“检查账号连接（只读）”。此检查不证明简历读取成功，不消耗模型 Token。
2. 首次候选人及附件验证使用新增的[限期样本读取入口与离线预检](recruitment-real-account-tools-20260908.md)：先由运维精确批准企业、本人和测试岗位，再独立确认读取一份样本，记录权限和经审核的附件 HTTPS origin。**不能为了让页面变绿，直接把 `OTTO_WORKABLE_REAL_ACCOUNT_VERIFIED=1` 写进生产**。批准范围外的来源继续关闭；样本检查也不会开启生产、付费模型或候选人入档。
3. 有真实读取证据并经过部署负责人确认后，才配置该部署的 `OTTO_WORKABLE_REAL_ACCOUNT_VERIFIED` 和 `OTTO_WORKABLE_AUTHORIZATION_REFERENCE`。`OTTO_WORKABLE_RESUME_ORIGINS` 只加入实际审核过的精确 origin，不加入通配符或任意下载地址。
4. 付费分析另行配置 `OTTO_RECRUITMENT_BACKGROUND_ANALYSIS_ENABLED`、`OTTO_RECRUITMENT_MODEL_ORGANIZATION_IDS`、`OTTO_RECRUITMENT_MODEL_API_URL`、`OTTO_RECRUITMENT_MODEL_API_KEY`、`OTTO_RECRUITMENT_MODEL`、`OTTO_RECRUITMENT_MODEL_APPROVAL`，并核查调度器付费任务许可。未审批不设置，不以模拟结果替代真实许可。

入口与现有参数的详细限制见 [Workable 运行说明](recruitment-workable-runtime-20260908.md)、[浏览器授权说明](recruitment-workable-browser-oauth-20260908.md)、[后台分析费用边界](recruitment-background-analysis-20260908.md)。这些是代码当前支持的范围，不是实时官方接口兼容性承诺。

## 验收顺序与通过标准

所有项目当前均未执行。每项记录：日期、操作者、部署版本、匿名岗位/档案 ID、结果与脱敏证据；不要把令牌、签名下载地址和简历原文写入验收日志。

| 顺序 | 操作 | 必须看到的结果 |
| --- | --- | --- |
| 1 | 本人登录 → 选择账号 → 绑定已发布岗位 | 只显示有权访问的账号和岗位；不默认替用户选账号；取消/过期回调不可继续 |
| 2 | 读取一名测试候选人及获准简历 | 区分摘要与全文；原文可核对；文件格式或权限不支持时明确失败，不改用内部接口或爬虫 |
| 3 | 授权后台接收，先不开付费分析和入档 | 材料只进入共享待处理箱，模型账单无新增分析调用 |
| 4 | 确认模型和本岗位预算，开启一次后台分析 | 原文依据可回查；只展示简历自述支持；调用/Token 记录与厂商账单逐笔核对 |
| 5 | 单独授权自动入档，再关闭所有桌面端 | 服务器直接保存正式候选人、历史及回执；入档不增加模型请求 |
| 6 | 两位 HR 各自加载同一共享岗位 | 不用再次导入；看到同一份档案、分析和来源；无权限账号及另一企业不能读取 |
| 7 | 同一来源补充第二版材料 | 只在内容确有变化时按既有分析预算处理；自动档案更新，旧版仍可回查，保存期限不变 |
| 8 | 同事先录入面试/实战或人工判断，再出现新简历 | 原档案不覆盖；待处理箱显示需复核，不能把仅简历分析冒充联合分析 |
| 9 | 删除档案，再接收同来源的新材料 | 不自动重建；材料留在待处理箱，提示原档案已删除 |
| 10 | 暂停入档、撤销岗位共享/账号权限，分别测试 | 暂停后晚到写入被拒绝；范围变化要求重新确认。暂停入档不冒充暂停付费分析 |
| 11 | 撤销 Workable 授权/令牌到期 | 不再访问平台；已授权保留的本地/企业历史不会被假装同步删除。重新授权需重新绑定，跨授权同人合并仍需复核 |
| 12 | 两个独立服务实例竞争、网络中断、审计失败、进程重启 | 同一结果只一份正式档案；已知模型结果不重复计费，未知请求先核对账单；不丢原档案，不跨企业写入 |

第 12 项必须在实际 PostgreSQL 和两个独立进程上运行；内存 SQLite 的并发测试不能替代。还需测量积压清空时长，检查原始文件、正式档案及备份的到期处理，才能确定生产容量和保留政策。

## 停止条件

发现账号范围不一致、原文缺失却显示全文、模型账单无法核对、重复入档、权限撤销后仍读写或人工档案被覆盖：立即暂停相应接收/分析/入档任务，保存脱敏诊断证据。结果未知时不得靠自动重试“修复”。

本轮只补入档与联调准备；跨入口统一费用账本、企业总预算、原始文件托管、完整跟进回写、招聘质量/HR 节时评测均未被本清单视为已完成。
