# 招聘下一步：单份企业模型分析，共用后台费用账本

日期：2026-09-08。本轮衔接第 4 项费用控制：**已在服务器待处理箱中的简历，可以单次调用企业批准的模型，不必开启持续后台分析。** 不是所有手动上传入口已统一，也不是已完成真实平台验收。

## 可以直接检查的效果

1. 岗位创建者或企业管理员在“智能招聘 → 后台接收简历 → 后台分析”确认材料处理、费用和共享范围，选择“保存额度，不开启后台”。服务器仍须配置获准的企业模型、指定企业和企业总额度。
2. 获授权的招聘同事，在一份已有完整正文的待处理简历下展开“用企业模型分析这一份”。确认面板展示模型、服务器已保存的岗位要求、处理范围及共享说明。**尚未保存的本地岗位修改不会用于本次分析。**
3. 独立勾选该份简历的费用与共享确认后，点击“只分析这一份（企业模型）”。此前的工作台授权或后台接收授权不代替这次确认。岗位版本、模型、材料或共享范围变化后，需重新确认。
4. 返回结果标明“企业模型已分析 · 简历自述支持，尚未核实能力”，并保留触发方式、处理账号、原文引用和用量。只提交所选材料；没有开启后台开关，也不会改用桌面模型。
5. 如果此前另行授权了自动正式入档，结果由已有零模型费用的入档任务继续处理；未授权时，仍可导入已保存结果，不新增模型调用。自动入档按服务器调度执行，不承诺 HTTP 返回时已完成。

## 安全、费用与恢复边界

- 单次入口和后台入口复用同一个执行器、岗位预留、企业持久账本及输入指纹。与后台任务、桌面认领同时竞争时，只有获得处理许可的路径可执行。未知结果不自动重发，换待处理编号也不能绕过相同任务指纹。
- 只接受服务器岗位与材料编号、确认过的版本和范围，不接受客户端附带简历正文、自定义模型地址或提示词。用户只能处理本企业自己有权访问的岗位。
- 调用前及结果写回前检查当前账号、岗位权限、许可证、模型授权和共享范围；移除材料后不重新生成该副本。权限撤销后不向原调用人返回档案。
- 管理员可在另一会话刷新待处理箱后，选择“停止接收本次结果（可能仍计费）”。它使晚到结果失效，不承诺取消厂商请求或退回已预留额度。发起分析的界面在等待期间锁定相关操作，避免并发修改。
- 模型请求上限 90 秒，客户端 HTTP 等待上限 120 秒；网络或代理可能更早中断。关闭窗口、断网、进程崩溃后应先刷新原记录，不自动切换模型补跑。数据库预留或用量回报不确定时，保守保留预留记录。
- 预留 Token 是准入估计，不是实际 token 或人民币费用保证。单次企业分析和后台分析共同受岗位及企业每日额度约束；桌面端自带模型仍单独处理，不能称为统一全公司账单。
- 老服务器不支持 `recruitment_intake_once_v1` 和 `recruitment_organization_budget_v1` 时，客户端拒绝这次单次请求，不自动降级。就绪检查模式 `OTTO_ENTERPRISE_CANARY_MODE` 下，企业模型解析为不可用，不能通过此 HTTP 入口绕过后台暂停。

## 未扩大的范围

本轮没有自动上传本地简历，没有传送企业记忆、面试或实战材料，没有主动联系、拒绝或录用候选人，也没有开启真实企业的后台任务。常见身份字段会预先遮盖，但这不保证完全匿名。

配置方式和升级顺序沿用 [企业额度说明](recruitment-enterprise-budget-20260908.md)：暂停旧分析实例、升级全部实例，核对当天历史消耗，避免新账本忽略升级前用量。真实账号准备沿用 [联调工具说明](recruitment-real-account-tools-20260908.md)。

## 本轮验证

- 服务端招聘模块和集群宿主 334 项、桌面招聘 191 项、定向 HTTP 2 项，共 **527 项测试通过**。被定向筛选跳过的其他 HTTP 测试不计入。
- HTTP 集成使用隔离临时数据库、合成简历和模拟厂商响应，验证“接收正文 → 保存额度但后台关闭 → 单次分析 → 独立授权自动正式入档”，模型调用次数为 1；重复读取不新增调用。
- 回归覆盖独立确认、仅所选简历、旧版本和权限拒绝、未配置模型、并发认领、企业上限、失败不换模型、不自动重试、账号停用、移出岗位、停止接收结果、移除副本及陈旧确认失效。
- 服务端与桌面类型检查、服务端构建、桌面渲染构建和相关文件 ESLint 通过。
- 上述测试证明受测实现，不证明招聘判断质量或实际厂商计费；PostgreSQL 仍仅是适配与契约测试，没有实际跨实例故障恢复验收。

本轮未推送、未部署、未调用真实付费模型。下一步仍需在获得授权的隔离环境中做 Workable、企业模型及数据库联调；本地上传 / 自带模型的跨设备统一账本另行推进，不能据此宣称已经完成。
