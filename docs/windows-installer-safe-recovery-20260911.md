# Windows 安装冲突：中文提示与保留原文件的恢复入口

状态：本地实现与隔离回归完成；尚未打成新正式安装包或发布。已发布的 1.9.15 不会因本地源码修改而改变。本次未修改服务器。

## 用户看到的流程

1. 原目录保护检查发现问题时，显示中文原因、**实际冲突位置**和正在检查的安装目录。旧安装登记也可能在目录选择页出现前触发保护，并不表示用户已经启动过 Otto。
2. 提示原文件已保留，不要求用户改注册表、删除目录或反复卸载。用户选择“是”进入安全恢复，默认选择“否”退出。
3. 向导再次展示原位置、新位置和版本。确认后，保存旧安装登记，在 `%LocalAppData%\Programs\Otto-Recovered-<随机标识>` 的全新独立目录安装；不会执行旧卸载器。不能安全使用这个位置时停止，不擅自覆盖其他目录。
4. 成功后提示从新版快捷方式打开，明确原目录仍然保留。旧卸载登记的备份从 Windows 应用列表隐藏，避免用户再次误触旧卸载入口。
5. 失败或中断后，下次交互式打开安装器会提供结果核对入口：已确认成功则保留新版；已确认失败则恢复原登记。遇到外来登记或结果尚未知时保留记录并停止，不猜测、不覆盖。

## 安全边界

- 当前自动恢复仅支持正式 Otto 的 **Windows x64 当前用户安装**。全用户安装、其他架构的全用户登记和 Otto Green 暂不自动迁移，显示中文说明并引导联系管理员/支持。不是所有损坏安装均可自动恢复。
- 安装器和卸载器保留原目录检查；未知文件、源码目录、链接、系统/用户资料根目录等仍会阻止覆盖或卸载。无静默迁移或卸载保护开关。
- 静默更新遇到冲突仍返回 73，不自动移动安装登记。恢复子安装是在用户显式确认后对新的独立目录执行，仍运行原路径检查。
- 恢复通过原生注册表键重命名保留完整值及子键，不删除原目录或注册表子键。预检备份重名、恢复标记冲突、原路径关系；恢复不覆盖已有外来登记。
- 执行前锁定原安装包，保存副本并校验 SHA-256；执行期间保持副本只读句柄。没有下载脚本、PowerShell 执行策略修改、强制终止 Otto 或系统重启。
- 使用恢复专用互斥锁及上游安装互斥锁。先写入不可覆盖的意图记录，再改登记。等待超过 15 分钟不强杀安装进程；结果未知时保留待核对记录。
- `%LocalAppData%\OttoInstallRecovery` 保留 `pending.json`、已安装/已恢复回执和安装包副本。它们用于恢复和核对，不自动清理。原安装目录也不自动删除，会额外占用磁盘空间。
- 此保护用于防止意外数据丢失，不是抵抗同权限恶意进程或管理员同时篡改文件/注册表的沙箱；没有以此替代 Windows 代码签名。

## 实现位置

- `packages/desktop/build/installer-safety.nsh`：中文原因、冲突位置、交互恢复与中断恢复入口；原守卫继续生效。
- `packages/desktop/build/InstallerRecovery.cs`：原生向导、全新安装目录、完整登记保留、部分失败/中断核对。
- `packages/desktop/scripts/installer-recovery-build.mjs` 与 `before-pack.cjs`：Windows 打包时编译小型原生辅助程序；有平台签名配置时使用同一签名入口。保留锁定的 electron-builder 默认安装/卸载脚本，不补丁修改依赖。
- 生成的 `InstallerRecovery.exe` 忽略 Git 跟踪，只作为安装恢复所需程序嵌入安装器；不把 C# 源文件、测试或测试目录打进应用。
