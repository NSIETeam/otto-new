The mirror's exact-count comparison would therefore reject the valid canonical Release after enterprise deployment and canonical publication.

The run was cancelled before its build environment approval. The preserved terminal inventory contains 38 jobs: 19 successful, 17 cancelled, one failed closed after its required attestations were cancelled, and one skipped. Packaging, Windows acceptance, draft creation, publication, deployment and compensation jobs had no execution steps. This was a pre-publication discovery, not an observed production outage. The production correction is exactly two entries in the mirror job's **public Release identity check**. It does not add files to the mirror payload or change any integrity comparison. Canonical and legacy Releases each retain 16 assets; the mirror retains seven payload files (three installers, three blockmaps and `latest.json`) plus its two private signature/checksum metadata files. No installer size ceiling, source exclusion, approval, provenance or rollback boundary changed.

A regression reads the actual workflow vector and resolves each pattern against the real `buildExpectedDraftIdentity` result from fixture files. The exact set and uniqueness checks reject omissions, duplicates and extra patterns. The same test requires the unchanged mirror-copy set. It failed against the original 14-entry vector and passed after the two-entry correction. Five focused suites passed all 53 cases, including draft/publication recovery and mirror manifest checks. These tests are not installer or production acceptance: the corrected source must still pass fresh CI and a new formal release.

## Formal focused-test configuration

An advance local run of the formal workflow's unchanged 11-file focused command exposed a second integration omission: it invoked Vitest at repository root, where there is no shared test configuration. Nine files passed; two files had three default-five-second timeouts (479 passes, three failures). This did not establish a macOS product defect, but demonstrated that formal acceptance was not using the owning workspaces' established setup, isolation and timeout configuration.

The formal step now uses the existing workspace runners: the same two Core tests, five Desktop tests and four Server tests, with each Server file in a separate process as in ordinary CI. No test, threshold or mock implementation was changed. A new wiring regression requires the exact original 11-file scope and owning workspace commands, with no conditional skip or ignored error. It failed before this correction; all 26 tests in four focused workflow suites passed afterwards. The complete original legacy-upgrade command also passed locally: 84 passes and two documented Windows platform skips. Local fixtures and workflow wiring remain distinct from hosted installer and production acceptance.
