## 本轮范围

落实优先事项 1、2：纠正确定性表述、分离人工核实记录、阻止不同分析口径直接比较。

## 已改变的行为

1. **材料不再被称为已验证属实。** 界面、对话、提示词统一区分材料支持、部分材料支持、存在矛盾、仍待核实、材料不清楚。引用显示简历自述、面试回答或实战材料的来源；旧档案中的 `verified` 仅作兼容字段解释，不代表人工核实。
2. **覆盖率改名并解释。** “引用维度覆盖”仍按有原文引用的分析维度数 / 全部分析维度数计算，不是岗位条件核实率或录用概率。没有写明某项能力不等于不具备该能力。
3. **新增逐项人工核实记录。** 在“岗位证据图谱”选择条件、填写核实方式和依据、明确勾选确认，再保存“核实后支持 / 核实后不支持 / 仍待补证”。保留填写人、时间和依据；填写人可撤销自己的记录。不会修改模型状态、抹去矛盾或作出招聘决定。
4. **核实记录绑定具体版本。** 候选人、岗位、材料正文、来源正文摘要指纹、原附件摘要及分析变化后，旧核实记录显示为待重新复核。最多保留 100 条，达到上限时拒绝新增，不静默覆盖历史。
5. **比较前检查口径。** 检查岗位标题与要求、分析时的材料指纹与类型、材料完整状态、保存期限、分析规则版本、模型标识和企业上下文指纹。任一条件不一致，整组选中人选暂不展示比较分数并说明原因。可取消勾选不一致的人选，只比较同口径子集；不自动排名。
6. **导出使用同一检查结果。** 不另开一条无版本校验的导出路径。岗位或材料变动期间立即停用旧比较结果和导出按钮。旧档案仍能读取，但缺少版本元数据时不能直接比较。
7. **版本由程序记录。** 主进程捕获岗位、材料、企业上下文的 SHA-256 指纹、材料类型和实际配置模型标识；不接受模型自己生成的版本信息或人工核实记录。分析规则版本升级到 `otto-recruitment-semantic-v3.1`。
8. **修正引用及材料边界。** 面试 / 实战文本中的空行不再造成引用行号偏移；带明确来源的引用不能被归到另一来源。仅有面试时不会把占位说明当简历。没有任何实际材料时不会调用模型。
9. **旧规则结果不再静默复用。** 来源导入复用检查包含分析规则版本；旧版结果重分析前保留在来源历史中。没有更改模型且输入和规则未变化时，原有来源导入复用继续有效。

## 人工验收步骤

1. 在智能招聘导入一份已获授权的测试简历，打开“查看原文证据”和“岗位证据图谱”：应看到材料支持和引用来源，不应将模型结论称为人工已核实。
2. 检查“引用维度覆盖”的解释，不应显示为能力验证比例。
3. 在“招聘人员逐项核实”填写依据但不勾确认：不能保存；确认后可保存并在同一档案查看。
4. 更新岗位、面试 / 实战材料或分析：旧核实记录应显示“待重新复核”；不应自动变成针对新材料的有效核实。
5. 在“企业共享岗位”按现有流程保存，再重新加载：分析版本与人工填写记录应保留。此步骤仍需主动保存，不是自动保存。
6. 比较两位同岗位、同模型、同企业上下文且材料类型一致的新分析候选人：可看分数，维持原导入顺序。
7. 混入旧档案、旧岗位分析、不同模型或仅部分来源资料：显示具体阻止原因，UI 与导出的 Markdown 都不列比较分数。
8. 取消勾选不一致人选：剩余人选满足条件且至少两位时，允许比较。编辑岗位时旧导出结果不可继续使用。

## 明确边界与下一轮

- 核实记录是招聘人员在客户端填写的协作记录，不是服务端签名证明，不能据此声称材料真实性已经由 Otto 或第三方认证；现有共享岗位权限仍由服务器控制。
- 同口径只说明比较条件一致，不保证材料质量相同、模型判断正确或提供商背后权重永不变化。企业上下文指纹反映分析时采用的内容，不是对企业记忆当前有效性的实时认证。
- 版本检查和人工记录在本地完成，不增加模型调用。用户主动重分析旧档案会产生正常模型费用；来源导入触发旧规则更新也会调用一次模型，不会因为打开比较界面自动重分析。
- 尚未统一手动导入、面试更新等所有入口的去重 / 历史 / 费用机制；配置模型变更后的缓存失效策略还需接入当前模型身份查询。此次不能称为完整的统一分析版本系统。
- 自动保存、候选人粒度并发更新、非管理员首次创建共享岗位仍待下一轮。
- 服务器持续收件 / 获取材料 / 分析调度、真实来源账号验收、真实 PostgreSQL 跨实例测试仍未完成；缓存清理任务不等于持续招聘任务。
- 本轮只统一现有对话证据表述；复杂指代与“比较三人再准备邀请”等组合指令尚未扩展。对外发送仍须人工确认。
- 后续顺序：自动保存与统一分析历史 / 费用控制 → 一个授权来源的服务端持续入档 → 真实账号和 HR 质量 / 耗时评测。
