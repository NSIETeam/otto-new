# 企业星链图 PRD

版本：1.0｜日期：2026-09-08｜项目：Otto｜状态：代码已实现并通过自动化检查；2026-09-09用户确认本次只交付代码，不要求真机验证。详细结果见 docs/research/enterprise-star-map-delivery/implementation-status.md。

本文整合此前产品讨论、Obsidian/Juggl 调研、现有代码检查和北控宏创企业数据调研。用户已明确的方向为约束；此前未逐项确认的交互和参数在本文中收敛为“本版建议”，供评审使用，不表示用户已经逐项批准。未明确标注为后续版本的要求均属于首发范围。

## 1. 功能名、需求描述与概述

**功能名：企业星链图。**

**需求描述：** 园区用户在一张可拖动、缩放、聚焦的企业关系图中，发现园区内有哪些企业、哪些企业与自己同行、各自提供什么产品和服务，并进一步查看公开资料和联系渠道。首发只实现“同行业”连接；通过右上角“连接方式”下拉列表为未来关系类型保留入口。

**概述：** 企业资料分散在名单、介绍和管理页面中，用户不容易发现身边潜在的交流对象。星链图将企业资料组织成可探索的关系网络，帮助用户从“知道一家公司”走向“看到一组值得了解的公司”。视觉和动态参考用户提供的 Obsidian 截图，以小圆点、外置名称、细线和聚焦淡化形成清晰的探索体验。

首发价值是**发现同行、理解业务、找到公开联系入口**。同行业关系只证明分类相同，不证明合作意愿、上下游关系或已有交易。不将这张图包装成合作成功率预测系统。

### 1.1 用户已经明确的方向

| 已明确事项 | 产品约束 |
| --- | --- |
| 喜欢 Obsidian 图谱效果，提供 Juggl 参考 | 浅色自由画布、小点细线、自然布局、节点拖动与邻居聚焦是设计基准。 |
| 先实现同行业 | 首发关系类型为 same_industry，不把已有供需匹配直接改名。 |
| 右上角下拉选择连接机制 | 使用连接方式下拉；不把关系模式藏在复杂设置里。 |
| 不需要点击线解释“两家都是某行业” | 同行业线无点击详情；依据在选择方式及企业行业字段中自然表达。 |
| 复用企业管理 → 企业资料 | 保留一个资料维护来源，不另建重复企业档案。 |
| 默认有北控宏创企业名单，方便演示 | 演示入口自动加载准备好的公开资料样本；正式环境不静默混入演示数据。 |
| 后续 AI 可直接参考 | 附数据、研究、代码入口的绝对路径，并规定字段、导入与验收规则。 |

### 1.2 本版收敛的建议

- 节点默认等大；视图设置另提供“按关联企业数”大小模式。
- 点击企业固定选中并打开右侧资料栏；悬停只做临时聚焦。
- 首发下拉仅“同行业”可用，其他关系类型以“规划中”禁用项展示，不提供空壳功能。
- 统一行业采用单个主营行业编码，原有多个自由标签继续保留；演示使用调研分类，正式企业由有权限的企业资料维护者确认。
- 小行业簇显示全部淡线；大簇仅在聚焦时显示当前企业关联线，所有同行仍能从列表找到。
- 首发目标覆盖 300 家授权企业；1000 家用于压力评估，不先行承诺流畅容量。

以上建议发生变更时应同步更新对应验收项，避免不同 AI 分别采用冲突方案。

## 2. 用户、需求与成功标准

| 角色 | 真实需求 | 成功体验 |
| --- | --- | --- |
| 园区企业普通用户 | 知道园区有哪些同行，理解对方业务 | 找到本企业或感兴趣企业，查看同行并打开资料。 |
| 企业负责人、业务拓展人员 | 找到可进一步沟通的对象 | 根据具体产品和服务判断是否值得联系，取得公开联系渠道。 |
| 企业资料维护者 | 准确展示自己的企业并控制公开范围 | 在现有企业资料中维护行业与介绍，修改后图谱同步。 |
| 园区运营人员 | 演示产业分布和企业发现流程 | 打开就有可追溯样本，可现场搜索、拖动、聚焦企业。 |
| 键盘或辅助技术用户 | 不依赖鼠标和 Canvas 完成查找 | 使用同步企业列表完成搜索、选择和查看详情。 |

首发可用性验收建议：邀请至少 5 位未参与设计的目标用户，至少 4 位能在无口头指导下于 60 秒内找到指定企业并打开一家同行资料；所有参与者在完成任务后均不应将连线理解为“已合作”或将大节点理解为“企业实力更强”。这是待执行的验收目标，不是已有研究结果。

上线后观察：进入图谱后有至少一次企业详情查看的会话占比、同行探索使用率、公开联系渠道操作率、资料行业完成率、错误与空态占比。首版先采集基线，不预设没有依据的商业转化率承诺。

## 4. 现状与改造边界

截至本次本地检查，现有 `EnterpriseStarMapView` 采用固定坐标 SVG：本企业在中心，其余企业按椭圆排列；页面有统计卡、线索强度及选中连线逻辑。当前效果尚不是本 PRD 定义的连续力导交互。

“企业管理 → 企业资料”已有简介、官网、多个行业标签、产品服务、能力、合作需求、公开联系方式及公开开关。服务端会读取公开资料；现有匹配偏向产品、能力与需求文本，并非本 PRD 的标准行业相等规则。

本轮没有读取生产数据库，因此不能断言生产系统“没有真实企业数据”。已确认的是 CSV 已生成，但尚未导入；现有图也尚未完成本次动态 UI 和同行业策略改造。

保留企业身份、园区权限、资料维护入口；替换图形展示与首发关系策略。不要为了演示在正式接口出错时自动回退假企业。

## 5. 信息架构与页面设计

### 5.1 入口与布局

入口沿用园区服务中的企业星链图，沿用现有返回路径。页面层级为：顶部工具栏、主体图画布、可展开企业列表、选中后出现的资料栏。

```text
┌ 返回园区服务   北控宏创科技园 · 企业星链图       [连接方式：同行业 ▾] ┐
│ [搜索企业名称或业务]  [企业列表]       [公开资料演示数据] [视图设置] │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                ○ 企业甲 ───── ○ 企业乙                       │
│                  ╲            ╱                选中后资料栏  │
│                     ○ 企业丙                   企业全称      │
│                                                行业 / 简介   │
│      ○ 独立企业                                产品 / 联系   │
│                                                同行企业列表  │
│ [适配全图] [回到本企业]       当前17家 / 仅聚焦时展示密集关联线 │
└──────────────────────────────────────────────────────────────┘
```

图示只表示结构，不要求固定坐标或固定行业簇形状。默认资料栏关闭，画布占主体可用区域；取消大面积常驻统计卡和线索解释面板。数量与状态用一行轻量信息呈现。

宽度≥1100 CSS px：资料栏建议宽340 px，画布自动重测，不重新布局或自动缩放。宽度768–1099 px：资料栏以右侧覆盖抽屉展示；宽度<768 px：默认企业列表，可切换图谱，详情占满内容区。关闭详情恢复此前画布视角。

### 5.2 视觉基准

| 元素 | 本版设计要求 |
| --- | --- |
| 画布 | 浅色主题以白色或近白为主，深色主题使用现有主题变量；无装饰星空、重渐变。 |
| 企业节点 | 小实心圆，默认中性灰，无大圆内塞字、重阴影；选中使用品牌强调色。 |
| 本企业 | 描边或小标识标注“本企业”；不固定成巨大的中心球。 |
| 名称 | 圆外显示简称；详情始终显示完整主体名。 |
| 连线 | 细直线，约0.5–1 CSS px；同行业无箭头。聚焦线可提升至1–1.5 px。 |
| 行业 | 行业簇附近可显示轻量名称和数量；不是可被误认成公司的额外大节点。 |
| 聚焦 | 当前节点和关联线强调，同行可读，无关节点与线淡化但不突然消失。 |
| 控件 | 右上角连接方式始终可见；图标按钮均有中文名称和键盘焦点。 |

具体颜色使用项目主题 token；次要装饰可低对比，但搜索、工具栏、详情正文与键盘焦点必须可辨认。静态验收对照截图，动态验收必须实际操作，不能只交付静态效果图。

## 6. 功能 F01：企业资料与标准行业

**需求描述：** 用户希望企业在正确的行业中被发现，而不是因任意标签文字被误连。

**相关页面：** 企业管理 → 企业资料；星链图资料栏。

**用户故事：** 作为企业资料维护者，我希望选择一个主营行业并补充业务标签，使同行能找到我，也能看出我的细分业务。

**实现逻辑：** 在现有资料模型上新增标准主营行业字段，复用原有资料，不另建第二套编辑页面。

| 字段 | 规则 |
| --- | --- |
| primaryIndustryCode | 单选，引用稳定行业字典；缺失时为null，不用空字符串建立关系。 |
| primaryIndustryName | 由代码映射，不接受客户端任意代码与名称组合。 |
| industryClassificationBasis | company_selected / researcher_classified_from_public_business / migrated_suggestion。 |
| industryConfirmedByCompany | 企业有权限的维护者明确选择并保存后为true；研究或迁移不得自动设true。 |
| industryTags | 继续保留多个业务标签；旧表单和存储约束保持兼容。 |

**交互细节：**

1. 主营行业为可搜索单选；展示行业名称，必要时附分类说明。没有合适项时允许暂不选择，不强行归到“其他”。
2. 原自由标签、`organizations.industry` 可生成待确认候选，不自动将首个标签当作主营行业。私有政策画像不自动转成公开企业资料。
3. 新增确认行业后不改变原公开开关；修改前若未公开，保存后仍不公开。
4. 已公开但缺少主营行业的旧企业仍能出现在图中，标为“行业待完善”，无同行业连线；本企业维护者可点“完善主营行业”。
5. 普通用户无编辑按钮，看到“请联系企业资料管理员完善”；授权判断沿用已有企业资料权限，由服务端校验，不只依赖前端隐藏。
6. 保存中禁止重复提交；失败保留输入并说明原因；未保存离开时询问是否放弃修改。成功后显示“已保存”，下次刷新或接收资料更新后同步图谱。
7. 正式同行业关系只使用企业确认的行业。调研分类在独立演示范围可用；正式页面显示“行业待确认”时不冒充企业自述。
8. 行业相同但业务标签不同仍为同行；业务标签相同、主营行业不同，首发不连线。

行业字典由应用维护，首发采用版本化字典；不允许普通用户通过输入相似名称生成重复分类。本版演示字典是宽口径产品分类，不宣称属于国家标准。

## 7. 功能 F02：同行业关系与连接方式

**需求描述：** 用户希望明确自己正在用什么标准探索企业，并看到真实符合该标准的对象。

**用户故事：** 作为园区用户，我选择“同行业”后，希望相同行业的企业相连，切换视角时不会看到没有依据的关系。

### 7.1 下拉菜单

右上角控件标签为“连接方式”，当前值“同行业”。点击或键盘打开菜单；选中项有勾选标识，Esc关闭，关闭后焦点返回控件。点击当前项只关闭菜单，不刷新布局。

| 选项 | 用户价值及关系定义 | 首发状态 |
| --- | --- | --- |
| 同行业 | 发现主营行业相同的企业 | 可用，默认。 |
| 供需匹配 | 一方公开需求与另一方公开产品或能力匹配 | 规划中，禁用；不能直接公开未经评估的旧文本策略。 |
| 上下游 | 发现产业链上可提供投入或承接产出的企业 | 规划中，禁用；需要产品或产业链映射证据。 |
| 能力互补 | 找到能补充自身交付能力的企业 | 规划中，禁用；需要可解释能力规则。 |
| 共同服务领域 | 找到服务相同客户领域的企业 | 规划中，禁用；服务领域不等于主营行业。 |
| 已确认合作 | 查看双方同意公开的合作关系 | 规划中，禁用；不能从参会或相同行业推断。 |

禁用项显示“规划中”，不发请求、不跳空页；辅助技术可读状态。首发不提供“全部关系”，避免混合不同语义。后续开放选项时，必须补充独立规则、权限、空态和验收。

### 7.2 关系计算

定义当前账号可见、同园区、有效且主动公开资料的企业集合 U。演示 U 由演示数据提供器定义。企业 A、B 满足以下条件才具有同行业关系：

- A、B 均属于 U，且企业ID不同。
- 两者主营行业代码非空且精确相等，分类版本可兼容。
- 正式数据的行业均已确认；演示数据使用明确标识的调研行业。

关系是无向边，无自环，每一对仅保留一条。边键可由 relationType 与排序后的两个企业ID生成。公司简称、关键词包含、园区同址、共同参加活动都不能替代规则。

n家同行有 n(n−1)/2 条业务关系。首发允许按行业分组传输成员及计算邻居，无须构建全部边对象。节点数量统计不能泄露未授权企业。

### 7.3 关系与画面密度

- 行业簇≤12家：默认画全部淡线。
- 行业簇>12家：默认保留企业与行业分组标识，不画簇内完整网线；悬停或选中企业后展开其全部同行连线。
- 一旦存在聚焦，优先显示焦点直接关联线；密度提示为“密集行业的连线在聚焦企业时显示”。不得显示“暂无关联”。
- 首发300家容量内不得随机漏掉邻居；可对视口外线段做绘制裁剪，业务计数和同行列表保持完整。
- 不用隐藏部分企业构造“最相关同行”假排名；行业成员列表按企业名称稳定排序，以ID作最终去重依据。
- 单一行业模式会形成多个互不相连的行业簇；不补造跨行业线以模仿笔记网络。

## 8. 功能 F03：节点大小、标签和布局

**需求描述：** 图谱应自然、轻盈、容易辨认；视觉大小不能误导用户判断企业实力。

**用户故事：** 我希望拖动一个节点时周围网络有自然响应，停止操作后能安静阅读企业名称。

### 8.1 大小规则

视图设置提供“节点大小：统一 / 按关联企业数”，默认统一。

- 正常显示下统一节点直径建议10 CSS px；命中区域至少24 CSS px，和绘制大小分开。
- 按关联数模式：d为当前连接方式下、当前授权园区完整数据中的业务邻居数，建议直径 `8 + 10 × min(1, sqrt(d / 30))` CSS px，范围8–18。固定比例不因过滤后最大值变化重新归一化。
- 搜索、悬停、只看局部、隐藏边不改变d。关系类型或公开数据实际变化可以更新d与大小。
- 同行业簇内企业具有相同d，大小相同是正确结果；不添加随机大小。
- 设置下方说明“大小表示关联企业数，不代表企业规模或实力”。
- 悬停或选中可短暂放大约15%，作为操作反馈；本企业用描边强调。缩放时节点显示保持可辨范围，避免覆盖文字。

### 8.2 标签规则

默认用经过维护的简称；没有简称时用全称截断显示，建议最多12个可见字符加省略号，按Unicode字素处理。完整名称在悬停提示、搜索列表和详情中提供。

名称优先级：选中企业 > 悬停企业 > 本企业 > 搜索命中 > 选中同行 > 其他企业。缩小或拥挤时隐藏低优先级重叠标签；不隐藏节点本身。无法同时展示所有邻居名称时，完整名单由资料栏提供。无交互状态变化不得不断重新排列标签造成闪烁。

### 8.3 力导与动画

- 初次进入仅在完成必要布局后适配一次；同行自然聚集，簇之间分离，碰撞避免节点重叠。
- 允许布局使用行业吸引约束；布局约束不等同对用户展示的企业关系，行业中心不作为企业节点计数。
- 布局在约2秒内趋于稳定，3秒后应停止持续可见运动。该数值为待测目标。
- 拖动时局部网络跟随，松手后短暂回稳；不永久固定节点，固定位置属于后续功能。
- 平移、缩放、悬停、选中不重置随机种子，不触发全量重排。
- 减少动态效果开启时，取消弹跳和持续过渡，可预计算布局并直接呈现；拖动仍能使用。
- 坐标仅表达可读布局，不将两家公司距离显示为相关度或地理距离。

## 9. 功能 F04：画布探索交互

**相关页面：** 星链图主画布、视图设置、企业资料栏。

| 操作 | 结果及边界 |
| --- | --- |
| 悬停节点 | 临时突出该企业、其同行及直接连线，无关内容淡化；约300ms后可显示完整名称提示。 |
| 离开节点 | 有固定选中则恢复该选中聚焦，否则恢复全图；不刷新数据。 |
| 点击节点 | 固定选中、同步列表、打开资料栏；再次点击同节点保持选中，不意外关闭。 |
| 已选中A时悬停B | 画布临时显示B的邻域，资料栏仍为A；点击B后才切换资料栏。 |
| 点击空白 | 清除选中、关闭资料栏，保持相机位置与搜索条件。 |
| 拖动节点 | 指针移动超过5 CSS px视为拖动；松手不触发点击或自动开详情。 |
| 拖动空白 | 平移画布；拖动后不触发空白点击。 |
| 鼠标滚轮 | 以指针位置缩放；仅当指针位于画布时接管滚轮。 |
| 触控板 | 双指平移、捏合缩放；验证Electron事件兼容，避免同时触发页面滚动。 |
| 放大/缩小按钮 | 提供与手势相同的能力，并有缩放上下限；建议相对初始视角0.25–4倍。 |
| 适配全图 | 适配当前视图范围内全部企业并保留留白；不清空选中或重新计算布局。 |
| 回到本企业 | 本企业可见时平移定位并选中；缺失时按钮禁用，显示原因。 |
| 仅看该企业同行 | 由详情触发，显示该企业及同行，自动适配一次，顶部出现“返回全图”。 |
| 返回全图 | 恢复进入局部前的相机、节点坐标和选中企业；资料变化按最新权限调整。 |
| Esc | 先关闭菜单或提示，再取消选中关闭详情；再次Esc可退出局部视图；不退出应用。 |

“回到本企业”不可用的原因要区分：演示未设置本企业、账号未关联企业、本企业尚未公开或已不在可见数据中。演示默认不给操作员虚构所属企业，不自动把第一家公司当作本企业。

视图设置首发包含：节点大小、显示行业标识、减少动态效果（默认跟随系统）。参数保存在本机当前账号偏好中。拖拽位置和相机仅作会话级缓存；首发不承诺跨设备同步探索视图。

## 10. 功能 F05：搜索与企业列表

**需求描述：** 用户应能有目的地找到企业，而不必在画布中逐个辨认。

**用户故事：** 我记得企业名字的一部分，或想找做某种产品的公司，希望立即看到匹配结果并定位。

1. 搜索框占位：“搜索企业名称或业务”。匹配授权企业的全称、简称、已公开简介、行业标签与产品服务；不检索私有字段。
2. 输入首尾空格忽略，拉丁字符大小写不敏感；中文按文本匹配。首版不承诺拼音、语义推荐或错别字纠正。
3. 输入约200ms后更新结果；优先精确名称、名称包含、其他字段匹配，再按企业名稳定排序。用ID处理同名企业。
4. 搜索只高亮和提供结果列表，不即时删除画布其他节点或改变同行计数。业务命中可在列表显示命中字段摘要。
5. 点击结果或键盘Enter定位并选中企业；若当前局部视图不包含该企业，退出局部并选中，显示轻提示“已返回全图”。
6. 清空查询恢复普通列表，保留当前已选中企业；取消选中由空白点击或Esc完成。
7. 无结果显示“未找到相关企业，试试企业名称或其他业务关键词”，提供清空搜索，不提示导入假企业。
8. 企业列表可独立打开，显示授权企业数、全称、主营行业、本企业标识及必要数据状态。与图同步选择，长列表虚拟化但保留键盘可达性。
9. 无筛选时列表显示当前局部或全图范围；搜索始终检索完整授权集合，并标明“搜索整个园区”。
10. 上下键选择搜索结果，Enter打开，Esc关闭结果层。Canvas外的列表提供与图等价的查看资料及同行探索功能。

## 11. 功能 F06：企业资料与联系

**需求描述：** 用户看到关系后，应能判断企业具体做什么，并自主选择下一步。

**用户故事：** 我点开一个同行，希望看到业务介绍、产品和公开联系方式，而不是只有名称和一条行业解释。

**资料栏从上到下：** 企业全称及关闭按钮、简称/本企业标识、主营行业及分类状态、简介、产品服务、公开能力、公开合作需求、园区相关地址、官网与公开联系方式、同行数量和名单、数据来源（演示）。

- 只展示当前授权公开字段；列表为空时收起对应内容块，核心简介缺失显示“暂未填写企业介绍”。没有合作需求不生成“暂无合作意愿”的判断。
- 演示资料注明“公开资料整理 · 行业为调研分类”，来源区可展开查看来源链接、核查日期和notes；不把日期标作企业最近更新。
- 地址按addressType标为“联系地址”“生产地址”“登记住所”或“园区位置”；缺失楼号不猜测。
- 点击官网在系统浏览器打开http/https链接；不允许javascript等协议。公开电话/邮箱提供复制按钮，成功提示“已复制”，失败提示重试。
- 无联系方式显示“暂未公开联系方式”。不出现不能使用的“立即聊天”“申请合作”按钮；不自动外发消息。
- “同行企业 N 家”不含自身，展示全部可见同行，可滚动；点击其他企业切换选中；提供“仅看同行”。N=0时区分行业缺失、待确认、暂时无其他同行。
- 点击资料栏关闭只取消选中，保留相机与当前局部范围。加载其他企业资料时保持栏宽，避免画布跳动。
- 同名公司在列表和详情用完整主体、行业与公开地址区分，不能只用简称生成身份。

## 12. 功能 F07：北控宏创演示数据

**需求描述：** 演示人员无需现场填表或手工导入，就能展示真实企业公开资料组织成的同行网络。

**用户故事：** 我打开演示版本，希望直接看到北控宏创企业，能顺畅完成搜索、拖拽、同行聚焦和资料介绍。

### 12.1 默认行为

- 演示模式启动时幂等加载本数据集推荐的17家企业，默认连接方式“同行业”，无选中企业，不随机指定本企业。
- 演示图顶部始终显示“公开资料演示数据”，不称“官方完整入驻名录”。
- 正式账号默认读取真实服务；演示从明确的演示入口进入。两种来源切换时清空相机、选择和资料缓存，重新授权/装载，不能混合显示。
- 本次数据共21条：17条推荐企业、3条待核实候选、1条运营方。仅导入 `includeInDemo=true && entityRole==='enterprise'` 为图节点。
- CSV包含13个行业类别，推荐17家实际覆盖10类；其中部分行业只有一家，因此应正常显示孤立点，不能为了满屏连线补造公司。

### 12.2 导入与身份

采用标准CSV解析与UTF-8 BOM处理，JSON数组逐字段解析，布尔显式比较字符串。以 `(dataset='bhc-public-2026-09-08', seedId)` 幂等更新；seedId不是现有organizationId。不得按简称覆盖真实企业。

CSV中isPublic=false表示不能代替企业在正式环境发布资料；独立演示数据提供器可展示推荐样本，或独立演示园区导入时对演示profile显式设true。不得把这一转换用在生产真实企业资料上。

来源、地址类型、核查说明、行业来源保存在旁表或扩展元数据中，不丢弃。cooperationNeeds为空保持为空。未核实官网、联系方式留空，不填测试电话或伪造联系信息。

### 12.3 数据集验收基线

在固定版本数据集上，17家推荐企业应产生11对同行业业务关系：工业自动化与机器人2家产生1对、软件与信息技术服务2家产生1对、电子与通信设备4家产生6对、医疗器械3家产生3对，其余单企业行业产生0对。

该11对是业务规则回归基线，不要求永久在界面展示“11条关系”统计卡。日后数据更新应同步更新基线，不为维持数量修改关系规则。

## 13. 用户旅程

### 13.1 演示人员首次打开

进入明确的演示入口 → 自动读取17家样本 → 看到短暂自然布局与行业簇 → 搜索“国金源富” → 定位并选中 → 查看业务、来源和同行 → 拖动观察网络跟随 → 返回全图。全程不需要登录成任何真实公司负责人，不需要手工填写资料。

### 13.2 正式用户发现本企业同行

进入园区星链图 → 点击“回到本企业” → 高亮本企业及同行 → 点击一家同行 → 查看产品与公开联系方式 → 自主复制联系方式。系统不声称双方已合作，也不自动联系对方。

### 13.3 企业资料不足

进入图谱 → 本企业节点提示行业待完善 → 有权限者点击完善入口 → 在原企业资料页面选择主营行业并保存 → 返回图谱刷新 → 形成同行关系。无权限者仅看到联系管理员提示，不被导入无权访问的编辑页。

### 13.4 用户深入探索

点击一家企业 → 仅看同行 → 查看完整同行列表 → 点击同行切换焦点 → 返回全图恢复原视角。搜索另一行业企业时自动退出局部，用户能理解范围变化。

### 13.5 企业撤回公开

企业维护者关闭公开 → 服务端更新可见集合 → 已打开图谱收到事件或下一次权限刷新 → 企业、关系、列表、详情同步移除 → 若当时选中，显示“该企业资料已不可查看”。不依靠隐藏点但保留可读详情实现撤回。

## 14. 状态、异常和反馈

| 状态 | 页面表现与后续操作 |
| --- | --- |
| 首次加载 | 显示轻量加载占位与“正在加载企业”，不展示空白假图。 |
| 首次网络失败 | 错误说明与重试；不自动装载演示样本。 |
| 授权企业为0 | “园区暂无已公开资料的企业”；有资料权限者可前往完善本企业，无权限者看到说明。 |
| 只有1家企业 | 居中显示单点，可查看详情；“暂未发现其他同行”。 |
| 有企业但无关系 | 保留所有企业，区分单企业行业与行业待完善；不显示加载失败。 |
| 本企业未公开 | 不创建占位假公司节点；轻量提示去原资料页维护，仍可按现有权限浏览其他企业。 |
| 手动刷新 | 保留旧图并提示更新中，禁止重复请求；成功增量更新，不自动适配全图。 |
| 刷新失败 | 普通网络错误保留当前会话图，注明“更新失败，显示上次加载内容”；重试可用。 |
| 401/403或园区授权变化 | 立即清除受影响数据与详情，提示重新登录或无权访问，不能按普通网络错误保留。 |
| 节点已被移除 | 清除其选中与邻接关系，提示资料已不可查看；其余图保持稳定。 |
| 模式加载失败（后续） | 返回最近成功模式和旧图，显示重试，不让下拉显示新模式而图仍为旧模式。 |
| 离线 | 仅保留当前会话已加载内容并标离线；不新建磁盘资料缓存。联网后先重新核权。 |
| 绘图引擎失败 | 提供可用企业列表及重试画布按钮；保留资料探索能力。 |
| 数据超过首发容量 | 服务端明确返回超限状态与总数，切换分页列表/限定行业探索，不静默裁掉企业当作全图。 |

权限变更优先复用现有事件；没有事件时前台至少每30秒重新检查可见数据，窗口恢复焦点立即检查。明确撤权响应必须立即移除，不把30秒当作继续展示许可。普通后台刷新不抢相机，不让用户拖拽途中整图跳动。

## 15. 数据与实现逻辑

### 15.1 领域与展示分层

1. 服务端资料层：组织身份、园区范围、公开开关与标准行业；SQLite与集群实现语义一致。
2. 关系层：relationType、行业分组、完整可见邻居集合及计数，不复用旧供需强度作为同行业评分。
3. 图形适配层：按企业ID建立可变坐标、速度与邻接索引，不修改领域DTO。
4. React界面层：工具栏、搜索、列表、资料栏、权限反馈与可访问性。

### 15.2 建议接口语义（新增设计，非现有事实）

星链图响应保留 parkId、parkName、currentOrganizationId、generatedAt、nodes；增加 relationType、dataSource(real/demo)、taxonomyVersion、industryGroups、unclassifiedNodeIds。节点可附标准行业与来源状态。同行计数由授权组成员计算。

industryGroups建议包含code、name、memberOrganizationIds；不必传输全部两两edges。若现有消费者依赖edges，可通过明确版本或适配保持兼容，不能直接删除字段导致旧界面崩溃。具体DTO命名由实现确定，但权限、计数和关系语义必须符合本文。

### 15.3 状态一致性

- requestId或取消机制防止旧请求覆盖新园区、新模式、新查询结果。
- 当前选中ID与悬停ID分开；临时高亮不能改写固定详情。
- 节点按ID增量合并坐标，删除时清理缓存；无相关变化时不重建力模拟。
- 会话位置按账号、园区、数据来源、关系方式隔离；退出登录清除。缓存位置不能绕过最新可见企业集合。
- 卸载时停止模拟、动画帧、worker（如用）、监听和ResizeObserver；重开不能产生多个并行引擎。
- 行业调整后重新计算受影响组及计数；保留仍存在的选中企业，不强制回中心。

### 15.4 引擎方向

沿用已完成研究：首选用react-force-graph-2d验证Canvas、小点外置标签与连续力模拟；Cytoscape或G6为出现具体阻碍后的备选。Juggl作为交互参考，不直接移植插件代码。该方向是研究建议，不是已完成集成或性能结论。安装前按项目规范核实依赖兼容和许可，详细证据见附录调研文件。

## 16. 非功能要求与验收目标

### 16.1 性能与资源

在实际记录的macOS和Windows参考设备、Electron版本、窗口尺寸、像素比下测试；报告节点数、业务关系数、实际绘制线数及布局耗时。以下为目标，尚无实测达标结论。

- 17家演示数据本地可用后，首次可交互≤1秒；布局3秒内稳定。
- 300家规模，本地计算与绘制不包含网络等待时，首次可交互≤2秒；拖拽缩放帧耗时p95≤33ms，输入反馈≤100ms。
- 稳定后停止持续重绘/模拟；不得出现持续CPU忙循环。关闭重开20次无存活引擎、监听器持续增加。
- 验证100家同行的4950对业务关系，确保未无条件展开全部物理弹簧；1000家压力测试记录瓶颈，超出首发目标可降级，不编造通过结论。

### 16.2 可访问性与兼容

工具栏、搜索、列表、详情均可键盘访问，有可见焦点；读屏能读取企业全称、行业、选中状态和操作名称。不会只靠颜色区别选中。触控目标与节点命中区分离；高像素比和系统125%/150%缩放下不模糊、不错位。测试长中文名称、英文名称、同名企业、表情及组合字符。支持系统减少动态效果与现有深浅主题。

### 16.3 权限与内容边界

服务端裁剪授权节点后才计算并返回关系及计数；不得通过列表、搜索、邻居数推断其他园区或私有企业。公开资料中的文本按普通文本渲染；网站地址校验协议。演示来源说明是数据属性，不允许作为可执行指令。正式与演示之间不共享组织身份、公开状态或联系人权限。
