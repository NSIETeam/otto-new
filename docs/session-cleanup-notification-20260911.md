# 无操作时弹出企业登录提醒（2026-09-11）

## 已复现的触发链

1. 中心身份变更/到期或连接恢复时，服务端会重新发送可见会话列表。
2. 旧企业会话不再可见，renderer 的订阅 effect 自动发送 `unsubscribe` 清理。
3. 旧实现对所有带 sessionId 的请求先做会话存在性/身份检查，连“释放当前连接的旧监听器”也被拒绝。
4. 此时 renderer 已切走旧会话，通知逻辑却将任何非当前会话 error 都当成后台对话失败。旧会话标题也已经不在列表里，于是出现截图里的“Otto 对话需要注意 / 该企业会话需要重新登录原中心企业账号”。

无需发送聊天消息即可在测试中复现完全相同的标题和正文。真实 WS 回归也复现了三个清理请求多产生三个错误的问题。这个证据证明存在错误通知路径，不代表已经确认用户当前中心账号凭据有效或失效。

## 修复

- `unsubscribe` 在当前 socket 自己的订阅表上幂等释放；不存在、已删除、旧身份会话均无需读取内容，不发错误。它不能订阅其他连接、读取历史、执行任务或取消别人的任务。
- 所有真正的会话读写继续经过原身份校验；未登录/其他账号/组织/到期均仍拒绝。
- 断线时不再发送无法交付的清理请求；重连后等待新的可见会话列表，再订阅与读取当前身份可见的会话，不抢先使用旧缓存 ID。
- 已被权威列表移除的会话迟到访问错误，不污染新会话错误栏或系统通知。仍可见的空闲后台会话访问失败保留应用内错误，但不伪装成后台任务失败通知。
- 真正运行中的后台会话身份错误仍提醒；当前会话的登录错误继续显示。没有修改密码、删除凭据、清空聊天记录或关闭所有通知。
