# 交付前收尾、需求验收与反馈基线

本轮在 `internal` 的 `6bef50f` 基础上修改本地源码，不推送、不发布安装包、不部署服务器。保留同工作区正在开发的政策情报功能。

## 已落地的行为

1. **交付前自动收尾**：模型没有继续调用工具时，先检查原生验收与任务图，不立即将本轮写成成功。仍有可核对的条件、至少还有两个模型轮次预算时，给模型一次补齐机会；第二次必须有真实缺项减少，每轮最多两次收尾。没有进展、预算不足、人工验收、权限拒绝、用户取消、后台操作或结果未知时不强行续跑。
2. **收尾权限边界**：只允许已有只读工具、内部计划和已识别的验收命令进入原有执行链；不能在收尾阶段开始新写入或外部动作。命令识别只是额外限制，不是安全授权，仍须经过原有策略和确认。不会自动重放部署、发送消息等操作。
3. **最终输出一致性**：未通过交付闸门的提前完成声明不再作为最终正文发布；继续核对时是普通自然语言过程说明。最终仍未完成时明确列出缺项，工作日志不记录成功。不增加界面模式标签。
4. **验收覆盖**：从当前用户原文提取可识别的列表、表格、复合要求，保留原文锚点。每项验收可用 `requirementQuote` 绑定一条具体要求；一个宽泛的目标引用不能代表多个独立要求均被覆盖。行为型要求不能仅用读取源码的观察证据充当功能验收；人工项不会被模型自动通过。多项变更要求不能靠省略计划绕开核对。
5. **受控重规划**：允许补充更严格的验收、增加依赖；调整依赖须有修订理由，未完成的前置目标不能被移除。旧目标和旧验收仍保留，不能改成更容易通过的命令来消除失败；保存版本与修订记录。取消目标或替换验收含义仍需要正常的用户指令流程。
6. **证据有效期**：原生单文件读取证据可在无关文件写入后保留。使用实际文件身份与真实路径区分同文件别名、硬链接与原子替换；只在成功操作后读取文件元数据，不探测被拒绝的路径。身份未知、相关文件改变时保守失效；进程测试仍保守地在写入后重新核对，不能假定测试没有跨目录依赖。
7. **文件型产物路由**：识别 `生成 result.json` 等明确的输出文件请求，避免本地数据转换因“当前”等词被误要求联网取证；外部写入风险判断没有因此降低。

## 反馈问题复现基线

新增 `feedback-v1`，与原有六个 `office-v1` 合成案例分开管理。八个类别来自用户实际报告，但输入为重建的脱敏数据，不包含真实企业或员工数据：

| 案例             | 独立预期结果                                          |
| ---------------- | ----------------------------------------------------- |
| 已读后退出再进入 | 已读会话保留；最后一条消息、联系人、未读数正确        |
| SQLite 时间      | 无时区 UTC、显式时区、跨年和无效输入正确处理          |
| 删除功能组       | 同组模块一并移除；其他组不受影响，无错误转移          |
| 许可证生效       | configured 与 entitled 均为真才启用，缺字段不默认授权 |
| 多客服回复       | 不漏回复、不覆盖回复人，不混入其他申请人工单          |
| 漏验收           | 过期证据、失败检查、口头“已完成”不能替代当前回执      |
| 修改验收标准     | 允许加强，拒绝删除和同 ID 偷换要求                    |
| 压缩后的目标变更 | 区分有效、暂停、取消；生成摘要不恢复被取消的目标      |

实际运行经过 Otto Config、模型适配器、CoreSessionRuntime 和文件工具。预期结果由固定 Node 验收程序核对；模型不能读取、修改验收程序，也不能执行自写脚本。这里只验证这些问题对应的数据处理任务，不等于完整 Electron UI 或生产后端的端到端验收。

报告包含数据集哈希、当前源码/依赖锁哈希、提交 ID、模型配置标识、重复编号、成功率、正确但未完成的次数、p50/p95 耗时、自动收尾次数、tokens 和可选估算费用。失败请求保留在分母；未知费用是 `null`，不是免费。对比时拒绝不同数据集、模型配置、案例或重复次数集合。

## 运行与对比

在专用进程中通过安全凭据注入提供 `OTTO_EVAL_BASE_URL`、`OTTO_EVAL_API_KEY`、`OTTO_EVAL_MODEL`；不要把密钥写入源码、普通配置或本文件。设置提供方账单上限，使用固定模型版本。

PowerShell 中可设置不含密钥的评测选项：

```powershell
$env:OTTO_LIVE_EVAL = '1'
$env:OTTO_EVAL_DATASET = 'feedback-v1'
$env:OTTO_EVAL_CASES = '8'
$env:OTTO_EVAL_REPEATS = '1'
npx vitest run packages/evals/src/live-runtime.live.test.ts --silent
```

最多八个反馈案例、每例最多三次重复、每批最多 24 次；每例最多十个模型轮次，150 秒时请求取消。提供方不响应取消时仍可能延迟结束，不能把这个时限当作账单硬上限。可以设置 `OTTO_EVAL_INPUT_PER_MILLION` / `OTTO_EVAL_OUTPUT_PER_MILLION` 计算估算费用；不等同于实际账单。

报告写入 `packages/evals/artifacts/live/`（不进入 Git）。下一次设置 `OTTO_EVAL_COMPARE_TO` 为上次报告的绝对路径，会先校验可比性，再按案例与重复编号报告改进和退步。默认不启用 live 时只跳过，不读取现有用户模型凭据、不产生模型费用。

## 验证与尚未证明的事项

- 服务端全量：254 个测试文件通过，1,895 项通过、2 项跳过。
- 场景评测：6 个文件、18 项通过，包含原有对抗/安全矩阵、指标核对及九条回环执行链路（一个办公案例加八个反馈案例）。回环模型是脚本，不是智能水平测量。
- 压缩连续性相关：13 项通过。服务端与 evals 类型检查、Desktop 主进程/预加载/渲染层类型检查通过；服务端构建、变更文件 ESLint、差异空白检查和 code map 检查通过。
- 本轮未调用真实付费模型；还需要指定评测模型与预算，才能形成真实模型成绩及优化前后对比。
- 覆盖检查是结构与证据类型约束，不是完整语义裁判。同一真实测试能否充分覆盖所有业务行为，仍需独立测试设计或人工评审。本轮不能据此声称全部复杂任务都能自主完成，或达到竞品的成功率、时延和成本。
