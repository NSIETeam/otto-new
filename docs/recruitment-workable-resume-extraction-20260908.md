# 智能招聘：Workable 简历附件读取与分析衔接

日期：2026-09-08。目录：`D:/otto/otto-push-20260901`；分支：`internal`。

接续 [Workable 只读适配第一版](recruitment-workable-readonly-adapter-20260908.md)。本轮实现受控附件下载、文字提取、材料版本记录与既有全文分析流程的衔接；不是 Workable 真实账户已接通，也不是六阶段路线全部完成。

## 本轮用户可见的进步

1. 经过授权及来源审核后，Workable 候选人详情中的简历链接可以继续读取，不再只能得到个人摘要。可用的纯文本或文字型 PDF 进入现有候选人工作台和分析流程；对话与模块沿用同一个导入函数。
2. 区分“完整可提取正文”“部分材料”“没有正文”。缺页文字、图片、解析恢复警告等均不标为完整，不调用全文分析模型；下载失败不会覆盖已经保存的候选人档案。
3. 来源材料区显示提取文字、获取时间、附件格式、字节数、PDF 页数、SHA-256 与提取版本。原始附件未托管的限制直接显示在界面中。
4. 正文和岗位分析上下文没有变化时，复用已有分析，不额外调用模型。如果文件字节改变但提取文字相同，则保留旧材料版本和校验信息，仍不重复分析。重复操作依然可能读取平台和下载附件，不是零网络请求。
5. 共享档案恢复校验新增附件元数据检查。原有企业共享岗位保存流程保留；本轮没有把本地材料改成自动云端持久化。未保存修改仍需按界面提示保存。

## 实现与安全边界

- `packages/server/src/modules/recruitment_intelligence/recruitmentResumeReader.ts`：仅接受部署侧明确审核的 HTTPS origin，默认空列表拒绝访问；不接受通配符、裸 IP、其他端口、用户名密码和 URL fragment。签名 URL 不进入返回材料或错误消息。
- 复用既有 MCP 网络层的公网 DNS 校验和固定解析结果连接方式；拒绝私网、回环、云元数据等地址。不自动跟随重定向，不将 Workable OAuth 凭据或 Cookie 转发到附件域名。
- 仅接受完整 HTTP 200 响应，拒绝分段、不一致长度、压缩传输及超过 8 MiB 的内容；边读边校验，超限不截取前半份简历继续分析。下载前后、解析前后再次检查授权。
- `recruitmentResumeExtraction.ts`：首版支持 UTF-8 TXT 与文字型 PDF。PDF 使用独立 Worker、8 秒解析超时、最多 40 页与 80,000 字符上限；不解码图片，关闭 PDF.js 动态求值，遇到恢复警告保守标为部分材料。每进程最多 2 个 PDF 解析工作者，每个读取器最多 8 个下载；超限明确失败，不无限排队。
- 工作线程只隔离执行和限制部分资源，不是操作系统级安全沙箱；V8 堆限制不等于整个进程内存硬上限。公开投递、不可信大规模文件处理上线前仍需容器资源约束及真实文件集安全验收。
- `workableRecruitmentAdapter.ts` 在候选人及岗位范围核对后使用新鲜的 `resume_url`，未配置附件读取器时保持原来的部分资料状态。读取出错不静默降级成“成功获取全文”。
- `createWorkableRecruitmentRegistration` 新增可选 `resume: { approvedOrigins }`。这是部署组合参数，不是让模型或普通用户临时填写任意下载域名的入口。原来的真实账号验收门禁和逐次授权保持不变。
- 文字内容视为候选人材料，继续经过现有身份信息分离后送入招聘模型。模型不自动联系、淘汰或录用候选人。

## 尚未完成

- 真实 Workable OAuth 登录、回调、加密令牌代理、账号/岗位绑定管理与账户联调仍待完成；现有启动配置没有自动启用真实 Workable 访问，默认生产关闭。
- 原始 PDF/TXT 二进制仅在读取时驻留内存，不托管、不生成原件下载链接。本轮保留的是提取文字、文件摘要和历史分析；不能把校验值称为原件已归档。
- 不支持自动 DOC/DOCX 提取、OCR、扫描件全文识别。即使图片只是头像，首版也可能保守标为部分材料，要求补充纯文本简历；不能承诺任意简历一次解析成功。
- 尚未验收真实附件域名、过期签名、平台限流与生产吞吐；没有新接入邮箱、投递页、多平台同步或对外联系。
- 提取器使用仓库已有 `pdf-parse@1.1.4` 中指定的 PDF.js 版本，补为服务端直接生产依赖。依赖升级、安全审计与实际企业发布包启动验收仍应纳入正式上线门禁。
- 附件提取设计在企业服务端执行。Electron 当前瘦身包裁掉了该 PDF.js 版本，不应在桌面本地服务里直接开启这套附件读取器。

## 检查时重点看什么

1. 授权配置未完成时，Workable 仍应显示待授权/验收，而不是“已连接全部人才库”。
2. 在受控测试来源中导入文字简历：来源结果进入同一候选人档案，可查看来源正文并继续分析。
3. 用图片 PDF、损坏文件或授权撤销重试：不能显示完整分析完成，不能破坏旧档案。
4. 同样的简历再次导入：不新增重复候选人、不重复模型分析；字节变了而文字未变时，历史材料仍可回查。
5. 查看“来源材料与版本”：应明确看到原件未托管、材料是否完整、共享保存状态，而不是仅显示内部技术结果。

后续优先完成企业授权代理和账号/岗位绑定，再用真实授权账户验收；原件加密托管、权限与保留期应一并规划，不能先把“首个真实渠道闭环”勾为完成。
