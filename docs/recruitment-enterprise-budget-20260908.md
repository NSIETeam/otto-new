# 招聘下一步：企业后台总额度与持久调用账本

日期：2026-09-08。本轮完成的是第 4 项的**服务器侧第一部分**，不是所有入口已经统一计费，也不是实际 Workable / PostgreSQL 验收通过。

## 用户能检查的改进

1. 在“智能招聘 → 后台接收简历 → 后台分析”中，岗位额度之外新增企业服务器额度快照：快照日期、记录时间、所有后台岗位累计预留次数 / Token、已知输入输出及未知用量次数。它不是实时总账，旧快照不冒充今天的数据。
2. 新版服务器开启付费分析前，必须有企业专属模型授权及企业总额度。缺少配置时明确拒绝，不自动采用无限预算。新客户端不会向旧服务器发送开启许可，暂停旧任务仍然允许。
3. 各岗位仍保留独立限额，同时所有后台岗位受同一企业限额约束。达到企业上限，材料留在待处理箱，次日北京时间再检查；这一拒绝不占岗位调用额度。
4. 相同岗位、共享范围、原始正文、提示词及模型 / 分析版本产生相同任务指纹。待处理编号变化或服务对象重新创建不会自动产生第二次付费调用。不同岗位不会复用彼此的评价，不因为相同姓名或相似脱敏正文合并候选人。
5. 数据库预留与企业计数使用同一次原子比较更新。只有拿到明确许可才调用模型。额度写入回包丢失、调用中断或结果未知时，不返还已预留额度、不自动重发；已知输入输出与未知用量分开记录。
6. 模型完成后，若企业用量回报失败，会保留可用候选人结果并暂停新调用，提示人工核对。不能把数据库失败转换成一次新的模型调用。

## 运维配置与上线边界

新增服务器环境项 `OTTO_RECRUITMENT_ORGANIZATION_BUDGETS`。值示例（只是说明，本轮未设置任何部署配置）：

```json
[{"organizationId":"replace-with-enterprise-id","dailyRequests":10,"dailyReservedTokens":200000}]
```

- 精确匹配企业，不支持通配符；同一企业重复配置、非法数字或缺失配置均不可启用。
- 每企业每天可配置 1–500 次、10000–20000000 预留 Token。示例额度不是建议人民币预算，也不是模型账单估价。
- 预留量沿用现有的提示词 UTF-8 字节数加输出余量估算。它用于保守准入，不代表真实 token 数、厂商限价或人民币硬上限。预留不因已知消耗较小而返还。
- SQLite / PostgreSQL 使用同一个账本协议，实际记录在 `enterprise_recruitment_usage_v1`，内容沿用各宿主的加密能力。多个实例必须连接同一权威数据库；分开的两个数据库不能共享额度。
- **上线前暂停所有旧后台分析进程，完成全部实例升级。** 新账本不追溯升级前费用，不可和不支持该账本的旧实例混跑。核对当天已发生费用后，只配置剩余预留额度，或从次日启用。不要删除账本或恢复陈旧账本来清零额度。
- `recruitment:check` 增加 `organization_budget` 检查；它只检查当前进程配置，不连接数据库或模型、不证明运行环境已经配置完毕。

## 保存、恢复与仍未完成的内容

- 账本只保存加密的调用指纹、编号、状态和计数，不另存简历正文、模型结果、姓名或联系方式。成功任务的去重元数据在后续准入写入时按 30 天窗口压缩；每日统计保留近八个日历日。没有后续写入时不会主动物理清理，不是长期审计报表。
- 结果未知 / 预留未确认的任务记录不会因超时或跨天自动过期为“可重新付费”。最多保留 20000 条元数据，达到上限会暂停，不能通过静默丢弃未知记录腾出额度。本轮没有提供人工清除未知调用的按钮。
- 指纹去重是阻止再次付费，不是自动合并候选人，也不是全量模型结果缓存。重复项会提示原调用编号，需要核对原候选人结果；本轮未实现从账本自动恢复丢失的模型输出。
- **手动上传 / 桌面端自带模型、跨设备手动分析仍未接入这一账本。** 原共享待处理项的手动认领防重复机制保留。未来统一时必须先确认模型、费用和资料共享范围，不能擅自把桌面请求切到企业模型。
- 本地回归使用合成材料、模拟模型响应与 SQLite。PostgreSQL 适配器的 SQL 契约测试不是实际 PostgreSQL 多实例、断网、恢复或重启验收。真实 Workable、批准模型、数据库 / 备份恢复仍待隔离环境与账号就绪。
- 本轮未调用真实模型、未登录或读取真实候选人、未推送或部署。

## 自查操作

在已获准的隔离环境中，将企业总次数设为 1、两个岗位各自次数设为 5。分别放入合成完整简历并开启后台分析，应只发出一个企业模型请求；另一岗位保留材料并提示企业上限。重复触发、重新开启不能重置当天计数。

再在模拟服务里制造超时 / 回包丢失，验证未知请求不自动重发；换一个待处理编号但保持岗位、范围、正文及模型不变，应提示相同任务已有记录。改变真实分析输入时允许新任务，但仍必须通过企业总额度。

真实账号准备与边界另见 [验收工具说明](recruitment-real-account-tools-20260908.md)。

## 本轮验证结果

- 服务端招聘及集群宿主 326 项、桌面招聘 181 项、定向 HTTP 权限 / 能力 1 项，共 508 项测试通过；定向运行跳过的其他 HTTP 测试不计入。
- 服务端与桌面类型检查、服务端构建、桌面渲染构建、改动文件 ESLint、doctor、代码地图检查与 `git diff --check` 通过。
- 新增回归包括 25 个竞争账本实例、跨岗位总上限、企业隔离、跨日与未知请求防重、重复用量回报、写入回包丢失、结算失败保留结果、预算撤销、旧服务器禁止新开启但允许暂停，以及额度快照校验。
- 这些结果证明受测代码路径，不证明实际厂商费用、招聘分析准确率或实际 PostgreSQL 跨进程容灾。
