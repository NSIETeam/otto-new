# 候选审计规则

## 阻断条件

- 没有可访问的源码仓库。
- 没有固定到 40 位 Git 提交哈希。
- 没有可验证的许可证或许可证禁止预期用途。
- 启动命令依赖 shell 拼接、远程管道执行或未固定下载地址。
- 包、仓库和 Registry 元数据的名称/版本无法相互对应。
- 本地 MCP 未完成锁文件、安装脚本、依赖漏洞和无 shell 启动参数审计。

## 至少展示的权限

- 文件：可访问的目录、读写范围、是否能看到整个用户目录。
- 网络：目标域名、监听地址、入站/出站、是否允许任意域名。
- 账号：环境变量名、OAuth scope、是否可写入或删除远端数据。
- 进程：可执行文件、参数、子进程、安装脚本和原生二进制。

## 风险措辞

用证据说明风险，不只给分数。例如：“需要 `GITHUB_TOKEN`，声明包含仓库写权限；首次创建/修改内容前仍需确认。”缺少证据时写“未知”，不要写“安全”。

远程 HTTPS MCP 没有在本机安装依赖时，可以把“本地依赖执行”标记为不适用，但必须明确说明远端服务实现无法由 Otto 本机完整扫描，不能因此写成“服务器安全”。
