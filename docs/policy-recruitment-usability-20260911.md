# 政策服务与智能招聘修复（2026-09-11）

## 状态与边界

本次是本地源码修改，不代表正在运行的 1.9.15 安装版或线上服务器已经更新。没有发布安装包、推送代码、重启生产服务或主机，也没有更改线上模型密钥。线上只做了低频只读排查。

## 政策智能服务

1. 保留顶部唯一的开启/关闭按钮，把必要的数据用途同意改为按钮旁的复选框；删除重复的整块开启面板。单次政策诊断的确认继续保留。
2. 配置写入失败后只用 GET 核对实际状态，不自动重放 POST。核对也失败时禁用再次切换，直到重新读取成功，避免把未知结果误当成关闭/开启失败。
3. 修复企业 HTTP 请求读取：Node `req.complete` 只说明网络接收完成，并不说明缓冲区已消费。此前异步鉴权后可能丢掉整个操作参数。读取仍按 UTF-8 字节数限额，超大、无效 JSON 不予接受，断流不再一直等 end。
4. 全国官方来源移到列表末尾、默认折叠，展开区单独限高滚动。初始加载失败和真正空政策库、筛选无结果分别提示，不再统一显示“0 条政策”；用户不再看到 Electron 的内部错误包装。
5. 前台模型分析增加 `policy_client_model_v1`：客户端从与普通对话相同的配置、认证和模型路由中为每次操作重新取模型；服务端短请求提供必要的官方原文与最小企业资料，客户端调用模型，再把结构化结果送回服务端校验、保存。API Key 不进入企业服务器、请求正文或普通配置文件。
6. 服务端继续执行管理员/租户检查、同意检查、额度限制、条件和原文校验。分析状态为每次操作隔离，不能覆盖另一个企业/用户的模型。任务有效期 210 秒、单个账号一个在途任务、最多 16 次模型交互，超时/失联不自动重放，结果不完整不当成有效评价。

### 发布注意

客户端和单进程企业服务器必须配套更新。旧服务器没有新 capability 时只阻止模型分析并说明升级原因，公共政策、资料和开关接口仍按原有授权工作；不能偷偷改用另一套独立企业模型。

当前执行交换是有界的前台内存任务，不是持久工作队列。多进程 clustered 入口没有宣告此 capability，不能将它当成已经支持跨 worker 恢复；进程重启后任务应视为结果未知，先核对已保存诊断。原有无人值守后台模型配置/授权不在此轮改写范围，也不会借用个人凭据在用户离线时发起付费调用。

只读排查记录显示：政策 actions 曾发生约 1.62 秒的上游连接重置 / 502；企业进程无重启，健康接口成功，独立政策模型环境变量未配置。请求体丢失是已定位并复现的代码缺陷，但没有证据证明它就是该次 TCP 重置的唯一原因。线上 502 仍需在部署候选验证时核实，不能仅凭本地测试宣布消失。

## 智能招聘

1. 功能组市场不再提供八个同页入口的“智能招聘”功能组；模块市场只保留一个 `recruitment-intelligence` / 智能招聘入口。简历、面试、证据、对比、实战与隐私仍在同一个工作台内。
2. 旧官方分组的重复入口合并到“日常办公”；用户自定义分组中的旧快捷入口原地合并去重。原分组里用户额外加入的其他模块保留。迁移只改布局，不访问或删除候选人、材料、历史、授权记录；用户之后主动移除模块不会被重新添加。
3. 分析版本升级为 v3.4，明确要求五个维度使用固定英文 ID，材料不足也必须保留维度并标记待核实；缩短输出要求，减少 JSON 输出不完整。
4. 只对收到的无效 JSON/缺维度/空摘要进行一次结构修正，仍使用同一已选模型、脱敏输入与工具禁用设置。不重放网络失败、未知结果或已变化账号的调用；第二次仍不合格则停止，不伪造缺失维度、证据或得分。
5. 成功修正时两次调用用量合计；任何一次缺少用量时 execution 用量仍为未知，不伪称零消耗。失败结果不缓存成成功。保留材料和重试入口，旧存档错误也经过中文展示层处理。
