# 1.9.15 mirror identity recovery

Before approving formal run `34435105404` (source `130011053bf8a5bf77a4993b65b62651a60651d7`), independent review found that the mirror job's public Release identity vector still contained 14 assets. Draft creation and both publication restagers correctly required 16, including the corresponding-source archive and its checksum. The mirror's exact-count comparison would therefore reject the valid canonical Release after enterprise deployment and canonical publication.

The run was cancelled before its build environment approval. The preserved terminal inventory contains 38 jobs: 19 successful, 17 cancelled, one failed closed after its required attestations were cancelled, and one skipped. Packaging, Windows acceptance, draft creation, publication, deployment and compensation jobs had no execution steps. This was a pre-publication discovery, not an observed production outage. Both temporary OAuth copies were removed and the normal self-review restriction restored.

The production correction is exactly two entries in the mirror job's **public Release identity check**. It does not add files to the mirror payload or change any integrity comparison. Canonical and legacy Releases each retain 16 assets; the mirror retains seven payload files (three installers, three blockmaps and `latest.json`) plus its two private signature/checksum metadata files. No installer size ceiling, source exclusion, approval, provenance or rollback boundary changed.

A regression reads the actual workflow vector and resolves each pattern against the real `buildExpectedDraftIdentity` result from fixture files. The exact set and uniqueness checks reject omissions, duplicates and extra patterns. The same test requires the unchanged mirror-copy set. It failed against the original 14-entry vector and passed after the two-entry correction. Five focused suites passed all 53 cases, including draft/publication recovery and mirror manifest checks. These tests are not installer or production acceptance: the corrected source must still pass fresh CI and a new formal release.
