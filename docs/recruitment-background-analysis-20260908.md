# 招聘下一步：受控的服务端后台分析（2026-09-08）

同日后续：已经补上独立授权的[后台结果自动正式入档](recruitment-auto-archive-20260908.md)。开启后不必逐份手动导入；本文原有手动导入流程仍可在关闭自动入档时使用。真实账号验收仍未完成。

## 本轮交付与检查入口

在上一轮“服务端后台接收 → 共享待处理箱”基础上，接入“显式开启付费分析 → 先预留额度 → 分析 → 查看与导入结果”。不是宣布所有招聘路线已完成，也未连接真实付费模型或完成生产部署。

入口仍为 **智能招聘 → 企业共享岗位 → 后台接收简历**。其中新增独立的“后台分析”，接收授权不代表分析授权。

1. 岗位创建者/企业管理员确认材料处理权限、模型费用和当前岗位共享范围后，设置每日请求次数（1–50）、预留 Token（10000–2000000），再开启。未配置本企业授权模型时，服务器拒绝开启。
2. 服务端每分钟检查，单次最多处理两个岗位，每岗位至多分析一份新完整正文；桌面关闭不影响已启动的服务端任务。不足、未获取正文的材料不自动分析。
3. 本轮输入只有当前岗位与简历。不会偷偷读取企业记忆、面试、实战材料，也不会对外联系、淘汰或录用。常见身份字段被遮盖，但不承诺完全匿名。
4. 待处理箱展示摘要、优势、缺口、维度判断及原文行引用。结论标明“简历自述支持，尚未核实能力”。完整详情可导入工作台后查看。
5. 点击“导入后台结果（不新增模型调用）”，复用原结果的 runId 与用量记录；不再请求模型。会检查岗位、材料、分析规则和模型配置版本。已有面试/实战材料或不同企业标准时，不自动把简历分析冒充联合分析。
6. 出错或中断保留材料及“结果未知”标记；导入未知结果只导入材料，不自动付费重试。先核对厂商账单，再由用户决定是否手动重新分析。

## 费用与权限边界

- 额度是**每岗位每日**，按北京时间换日，多岗位会累加；不是企业总账单限制。手动工作台分析仍走桌面模型设置，不计入本后台任务限额。
- 发请求前使用加密岗位记录的 CAS 原子预留一次调用及 `UTF-8 请求字节数 + 8192` 的保守 Token 额度。额外额度覆盖消息包装和最多 4096 输出 Token。它是准入估计，不是厂商 Token 精确计数或人民币硬上限。
- 已知实际输入/输出与未知次数分开显示；不把没有 usage 的返回当作零。失败、暂停和重新配置不会清空当天已预留额度。最近账目保留约 8 天，不是长期财务账本。
- 同一份待处理材料只自动尝试一次，包括配置改变后。升级规则/模型不会自动重跑全部旧简历、引发额外费用；旧结果仍可回查，重新分析须人工决定。
- 多实例通过同一岗位 CAS 竞争，模型请求之前持久化 pending 和尝试标记。过期 pending 按结果未知处理，不盲目重试。服务停止可能已产生费用，不能声称取消即免费。
- 调用前、结果入档前检查账号、企业、许可证、岗位要求、共享范围和模型路由版本；用户暂停、删除材料、删除岗位优先。已发出请求无法保证厂商端撤回，但晚到结果不能恢复已删除材料。
- 密钥仅从服务端环境/部署秘密管理注入，不放客户端或岗位档案。原文、分析结果和限额在现有岗位加密存储中保存，模型返回不能提交人工核实/招聘决定。

## 服务端配置（本轮没有设置或启用这些项）

部署者需要逐企业确认模型供应商的数据处理约定和端点，再配置：

| 环境项 | 作用 |
| --- | --- |
| `OTTO_RECRUITMENT_BACKGROUND_ANALYSIS_ENABLED=1` | 服务端付费分析总开关，默认不启用 |
| `OTTO_RECRUITMENT_MODEL_ORGANIZATION_IDS` | 精确企业 ID，逗号分隔；不支持通配授权 |
| `OTTO_RECRUITMENT_MODEL_API_URL` | 完整 HTTPS chat-completions 端点，无用户信息、查询参数或重定向 |
| `OTTO_RECRUITMENT_MODEL_API_KEY` | 从部署秘密管理注入，不写入普通配置文件或源码 |
| `OTTO_RECRUITMENT_MODEL` | 企业批准的模型标识 |
| `OTTO_RECRUITMENT_MODEL_APPROVAL` | 部署方模型/数据处理审批版本；变化使旧任务暂停复核 |

传输使用 chat-completions 兼容协议，禁用工具调用，最多 4096 输出 Token、90 秒截止、响应 1 MB 上限，非完整结束不视为成功。实际厂商协议、上下文长度和计费仍需真实验收。调度登记为付费任务，沿用核心付费开关；调度器中的 1 美元为付费门禁保守估值，不是产品报价或实际扣费。

SQLite 与 PostgreSQL 启停路径都接入任务；canary 不启动付费分析。沿用上一轮共享待处理箱的加密 payload 格式，滚动部署前需要全量升级读写该格式的服务器和客户端。不能将旧二进制重新接入新格式数据而不做兼容检查。
