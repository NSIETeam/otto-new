# 智能招聘：跨岗位候选人资料复用与独立进展

日期：2026-09-08。目录：`D:/otto/otto-push-20260901`；分支：`internal`。

本轮接续企业共享岗位档案，完成“同一候选人关联多个岗位、材料可复用、各岗位分别分析和跟进”的一个可验证版本。不是六阶段招聘路线全部完成，也不是 Workable/Ashby 真实账号接入完成。

## 用户可以怎样检查

1. 使用同时支持 `recruitment_jobs_v1` 和 `recruitment_people_v1` 的企业服务器及本轮 Electron 客户端。
2. 在智能招聘中保存两个岗位，分别分配有权参与招聘的 HR/用人负责人。已有旧岗位先使用新版客户端保存一次。
3. 加载来源岗位、选中候选人，展开“关联其他岗位与复用资料”。如果本地有未保存修改，先保存再操作。
4. 点击“选择目标岗位”，选择另一个已保存的岗位，确认有权向该岗位同事共享材料，点击“确认复用到目标岗位”。源工作台保持不变，没有再次调用模型。
5. 加载目标岗位。该人应为“待分析”，保留简历正文、来源、已有面试转写和实战材料；没有旧岗位分数、评价、面试问题或录用决定。按当前目标重新分析后，结果只属于目标岗位。
6. 修改“此岗位进展”为了解中、面试中、待跟进或已结束，保存岗位，另一个授权账号加载后应看到相同进展。其他岗位不跟着变化；外部 ATS 也不会被回写。
7. 点击“查找已有岗位记录”。仅展示可访问岗位中的关联和线索；有后续页时可继续查询。可直接跳到相关岗位查看材料。
8. 如果两个独立导入的档案存在配对联系方式或相同来源记录，可人工核实后关联。不会合并或覆盖两边材料与分析。“关联错人了？”可解除当前岗位关联，不删除材料。
9. 对话中说“查看当前候选人在其他岗位的记录”。它查询同一服务端档案，不调用模型；复用及身份关联仍需到右侧确认。查询未保存资料时会提示先保存。
10. 两位同事同时修改目标岗位，第二位应收到版本冲突。重复复制、撤销任一岗位授权、跨企业访问和到期材料复用均应被阻止。

## 实现与边界

- 服务端为岗位中的候选人分配独立于岗位评价的 `personId`，只允许服务端创建或通过显式关联改变。普通保存忽略客户端伪造的身份关联值。
- 复制产生新的岗位候选人标识，保留同一人物关联；两份岗位材料、评价和进展独立。原岗位历史分析仍留在原岗位，不注入新岗位评价。历史来源材料如被复制，其旧评价与决定清空。
- 同名、单独邮箱或单独手机号均不是自动合并依据。邮箱与手机号同时一致，或材料标注的来源记录一致，只作为人工核对线索；来源一致但联系方式矛盾时提示冲突。材料标注不是平台实名认证证据。
- 目标岗位已有相同人物关联或强匹配线索时阻止再次复制，提示先核对关联，不静默制造重复档案。
- 关联只改变所选目标岗位记录的身份关联，不批量改写该人物在其他岗位的记录。解除关联后，联系方式一致仍可能作为待核对线索出现。
- 来源与目标岗位均须授权且版本一致。目标更新与来源版本条件在同一数据库更新语句中校验；失败不先写入另一份资料。服务器从登录身份确定企业，不信任请求中的组织和管理员字段。
- 档案仍使用既有字段加密存储。关联标识不含姓名或联系方式；审计记录操作账号、岗位和候选人标识，不记录简历全文、手机号、邮箱或令牌。
- 复制继承原授权时间和到期时间，不重置保存期。到期或删除的岗位不能继续用于复制；各岗位现有副本、备份及导出仍按各自保存策略处理。
- 客户端切换账号、候选人或岗位后不应用旧请求结果。有本地未保存修改时禁止跨岗位操作。共享面板的协作者配置绑定岗位和版本，从其他入口切换岗位后必须刷新授权，不能沿用旧岗位协作者。
- 资料查询、复制、关联和人工进展维护本身不调用大模型。用户主动按新岗位重新分析才产生模型费用。

## 仍未包含

- 这版是服务端受控的人物关联加各岗位档案，不是全企业人物主档、全局自动合并系统，也没有跨岗位自动同步材料。普通共享档案保存仍是人工触发。
- 自动关联查询每页检查最多 15 个岗位，带分页游标。它读取已授权的加密岗位档案，尚未实现大规模人物检索索引；万级岗位吞吐不能据此宣称已验收。
- 尚未托管原始 PDF/Word/音视频二进制文件；复用的是已入档的文本、来源和已有材料，不会从第三方平台重新下载。
- Workable/Ashby 的真实授权、平台工具适配验收、邮箱/投递页/推荐入口、服务器持续收件、邀请发送及 ATS 双向同步仍是后续任务。
- 对话本轮增加跨岗位只读查询；不会将一句模糊话自动变成跨岗位资料共享、身份合并或对外联系。
- SQLite 使用真实数据库测试；PostgreSQL 使用适配器 SQL 合同测试，尚未做真实 PostgreSQL 集群并发、故障切换与长时间压力验收。
- 工作区同时有其他任务的未提交修改，本轮不批量暂存、提交或推送，也未部署到真实客户服务器。仓库 Issues 在上一阶段核查时未开放，因此验收记录放在本文件。
