# 拼车最终设计决策（修复第 2 轮）

当前三个阶段均已有实现，具体证据和限制以 [最终自查](final-self-review.md) 为准。用户已取消本轮真机验收要求；代码交付不授权生产开启。

## 配置与权限

`parkCarpoolConfig.ts` 是唯一配置解析入口，配置冻结；两种企业服务器 composition 与 health 使用 `carpoolRuntimeConfig` 启动快照，运行中修改环境变量不会改变部分层行为，修改需重启。测试显式注入启用快照，`NODE_ENV=test` 不享有默认放行。

协议支持 `park_carpool_v1` 与请求/邀请/组能力分开；园区授权仍由真实账号、企业及园区绑定推导。可选试点名单控制当前园区，地图配置和批准设备是依赖就绪状态。`availability.canPublish` 不能代替后端鉴权。暂停新增业务仍保留用户本人的意向、组/会话历史与停止/退出；对他人新候选/预览 fail-closed。缺省关闭会使旧部署的新业务暂停，升级必须显式启用，不能悄悄丢失历史。

## 模型与存储映射

意向存于独立 carpool 表，精确地点与路线字段加密；`routePolylineRef` 的语义由加密 route 承载，不另造无用引用表。活动意向实际状态与 workflow 中正式成员关系共同决定 grouped/paused 展示，不复制第二份成员事实。

请求、组、会话、通知在 workflow 持久记录中事务更新。`coordinatorOrganizationId`、确认人数、剩余容量、角色和成员企业由组/账号关联推导；待处理邀请属于 request，不计入正式成员。会话 member、joinedAt/leftAt/historyVisibleFrom 由 transport 授权代次及成员关系表达。字段名不同不代表语义缺失，但逐字段升级/序列化未独立验收的行已在矩阵留为未验证。

跨企业联系使用独立园区授权和 Native park MLS 群代次；不把企业两人私聊表改成跨企业群表。消息内容只在批准设备解密。加入前/离开后限制同时作用于读取授权与密钥，而非 renderer 过滤。

## 并发与维护

发布幂等键、意向版本及双库事务阻止旧请求复活；正式接收入组时重新校验角色、容量与单组约束。司机/协调人转交必须接受，不能自动选人。

维护每分钟注册运行，单进程防重入；集群租约 120 秒、40 秒续租，Lua 仅允许当前所有者续租。TTL 从请求开始扣减网络延迟；失租与 stop 触发合作式取消。业务通知稳定 ID 去重，后台扫描不计前台候选转化样本。不是跨 Redis/PostgreSQL 的 fencing 协议，不能保证不可逆外部请求全局只执行一次。

## 错误、地图和布局

HTTP 仅返回精确允许的业务错误和受限字段校验文本，未知异常统一安全提示；不靠“消息以地图开头”等宽松前缀放行。高德 key 留服务器；静态地图代理与坐标转换保留，坏响应/坐标/网络错误受控。几何相交算法及 Provider 绕行调用已测，不据 fixture 推断真实路网质量或许可。

保留一次性布局迁移：新增授权的旧园区模块只补一次，用户主动移除后不自动加回；拼车迁移不搬移已有模块、不重排其他组。取消旧的“每次都补齐”行为属于明确升级契约，相关布局测试已覆盖；完整 App 拖拽/移除操作未全部实测。

未扩展支付、叫车订单、导航、车辆认证、跨园区公开目录或组间合并。历史设计见 history，当前文档不再保留“阶段二三未实现”的旧结论。
