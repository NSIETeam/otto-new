## 已落地的部分

1. `liveEvalGate.ts` 在既有真实模型入口发出请求前检查显式启用、模型与声明修订、服务端点、单例预留费用、总预算和计价信息。缺项拒绝运行；不搜索用户账户凭据，不在报告中写入密钥、原始端点或提供商异常正文。
2. `LiveEvalBudget` 在每项任务开始前预留预算。用量或费用未知时保留未结算负债并停止后续请求；超过单项预留时也停止后续任务。**这不能保证正在执行的请求绝不超额**，必须同时设置提供商硬限额；`PROVIDER_CAP_CONFIRMED=1` 是操作者声明，不是远端限额证明。
3. 既有 `eval:live` 数据冒烟入口记录完整源码快照（含未提交源码），使用 TS 源码别名避免读取其他工作区旧 dist，并将依赖环境、预算、声明模型修订和评测代码纳入比较身份。仍明确标为 `data_smoke_not_stage7_end_to_end`，不能冒充 GUI、重启和企业流程测试。
4. `stage7Comparison.ts` 定义成对观察记录和准入规则：来源指纹/实验身份不一致、漏跑、重复记录、未知费用、监测缺失、人工复核缺失均不能通过。禁止项违反后宣告完成也计入错误交付。未运行的版本不计作改进或退步；未完整观测的一次完成率和错误交付率为 `null`，另提供带完整计划分母的“已确认成功率下界”。
5. 人工批准次数、必要澄清次数与纠错/催促次数分别记录。费用及耗时允许未知，不用零代替。具备完整证据的成对任务才比较结果；成本或 P95 延迟增加超过 20% 会阻止试点准入。
6. 即使输入的全部结果通过，也只输出 `manual_pilot_review`，始终 `productionReleaseAllowed=false`。这是报告审查模块，**不是已部署的发布开关**；不会自动发布、切换功能或触碰生产租户。
7. 新增六类共 12 个端到端任务合同，分别是代码修复、文件交付、GUI、重启、运行中纠偏和企业流程。每类两个不同任务，前后各一轮共 24 次预定执行，包含独立判据和负向检查。当前每个合同都明确标记 `adapter: not_implemented`，不把合同登记当成适配器已经可运行。
8. `prepare-agent-live-pair.mjs` 离线校验两份完整快照，记录环境差异和所有未满足条件，生成不可覆盖的准备报告。没有模型调用、安装依赖、应用启动或发布动作。

## 恢复工作时的顺序

1. 确认一个可固定的模型版本、本机或服务商端点和总费用额度。提供商若只有可变别名，不可仅把别名复制到 revision 字段当作固定证明。当前日期/哈希格式检查只证明声明符合格式，`observedProviderRevision` 尚为 `null`，不能证明远端模型未变。
2. 处理依赖差异并建立带原始指纹、变更清单的隔离实验版本。相同工具、数据、评分代码、依赖和预算用于两边；安装依赖和启动 GUI 均只在明确的测试环境进行。
3. 实现上述 12 项适配器：实际编辑/独立隐藏测试、PPT/PDF 解析和点击预览、桌面交互、独立进程重启、纠偏安全点观察、多租户 API 与 UI。模型看不到判分答案；先用脚本故障注入检查采集器，脚本成绩不计入真实模型成绩。
4. 先小额验证端点可用、实际修订和用量能回收，再固定成对任务顺序与实验身份。每次请求受统一批次预算控制，失败、超时、未知用量与未运行都保留在计划中。
5. 保存原生执行证据并进行盲化人工复核。报告模块只验证输入结构和门槛，不能证明导入的 `real_model` 标记、哈希或语义评分真实；必须从实际适配器证据核对，而非由模型自报。
6. 最多 24 次是小样本试点。即使 12 项候选均无错误交付，95% Wilson 上界仍超过 20%；相关任务不满足独立样本假设时不能把该区间当严谨可靠性保证。后续需独立保留任务集、重复样本和人为批准的测试租户灰度，再另行决定生产发布。
