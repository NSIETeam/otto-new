# 企业星链图：Juggl、Obsidian 交互与图谱引擎选型调研

日期：2026-09-08。读者：产品、设计与开发团队。范围：Otto 企业版 React/Electron 园区星链图，首发“同行业”连接，后续支持多种关系。本文是选型研究，不是已经落地的改造或性能验收。

## 1. 决策结论

**以用户提供的 Obsidian 截图作为视觉基准，以 Juggl 的局部探索作为交互参考；首选验证 react-force-graph-2d，Cytoscape.js 作为复杂图操作路线的备选。暂不移植 Juggl 插件。**

判断依据：用户最在意轻量点线、自由画布、拖动时的网络跟随、邻居聚焦和自然布局。react-force-graph-2d 的 React 接入及连续力模拟比较直接；Cytoscape 更适合需要丰富图查询、样式、局部扩展与多布局的产品。本结论是结合目标做出的技术判断，不表示前者在所有规模和场景优于后者。

正式选择前需要在同一批合成企业数据上验证中文标签、稠密行业、稳定布局和 Electron 双端表现。本轮没有把任何候选引擎接入生产代码，没有读取生产企业数据库或测量真实业务帧率。

## 2. 用户已经明确的方向

- 首发按照同行业建立连接，右上角选择“连接方式”。
- 后续可扩展供需、上下游、能力互补、共同服务领域及双方公开确认的合作；只有具备依据和实现的类型才开放。
- 不需要点击同行业连线弹出“A 与 B 都是某行业”的重复说明。
- 喜欢浅色大画布、小实心圆点、外置名称、低对比细线；聚焦时相关连接高亮、其他内容淡化。
- 企业资料复用“企业管理 → 企业资料”，不重复建设资料模块。

尚未定稿：企业节点大小、聚焦后的资料侧栏细节、默认可见连线密度、首发容量。本文给出建议，并不把此前助手建议当成用户已逐项确认。

## 3. Juggl 值得借鉴什么

Juggl 是 Obsidian 的图谱插件，基于 Cytoscape.js。官方定位强调可选择性展开节点，围绕任务保留相关内容，而非强求一次显示全部关系。[Juggl 官方仓库](https://github.com/HEmile/juggl)

值得采用的交互：展开/收起邻居、隐藏节点、固定位置、适配当前邻域，以及保存探索视图。这些可以转化为“探索某家企业及同行”“固定感兴趣的企业”“返回上次查看位置”。环形菜单和多选工作台不是当前首发必要项。[Workspace mode](https://juggl.io/features/workspace-mode/workspace-mode.html)

### 3.1 不应直接移植的原因

1. **不是独立 React UI 组件。** 源码包含 Obsidian 与 Svelte 依赖，以及 Obsidian 数据和插件接口。移植需要拆离笔记系统，再接企业身份、权限和业务数据。[Juggl package.json](https://github.com/HEmile/juggl/blob/main/package.json)
2. **插件全局图有明确规模限制。** 官方建议大笔记库使用 Obsidian 原生图；这是 Juggl 插件的自述，不可外推成“Cytoscape 都不能做大图”。[Global Graph mode](https://juggl.io/features/global-graph-mode.html)
3. **维护节奏较慢。** GitHub 查询显示最新 release 为 1.5.0，发布于 2023-11-10；默认分支最近提交为 2025-02-27，仓库未归档。不能据此断言已废弃，也不应称近期频繁维护。[Release 1.5.0](https://github.com/HEmile/juggl/releases/tag/1.5.0)、[默认分支提交](https://github.com/HEmile/juggl/commit/4c18c9ed009b8074da704ae3053df607f21e66ed)
4. **复用代码与参考交互要区分。** 仓库标 GPL-3.0，官网说明有双重授权可联系作者；商业授权的价格和具体条款本轮未取得。采用独立引擎自行实现可以避免把插件授权及 Obsidian 适配引入当前方案。本报告只记录许可事实，不作具体分发行为的法律判定。[官网授权说明](https://juggl.io/#Implementations_and_licensing)、[LICENSE](https://github.com/HEmile/juggl/blob/main/LICENSE)

### 3.2 “像 Obsidian”不等于使用某个默认布局

Juggl 文档写明默认力导布局是 Cola，并提供更接近 Obsidian 的 D3 选项。因此不能简单把“使用 Cytoscape + fCoSE”称为“复刻 Juggl 默认效果”。[Juggl Layouts](https://juggl.io/features/layouts.html)

原生 Obsidian 官方说明：节点对应笔记，大小随引用该节点的节点数量增加；悬停突出连接，支持平移缩放、文字显示阈值及力参数。它的有向笔记引用与企业同行业无向关系语义不同，大小公式不能不加说明地照搬。[Obsidian Graph view](https://obsidian.md/help/plugins/graph)

### 3.3 网站内嵌图不等于插件运行验证

本轮实际打开 juggl.io，观察到文档、插件演示动图及右侧内嵌关系图。网页 HTML 同时加载 PixiJS 7.4.0、graph-wasm.js、graph-render-worker.js 等脚本；这不足以证明该网站内嵌图就是 Juggl 的 Cytoscape 插件实现。个别脚本源码读取返回 403，未进一步确认其来源和授权。不能把网页右侧图的观感、性能或代码许可冒充插件本体的结论。

## 4. 引擎对比与推荐边界

| 方案 | 已确认能力 | 仍需自己做的部分 | 对 Otto 的适配判断 |
| --- | --- | --- | --- |
| react-force-graph-2d | React 组件、Canvas 2D、力模拟、拖拽平移缩放、hover/click 回调、自定义绘制 | 中文标签密度与避让、邻接高亮状态、布局缓存、企业资料 UI | 当前轻量动态网络首选验证 |
| Cytoscape.js + 布局扩展 | 图查询、样式、交互、多种布局和图操作 | React 生命周期封装、选定布局下的拖拽跟随、业务状态 | 后续复杂图探索的强备选 |
| AntV G6 5 | 图行为体系、力导拖拽、邻居状态、标签适配 | 业务样式、React 实例管理、具体版本 API 适配 | 希望利用较多现成图行为时可选 |
| Sigma.js + Graphology | WebGL 点线、Canvas 标签、图数据/布局分工 | 版本对应的拖拽、布局 worker、业务状态和中文策略 | 数据规模变大时值得评估 |
| 自行组合 D3 + Canvas/PixiJS | 可完全定制模拟与绘制 | 命中检测、相机、交互、标签及资源管理 | 当前无明显必要承担全套自建成本 |

表中“适配判断”为研究推断，非同机基准测试排名。各库默认 demo 风格都不是最终产品皮肤。

### 4.1 首选：react-force-graph-2d

独立 2D 包使用 HTML Canvas，提供交互和自绘接口。`nodeCanvasObject` 可以绘制圆点及外置名称；`onNodeHover` 配合邻接索引实现聚焦；`d3Force`、`d3ReheatSimulation` 与冷却控制用于拖拽、关系更新和停止模拟。默认 tooltip 不等于常驻画布标签。[官方 API](https://github.com/vasturiano/react-force-graph)

本轮打开官方 highlight 示例，实际确认节点邻居高亮及拖动后的网络位置调整。示例使用蓝色节点及较显眼高亮，不代表我们应复制其配色、粗线或粒子效果。[官方高亮示例](https://vasturiano.github.io/react-force-graph/example/highlight/)

实施注意：服务端 DTO 与绘图对象分开，模拟引擎会维护位置和速度；不能每次 hover 都重新创建整张图。按 ID 保留坐标与速度，切换关系只更新必要数据。中文长名称的测量、优先级和重叠处理属于额外实现，不能宣称开箱已有。

### 4.2 Cytoscape：图操作更完整，但需要选对布局

支持邻域查询、样式类、节点拖拽及文字布局，适合从企业扩展相关对象。原生实例可由 React 容器管理；不一定需要额外 React wrapper。官方提供性能建议，强调简化边和标签。[Cytoscape 文档](https://js.cytoscape.org/)

fCoSE 有固定位置约束及增量布局参数；从已有位置启动时可评估 `randomize:false`、`quality:'proof'`、`fit:false`。但 `animate:true` 不保证“拖动一个节点，所有邻居立即持续受力跟随”。如以该手感为核心，需要评估连续布局扩展或单独实现。[fCoSE 参数](https://github.com/iVis-at-Bilkent/cytoscape.js-fcose)

### 4.3 G6：可减少部分通用图行为实现

`drag-element-force` 专门配合 D3 力布局，区别于只移动节点的普通拖拽。`hover-activate` 要显式设置一跳邻居范围；标签适配行为可以作为中文密集标签方案的候选，但仍需真实文字验证。[力导拖拽](https://g6.antv.antgroup.com/manual/behavior/drag-element-force)、[邻居高亮](https://g6.antv.antgroup.com/en/manual/behavior/hover-activate)、[标签适配](https://g6.antv.antgroup.com/en/manual/behavior/auto-adapt-label)

使用时固定 v5 依赖版本，不混用旧版 modes 等示例。对我们目前的小点细线目标，它的更多能力是否值得额外复杂度，需要通过短原型判断。

### 4.4 Sigma：渲染与布局应分别评估

Sigma 的点线与标签分层渲染，Graphology 可配合 ForceAtlas2 worker 完成布局。这适合作为规模扩大后的候选；WebGL 并不自动消除稠密边和大量文字的成本。[Sigma Layers](https://www.sigmajs.org/docs/advanced/layers/)、[ForceAtlas2](https://graphology.github.io/standard-library/layout-forceatlas2.html)

v4 文档展示内置拖拽与力布局配合，但本轮看到的发布版本名称仍是 beta；不能把 v4 能力直接算到 v3 稳定实现上。[v4 drag and drop](https://v4.sigmajs.org/how-to/interactivity/drag-drop/)

## 5. 更重要的约束：同行业连接不等于笔记网络

一个细分类内有 n 家企业，全部两两连接产生 n(n−1)/2 条无向边。这个计算与使用哪种库无关。

| 同行业企业数 | 全部同行业边数 |
| --- | --- |
| 10 | 45 |
| 30 | 435 |
| 100 | 4,950 |
| 300 | 44,850 |

与用户截图中疏密不一、跨主题连接的笔记网络不同，单一主营行业会形成多个互不连接的完全子图。同一行业内企业邻接数相同，角色对称；不能承诺单靠力算法就自动出现同样丰富的中心/边缘结构。

### 5.1 建议分开三层

1. **业务关系：** 所有经确认同行业的企业关系，不因画面优化丢失。
2. **布局约束：** 采用行业聚集力及碰撞避让，可避免为每一对同行都建立物理弹簧；布局吸引不是一条虚构合作关系。
3. **当前绘制：** 小簇可显示全部淡线；较大簇默认显示企业点群及行业标识，悬停/选中时展开该企业所有直接关系。超大邻域通过局部视图、列表和明确计数探索，不静默随机抽样假装完整。

仅把边 opacity 设为零不能保证减少物理模拟成本。大图策略应避免在接口、布局和绘制三个环节都无条件展开完全图。同行业可用分组成员数据计算邻居，无需把所有企业对序列化传输。

### 5.2 避免误导性的布局

不为“好看”虚构跨行业线，也不把彼此不相同的行业强行放进同一关系簇。企业坐标只表达布局，不能宣称空间距离是相关度评分。行业较少或只有几家企业时，显示自然疏散的小网络即可，不加假节点补量。

## 6. 面向 Otto 的视觉与交互建议

以下是设计起点，不是已经验收的固定参数。

| 元素 | 建议 |
| --- | --- |
| 主画布 | 浅色大面积自由画布，取消常驻统计卡和说明列表；资料栏在选中后出现 |
| 节点 | 小实心圆，名称放在圆外；不使用大圆内塞字与重阴影 |
| 默认颜色 | 中性灰为主；行业分组可选择低饱和色，不默认彩虹铺满 |
| 聚焦 | 当前节点与关联线用主题强调色；相关企业文字清晰，无关内容降低透明度 |
| 连线 | 细直线；同行业无方向，关闭箭头和持续流动粒子 |
| 标签 | 缩小时隐藏普通名称，放大逐步显示；优先显示本企业、搜索命中、悬停和选中邻居 |
| 控件 | 右上角连接方式下拉、搜索、视图设置；角落提供适配全图、回到本企业 |
| 动画 | 初次短暂布局，随后停止；拖拽/数据变化时有限重启，尊重减少动态效果设置 |

建议正常缩放下节点直径约 8–18 CSS 像素起步，视觉大小与鼠标命中区域分离。中文名称保留完整详情，画布可按可见字符截断并使用省略号；不按 UTF-16 简单 slice 截断表情或复杂字符。避免所有企业名称默认一直显示导致重叠。

### 6.1 交互状态约定

- 悬停：临时高亮邻居；离开后恢复固定选中状态，不重新布局。
- 点击：固定选中并打开企业资料；资料包含可公开字段，不新增推断信息。
- 拖动：超过拖动阈值才进入拖拽，松手不误触点击。默认允许继续模拟；“固定位置”是独立动作。
- 平移缩放：只改变相机，不刷新关系；保留用户阅读位置。
- 切换关系：保留现存企业坐标、相机与可用的选中企业；加载时保留旧图并注明正在更新，失败不清空图。
- 数据刷新：按 ID 增量更新；企业撤回公开或离园后从图和详情移除，即使本机保留位置也不能继续泄露资料。
- 键盘与可访问性：Canvas 图外提供可搜索企业列表，列表选择与画布同步；支持 Esc 取消、明确焦点和中文读屏名称。

## 7. 节点大小：对前面讨论的修正与建议

Obsidian 的节点大小语义是入链节点数量。同行业是无向关系，可以采用“关联企业数”，但必须明确它只表示连接范围，不代表企业规模或质量。

**首发建议默认统一小节点，视图设置可选择“按关联企业数”。** 这是为避免热门行业内所有企业一齐变大而提出的产品建议，仍需用户定稿。若默认采用度数大小，建议限制直径范围并使用递减增幅，不让差异主导画面。

- 同一主营细分类内大小相同是正确结果，不随机制造变化。
- 度数来自当前关系类型及授权范围的业务关系，不来自当前被画出的少量连线。
- 悬停、缩放或只看局部不重新计算大小，保证稳定；显式切换关系类型才可更新。
- 本企业用描边或标识强调，选中短暂缩放属于操作反馈，不变成业务评分。
- 行业大气泡不再作为默认主画布；行业文字与数量可作为辅助分组标识。

## 8. 现有项目怎样接入

本轮检查未在当前 package.json/package-lock.json 检索到候选图引擎依赖。现有 EnterpriseStarMapView 仍用固定坐标 SVG；无需为换图谱引擎重建企业资料系统。

建议保留：

- 企业公开资料维护入口、公开开关、账号与园区授权。
- 服务端数据来源，SQLite 与集群语义保持一致。
- 统一企业 ID、主题变量、模块入口。

需要新增或调整：

1. 企业资料中的标准主营行业及确认状态；现有自由标签提供候选，不直接把第一项当作主营行业。
2. 独立的同行业关系类型；现有供需 evidence/confidence 不能冒充同行业依据。
3. 服务端按园区提供授权节点、行业分组及必要关系信息；“关系不存在”和“资料不足”分开。
4. 绘图适配层：领域 DTO → 可变图对象；缓存按账号/园区/关系类型隔离。
5. 一个负责 Canvas 生命周期的组件，React 管理工具栏和详情。卸载时停止模拟、销毁实例、解除 ResizeObserver 和事件监听。
6. 浏览器演示与真实服务清晰标识；接口不就绪不能自动以演示企业填充正式星链图。

## 9. 原型验证范围和选型门槛

不需要同时完成四套产品 UI。先用 react-force-graph-2d 做一个可抛弃的小原型；出现具体问题再用同一数据验证 Cytoscape 或 G6，避免为了比较重复实现全部业务。

| 数据/场景 | 必须验证 |
| --- | --- |
| 0、1、3 家企业 | 空态、单点、少量节点不显得故障；不造假数据 |
| 30 家、多个行业 | 小簇的整体观感、聚焦反馈与外置名称 |
| 100 家同一行业 | 4,950 条业务关系下，布局/绘制分离是否有效 |
| 300/1000 家、多行业 | 中文标签、搜索与视图响应；这是测试规模，不是承诺容量 |
| 长企业名称、同名企业 | 截断、详情区分、焦点标签优先、重叠抑制 |
| 拖拽/缩放/反复换关系 | 不误点击、不跳回中心、保留位置、没有重复模拟 |
| 稳定 30 秒、关闭重开 20 次 | 空闲 CPU、内存及事件监听是否合理释放 |
| macOS 与 Windows | 触控板/鼠标滚轮、Retina/缩放、字体、主题、GPU 差异 |
| 撤回公开及身份失效 | 缓存、当前选中详情和画布同步收回 |

记录机器型号、Electron 版本、窗口大小、节点数、业务边数/模拟边数/绘制边数、字体和像素比，再报告布局时间、交互帧耗时与空闲 CPU。现阶段没有测得这些指标，不给出“保证流畅一万家”等数字。

视觉验收以用户两张截图的点线密度、焦点淡化、外置文字和画布占比为参考。动态验收另看真实拖拽跟随，不能用静态截图替代。

## 10. 证据覆盖与研究边界

| 关键判断 | 证据/置信度 | 仍待验证 |
| --- | --- | --- |
| Juggl 使用 Cytoscape、有 Obsidian 耦合 | 官方仓库及 package.json，高 | 移植完整成本未估算，因为不推荐此路线 |
| Juggl 不适合作为大规模全局图的直接承诺 | 官方全局图文档，高 | 实际园区规模下的插件表现未测试 |

| 最合适的首发引擎 | 根据目标推断，中 | 同数据原型验证后定案 |

检索分三轮：第一轮查 Juggl/Obsidian 官方资料和项目接口；第二轮并行核对四种候选的 API、版本、许可和限制；第三轮复查发布元数据、重点 API，并查看官网及官方示例。已获得足以缩小到首选/备选的证据；继续增加库名单不太可能改变当前判断，下一步应转为有明确验收的原型而非继续泛搜。

## 11. 给下一阶段的明确建议

先实现一个“同行业”可交互验证版：复用授权企业资料，小圆点外置中文名称，自然聚集，悬停邻居高亮、无关淡化，点击企业看详情，自由拖拽缩放，右上角连接方式。图谱默认不显示复杂业务说明，不增加尚无依据的跨行业连线。

以 react-force-graph-2d 为首选验证；只有当标签、稠密关系或复杂操作出现实际阻碍，再切换到 Cytoscape/G6。Juggl 保留为交互参考和局部探索案例，暂不移植其插件代码。
