# 智能招聘：本人授权存储、岗位绑定与 HR 权限

日期：2026-09-08。目录：`D:/otto/otto-push-20260901`；分支：`internal`。

接续 [简历附件读取与分析衔接](recruitment-workable-resume-extraction-20260908.md)。本轮完成授权管理基础、企业接口与可见操作入口，不是 OAuth 登录已经完成，也不是 Workable 真实渠道已经上线。

## 用户可以检查的变化

1. “智能招聘 → 候选人来源”增加 **Workable · 本人授权与岗位绑定**。可以刷新本人授权状态；在服务端已经取得并验证本人授权的前提下，选择账号和平台岗位，绑定到当前 Otto 共享岗位。
2. 状态明确区分未授权、已过期、待绑定、已绑定待验收。没有自动选择第一个平台账号，没有粘贴令牌输入框，也没有把部署检查通过写成真实连接成功。
3. 绑定、解除当前绑定、撤销本人全部授权需要人工确认。撤销清除当前企业内本人保存的令牌与所有岗位绑定，不影响同事，不删除已有候选人档案，也不会再次调用模型。
4. 账号或岗位切换后，界面清空旧选项和确认状态，丢弃迟到响应。企业客户端请求同时绑定原服务器、会话令牌和认证代次。
5. 招聘来源接口不再对普通 HR 一律返回“仅管理员”。企业 HTTP 入口接入共享岗位 ACL；HR 必须获得当前岗位权限，真实来源还必须通过其自身授权和部署验收。管理员也不能检索未保存、无效的岗位标识。
6. 来源查询记录仅返回给原查询账号；同事协作应通过已经授权的企业共享候选人档案，而不是读取他人的原始查询记录。
7. 取消授权不依赖仍有共享岗位访问权；可以不选择岗位刷新本人授权并撤销。许可证受限时，本人的授权配置与撤销仍可用，候选人读取接口的许可证门禁不变。

## 实现范围

- `workableConnectionStore.ts`：SQLite 与 PostgreSQL 两种持久化适配。组织 ID 和账号 ID 是复合主键，令牌、平台岗位目录和绑定内容使用既有加密字段能力存储；认证附加数据使用无歧义的组织/账号元组，复制密文到别人的记录无法解密。
- `workableConnections.ts`：每次读取令牌都核对活动企业账号、共享岗位权限、本人有效授权、已验证平台目录和当前绑定。没有全局令牌回退，没有借用管理员或其他同事授权的路径。
- 使用递增修订号和条件写入防止覆盖并发变更；每次重绑改变绑定标识，原 MCP 会话再次校验时失效。撤销保留无令牌的修订记录，迟到的旧授权回调不能恢复授权；重新授权清空原来的绑定。
- `acceptVerifiedGrant` 仅为可信服务端 OAuth 回调预留的接收方法，没有 HTTP 或 IPC 令牌导入路由。调用方必须先验证 OAuth state、PKCE、发起账号、有效期以及平台返回的可选岗位目录，并使用发起授权时的修订号；本方法本身不实现这些 OAuth 步骤。
- `resolveGrant(scope, signal)` 已可接到上一轮的 `createWorkableMcpSessionFactory` / `createWorkableRecruitmentRegistration`，测试验证了绑定改变会使已有会话失效。实际部署仍需把该 broker 明确注入来源运行时，不能保留测试中的固定授权桩。
- `POST /enterprise/recruitment/workable` 和 `recruitment_workable_connections_v1` 能力标识已接入 SQLite / PostgreSQL 企业 HTTP 入口及 Electron main/preload/client。请求主体不能替换登录账号或组织。
- 审计只记录操作类型、修订号与必要作用域，不记录令牌或平台原始响应；写入前必须成功记录审计。写后审计异常会明确失败，界面提示刷新核对实际状态，而不是盲目重放变更。
- 账号隐私注销流程清空该授权表的密文和绑定，保留修订屏障；SQLite 删除账本恢复重放沿用该清理，PostgreSQL 在账号注销事务中清理可选授权表。

## 本轮不包含

- 尚无可用的浏览器 OAuth 登录、动态客户端注册、PKCE 发起/回调、令牌刷新、平台撤销请求或平台岗位目录读取流程。`authorizationAvailable=false` 是真实状态，不是暂时隐藏已完成能力。
- 当前 UI 中不会凭空出现真实平台岗位。只有未来可信授权流程完成并保存已验证目录后，才能选择绑定。受控测试通过服务端方法写入合成授权，不代表用户现在可以登录 Workable。
- 本轮没有真实 Workable 账户、候选人或付费模型调用，也没有对外联系、平台写回或生产发布。上轮原件托管、Word/OCR 等限制仍存在。
- 普通退出 Otto 会话不等于撤销第三方授权。需要撤销时使用本人授权管理；平台侧授权仍需在 Workable 管理。停用企业账号会阻断 broker 的访问，注销则清空保存的授权数据。
- PostgreSQL 测试为 SQL 契约与参数范围测试，不是远端 PostgreSQL 集群验收；没有实际验证平台配额、网络吞吐或生产攻击面。
