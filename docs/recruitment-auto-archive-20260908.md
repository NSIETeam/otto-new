# 智能招聘：后台结果自动正式入档

日期：2026-09-08。范围：补齐已经完成的后台分析到正式候选人档案的最后一步，同时准备真实账号验收。本轮不启用生产任务、不访问真实候选人、不调用付费模型、不推送。

## 用户怎么检查

1. 打开“智能招聘”，保存或加载企业共享岗位，展开“后台接收简历”。
2. 新增“后台结果自动入档”设置。它与“后台接收”“后台分析”分别授权，默认关闭，仅岗位创建者或企业管理员可开启。
3. 选择 7、30 或 90 天窗口，确认当前岗位共享范围，再开启。截止日从本次确认计算；窗口内新档案使用同一截止日，不是在每次入档后重新延长。已存在档案更新时仍沿用原期限。
4. 服务器将当前及随后待处理箱中已完整完成的后台结果建档。新候选人在列表中显示“后台自动建档”；同来源新材料更新显示“后台已更新材料”，保留旧材料、完整分析历史和审计。
5. 待处理项显示建档/更新回执，可点击“查看已入档候选人”。不再需要点击导入或再次保存，入档本身不调用模型。原待处理副本仍按原期限保留，可单独移除。
6. 已由同事修改、已有人工档案、旧材料晚到、分析口径不一致或容量不足时，保留原档案并显示原因。需复核的材料显示在待处理箱计数中，不自动接受模型的招聘决定。
7. 点击“暂停自动入档”后不继续建档；这不等于暂停接收或付费分析，后两者有各自开关。

后台已完成的结果无需桌面在线即可正式入档。**桌面重新启动后仍需加载共享岗位；这轮没有实现自动恢复上次岗位或自动重新确认桌面共享保存。** 加载后即可看到服务器已保存的候选人，不需要逐份导入。已开启的桌面自动保存/刷新仍沿用上一轮机制。

## 实现边界

- 服务端新增独立 `enterprise.recruitment-auto-archive` 零模型费用任务，在 SQLite、PostgreSQL 宿主的常驻任务生命周期中注册；canary 不启动常驻任务。每轮扫描 50 个岗位，最多处理 10 个启用岗位，每岗位一份结果。60 秒是检查间隔，不保证所有积压一分钟内完成。
- 候选人文档、入档回执、来源绑定在同一份加密岗位记录中原子条件写入（CAS）；同时处理不会产生重复正式档案。审计完成写入失败不撤回已保存结果，重试通过回执识别已完成，不再建档或调用模型。
- 调用前后检查操作者企业与角色、许可证、岗位标准、共享范围和有限期授权。岗位删除、暂停、重新配置及同事并发修改通过修订号校验优先于迟到写入。
- 只处理未人工认领、未到期、分析状态完整成功，且当前岗位、正文、规则、模型口径一致的结果。不会把部分材料、旧规则结果、未知请求当作完整分析自动入档。
- 自动匹配只使用同岗位同来源的确切记录标识；不凭姓名合并不同来源的人。Workable 标识还绑定授权与岗位范围；重新授权或更换绑定后的标识可能不同，不能据此承诺跨授权身份自动去重。
- 更新前比较原自动档案的规范化文档指纹。任何人工面试、实战、决定、核实、来源或进展修改都使后台转为“需复核”，不会只保护某几个字段。JSON 对象属性重排不算修改。
- 来源绑定的哈希和已删除档案标识保留至岗位删除，用于阻止自动恢复被删除/到期的档案；不含简历原文。上限 500 条，满后不自动清除删除屏障。
- 最多 100 个候选人，20 个分析版本，单人文档 100 万字符及岗位有效载荷约 5.9 MB。达到限制停止相应自动操作并提示，不自动删旧版本来腾空间。
- “简历自述支持”不等于已经核实能力。不自动创建录用、淘汰、对外消息或已分配负责人任务。待查看/需复核提示不是完整招聘待办系统。
- 保存的是既有提取正文、来源摘要、文件摘要与分析；不是原始 PDF/视频托管。这轮也没有增加备份删除或全量正式档案定时清理。

## 升级与验收

新增能力标记 `recruitment_auto_archive_v1`。旧服务器不会收到桌面端自动入档授权请求。部署需同时升级服务器和桌面端；不能假设旧实例能安全保留新的加密 JSON 字段。回退前暂停任务、备份并验证兼容性，不直接将旧版本接回新数据。

本地新增验证包括：25 个竞争 worker 只创建一份档案；默认关闭与独立授权；岗位/账号/许可变化；有限期授权；人工修改保护、删除不复活；源材料更新保留历史；审计失败恢复；零模型费用任务启停；HTTP 授权与健康能力；服务端文档在桌面真实解析、比较、共享保存再更新；已入档结果拒绝重复导入；旧服务器拒绝授权。

这些检查使用合成材料、模拟模型和本地数据库。真实 Workable、模型账单、PostgreSQL 跨进程故障恢复及招聘效果仍待验收，详见 [真实账号联调清单](recruitment-real-account-checklist-20260908.md)。

本轮最终验证：招聘服务 262 项、桌面招聘 176 项、集群服务器替身回归 41 项、企业 HTTP/常驻任务针对检查 3 项，共 482 个不同测试通过（重复运行不重复计数，过滤跳过不计入）。服务端 TypeScript 构建、桌面 main/preload/renderer 类型检查、renderer 生产构建、相关 ESLint、doctor、代码地图与 diff 空白检查通过。未制作安装包或部署，也没有进行真实账号、实际 PostgreSQL 或招聘判断准确性验收。
