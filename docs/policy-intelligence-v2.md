# 政策智能服务：企业通用版

> 本文保留 v1.1 落地阶段的历史记录。2026-09-03 的 v1.3 增量以 [新版 PRD](Otto-政策智能服务-PRD-v1.3-修订版.md) 和 [改进与验收清单](policy-intelligence-v3-checklist.md) 为准，包括新版能力握手、排除核验、反馈隔离和有限历史复查。

本次以《Otto-政策智能服务-PRD-v1.1-修订版》为依据，优先实现企业通用、地域匹配、可扩展分类与模块/对话共享诊断。不是全国政府网站已经全量接入的声明，也不是 PRD 所有后续能力已交付的声明。

## 产品行为

- 独立的官方常用模块，保留现有添加入口。不要求宏创园区成员身份、园区服务商业授权或园区开关。仍须有效的企业账号及服务端基础使用权限；个人空间不展示。
- 普通企业成员浏览本企业范围内的公共政策；管理员管理开关、企业资料及诊断。默认关闭个性化模型分析。关闭后保留政策和历史，不再发起该企业的新分析。
- 复用本企业现有公开档案中的名称、行业、主营产品/服务；缺少的注册所在地等由用户补充。注册地决定区县、市、省、国家级来源范围，直辖市不重复省/市。资料不明确时只显示确定范围，不猜为北京，不按“园区所在地”覆盖企业注册地。
- 来源覆盖明确显示“已配置”或“尚未接入”。仅配置来源不等于全部政策均已收录。新城市可接入服务端官方来源注册表，无须改界面或重新定义商业模块。
- 默认类别包括资质、人才、项目补贴、税收、活动、融资、就业社保、知识产权、绿色低碳、数字化转型、外贸。模型可以根据正文产生新的多标签分类；采集不依赖上述分类关键词，界面筛选自动纳入新类别。
- 页面按“值得评估 / 提前准备 / 全部政策”组织，支持关键字、级别、类型和申报状态筛选。政策卡片不展示分数或承诺获批。
- 对话可说“有哪些适合我们公司的政策”“完善政策企业资料”“诊断第1项”。对话和页面使用同一企业服务端状态；逐题追问，允许“不确定”，诊断前确认模型数据用途。回答默认保存在本账号诊断；支持的共享字段须另行勾选或确认。
- 诊断采用正文语义分析、逐条原文证据、AND/OR 条件关系及数值校验。缺失资料保持未知，不算作不符合；没有明确有效期不冒充长期有效。政策版本、企业资料和服务开关变化时旧分析失效。
- 材料状态由管理员人工标记，政策正文变化后旧标记不作为新版本已准备依据。资源链接必须来自原文；系统不代用户申报、联系机构或发送企业资料。

## 执行和存储

- 公开采集由企业服务端按北京时间 03:00 / 18:30 的时间槽调度；服务启动后会尝试补跑最近时间槽，不要求桌面客户端在线。客户端打开、关闭只影响界面，不再触发抓取或付费模型调用。
- 定时任务使用共享存储按槽去重。单个详情失效保留同来源其他成功条目，同时显式显示异常；原文暂不可用和未解析的附件不产生资格结论。
- SQLite 与 PostgreSQL 均通过 `enterprise_policy_records_v1` 保存状态；使用既有字段加密、企业标识隔离和账号诊断隔离。新增表自动建表，部署账号须具有相应 DDL 权限。
- 同一诊断和同一企业推荐刷新使用事务租约；未变化结果复用。默认每企业每日最多 24 次分析、每轮最多处理 8 个推荐候选，公共结构化提取每日最多 48 次。失败调用也占用尝试额度，避免故障时无限重试；次数不是精确金额预算。
- 关闭服务会取消当前进程中进行的企业分析，并在写入前重新检查企业状态/资料/账号权限。跨进程的已发出模型请求不能保证撤回，但过时结果拒绝保存。服务停机取消调度和后台请求。
- 旧桌面本地政策状态文件没有删除，也没有静默上传到共享企业数据库。新服务默认重新取得管理员启用和资料共享同意。原桌面采集/模型实现已由服务端版本替代，源码历史可由 Git 恢复。

## 部署配置

桌面端与企业服务端需一并升级。服务端公布 `policy_intelligence_v2` 能力；连接旧服务端时客户端明确提示升级，不假装本地演示结果是真实服务。

| 环境变量                               | 作用                                                           |
| -------------------------------------- | -------------------------------------------------------------- |
| `OTTO_POLICY_MODEL_API_URL`            | 兼容 Chat Completions 的完整 HTTPS 接口地址                    |
| `OTTO_POLICY_MODEL`                    | 模型名称                                                       |
| `OTTO_POLICY_MODEL_API_KEY`            | 服务端注入的密钥，不放入普通配置文件或客户端                   |
| `OTTO_POLICY_SOURCES_FILE`             | 经运营审核的官方来源 JSON 文件绝对路径；不设置时使用随包注册表 |
| `OTTO_POLICY_COLLECTION_ENABLED=false` | 停止服务端自动采集任务                                         |

模型三项未配齐时公共采集仍可运行，个性化分析提示未配置，不伪造诊断。来源配置仅接受 HTTPS、精确官方域名白名单和明确行政区层级，客户端不能提交任意抓取网址。

来源 JSON 是列表。每项须含 `id`、`name`、`listUrl`、`allowedHosts`、`level`、`region`；`level` 取 `national/province/city/district`，地域包含 `country: "CN"` 及适用的 `province/city/district`。区县来源必须有城市，不能只写容易重名的“朝阳区”。域名、路径要经实际采集验收，不能仅凭猜测填入。

## 已验证与边界（2026-09-03）

本地分组回归：政策专项 33 项、企业服务端相关 183 项、客户端政策/模块/工作区 40 项通过。Server 与 Electron main/preload/renderer 类型检查、相关文件 ESLint、renderer/preload 生产构建及 `git diff --check` 通过。这里的并发验证是去重和隔离测试，不是生产容量承诺。

- 单元测试：地区归一化、跨市隔离、新类别、条件 AND/OR、缺失日期、证据引用、数值、显式同意、账号隔离、版本失效、材料状态、加密落盘、事务回滚、定时槽、网页大小/域名限制、部分 404 容错、后台错误脱敏、100 并发去重、取消后的结果拒绝。
- HTTP 集成：没有园区功能的企业可访问；未登录拒绝；普通成员不能通过请求体伪造管理员；异地企业资料隔离；基础授权仍可访问政策接口。
- 页面：真实组件使用明确标注的虚构数据做浏览器验证，检查了类别筛选、条件展开、窄窗无水平溢出。不是生产企业在线数据验收。
- 官方源只读实测：国务院部门文件、北京市科委列表及详情可采集；浦东来源复测保留 8 条正文，另外 1 条失败详情被单独标记。部分官网存在 403、TLS 或失效详情，需要站点适配。未降低 TLS 校验，也未绕过站点访问限制。
- 尚未实测：带付费模型的生产闭环、真实 PostgreSQL 集群并发/故障演练、全国城市和区县覆盖。
- PRD 中尚未完整交付：政策母文/多年度批次的独立关联模型、历史政策每周复核、复杂附件解析、既有消息中心的首次/截止/变更提醒、机构对接质量运营。当前只展示已核实的原文与链接，不给这些能力放空按钮。

部署前必须配置并验证模型、接入目标企业所在地区的官方来源，再使用脱敏企业资料进行端到端验收。本地测试通过不等于现有线上服务器已经升级。
