# 智能招聘：Workable 运行链路与岗位级连接检查

日期：2026-09-08。此记录描述本轮增量，不代表整个招聘路线或真实平台生产验收完成。

## 本轮用户可见变化

- “智能招聘 → 来源 → Workable”增加“检查账号连接（只读）”。先保存或加载企业共享岗位，刷新本人授权，完成浏览器授权并绑定对应的 Workable 已发布岗位，再确认执行检查。
- 检查只发现工具契约、读取本人可访问的平台账号。成功后显示检查时间，并明确标注没有验证候选人、简历读取或生产验收。不调用模型，不联系候选人。
- 来源状态按当前企业、本人及所选岗位计算。切换岗位会重新加载；刷新授权、绑定、解除绑定、撤销授权后同步刷新来源状态。
- 没有简历全文时继续显示“部分资料”，不把个人摘要包装成完整简历分析。

## 修复的实际连接缺口

先前 Workable 授权仓库、MCP 适配器及材料读取器都已存在，但普通企业服务器启动只接受调用方注入的招聘 runtime。本轮为 SQLite 和 PostgreSQL 两种宿主加入默认组合，将本人授权 broker、岗位绑定、只读适配器、既有加密来源存储、审计与材料接口连接起来。已有自定义 runtime 注入仍优先，不覆盖其他连接器。

来源列表和检索授权现在传递 `requisitionId`；HTTP 层在异步检查前后复核岗位权限。桌面列表请求固定发起时的登录会话，登录变化后丢弃旧结果。来源、材料及搜索记录响应禁止缓存。

## 状态与部署边界

四件事互不等价：安装了连接器、本人已授权、当前岗位已绑定、完成真实数据验收。浏览器登录或连接检查不会自动提升为生产可用。

部署参数只由服务器运维在相应验收后配置，本轮没有修改任何真实环境参数：

| 参数 | 含义 |
| --- | --- |
| `OTTO_WORKABLE_OAUTH_ENABLED=1` | 开启浏览器 OAuth 入口，沿用上一轮实现；本身不开放候选人检索 |
| `OTTO_WORKABLE_REAL_ACCOUNT_VERIFIED=1` | 运维确认实际账号验收完成的部署决定；模拟测试不得用于此确认 |
| `OTTO_WORKABLE_AUTHORIZATION_REFERENCE` | 非空授权/验收记录引用；与上一参数同时满足才允许进入本人授权检查 |
| `OTTO_WORKABLE_RESUME_ORIGINS` | 经审核的精确 HTTPS 下载 origin JSON 数组；不猜测域名，不允许通配符、凭据、路径或 IP。未配置时只读取结构化部分资料 |

即使部署批准，访问仍要求有效的本人令牌、企业身份、岗位 ACL 和匹配的绑定；不会借用管理员或同事的令牌。仍只查询绑定岗位中的候选人，不是全站自由文本搜人。真实接口失配时拒绝并提示，不自动改用内部接口或浏览器抓取。

## 本轮检查内容

本轮共验证 588 个不同测试用例：企业主 HTTP 文件 106 项；招聘服务端、集群与仓库/权限回归 279 项（23 个文件）；桌面招聘及相邻会话/客户端回归 203 项（22 个文件）。Core/Server TypeScript 构建、桌面三端类型检查、Preload/Renderer 生产构建、相关 ESLint、doctor、代码地图检查及 `git diff --check` 通过。多次重跑未重复计数。

- 默认服务器能列出“待生产批准”的 Workable，未批准时不访问平台。
- 显式批准的模拟运行按当前岗位检查本人授权；其他岗位、缺少授权及撤销均拒绝。
- 连接检查要求确认和当前修订号，检查过程中重新绑定/撤销不会显示成功；同一用户的并发检查被限制。
- 工具缺失、未知必填参数、授权账号不匹配、取消和不可接受的简历域名均拒绝。
- 真实本机 HTTP + 临时数据库 + 模拟官方 MCP 响应覆盖：绑定 → 只读检查 → 检索 → 加密保存 → 部分资料读取 → 撤销后停止读取。重新创建 runtime 能读取之前保存的搜索记录。
- 桌面组件测试覆盖按钮确认、结果范围说明、岗位/企业切换和授权后来源刷新。不是桌面真实账号演示。
