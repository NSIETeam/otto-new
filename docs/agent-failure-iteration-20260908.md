# 按失败类型迭代与保留任务

## 本次边界

本次只修改评测层，没有修改产品的模型提示词、执行权限或企业服务器。新增的是分类、轮次审查和任务封存工具，不是已经跑出的真实模型收益。首轮真实对照仍为 0/24：固定模型/预算、真实模型隔离执行器及 GUI 等链路尚未就绪。

## 失败如何记录

`packages/evals/src/iterationReview.ts` 使用六类人工确认的根因：

| 内部标识                  | 分类         | 必须附带的依据                 |
| ------------------------- | ------------ | ------------------------------ |
| requirement_omission      | 需求遗漏     | 被漏掉的要求与独立结果检查     |
| wrong_tool                | 工具选择错误 | 实际调用、所需能力与不匹配原因 |
| constraint_false_block    | 约束误拦     | 合法任务范围与实际拒绝回执     |
| insufficient_verification | 验证不足     | 交付声明与独立检查的差异       |
| recovery_duplicate        | 恢复重复     | 接收端计数、幂等键和恢复记录   |
| presentation              | 展示问题     | 实际界面/预览/交互证据         |

分类需要对应到已执行且独立检查失败/违反约束的记录，并引用该记录的证据哈希。未确认分类保留为待分析；不靠错误文本猜测。未运行、超时和供应商错误保留原执行状态，不能硬塞进六个产品根因。

分类允许记录原案例和保留任务的问题，但本轮修复焦点只能绑定原案例的一个已确认问题。保留任务暴露的问题应进入下一轮回归集，不能边调试边继续称它为未见任务。

## 逐轮流程

1. 保存前轮报告与原始结果，登记一个有证据的问题及允许变更的准确文件清单。由受信任控制器在修改前封存，不能由模型完成后补写授权。
2. 仅做针对性修复，生成新的完整源码快照。离线报告入口会从前后快照实际计算新增、删除和修改文件，不信任输入声称的变更列表；任何超范围文件单独列出并阻止进入试点审查。
3. 固定模型、工具、依赖、输入、评分、预算和执行顺序，对相同原案例再次运行。焦点的对应新版记录必须有真实模型结果和独立检查；缺失/超时不算复验成功。
4. 同一对冻结版本另跑未用于调试的保留任务。原案例与保留任务分别报告，不合并一个大成功率。每组仍受已有 24 槽位上限约束，新增保留批次需要另计预算，不能悄悄挤占原 24 次试点。
5. 关键安全反例必须使用当前候选指纹的证据持续通过：不外部打开、不越界写入、不虚假交付、不重复副作用。缺项、旧版结果和任何失败均阻断；如需增加安全项，可追加，不能删除这四项。
6. 成本总额或 P95 延迟增幅超过既有 20% 阈值时，报告始终保留前后值、增幅和原因。原因缺失会额外阻断；填上原因也不会删除原告警或自动放行。

报告继续调用 `compareStage7`，保留所有计划项、失败、超时、未运行和未知用量。模型自称完成不作独立判分依据；脚本模型不能提高真实模型完成率。成本未知不是免费，未观测不是 0 次纠错。

## 命令入口

在仓库根目录执行；以下都是离线控制，不调用模型、不启动产品或生产服务：

```text
node scripts/review-agent-iteration.mjs reserve ABS_TASKS_JSON ABS_CANDIDATE_SNAPSHOT ABS_NEW_DIR
node scripts/review-agent-iteration.mjs expose ABS_RESERVED_DIR EXPERIMENT_SHA256 CANDIDATE_SHA256
node scripts/review-agent-iteration.mjs review ABS_INPUT_JSON ABS_NEW_REPORT_DIR
```

`reserve` 输入含 `tasks`，每项具备 `id/family/request/oracle/critical`。实际执行器必须另行准备，不能把合同当成可执行任务。

`review` 输入含：

- `review`：`IterationInput`，包括两个独立的 `Stage7Plan/records`、相同条件指纹、分类与焦点、保留任务历史、安全观测及性能解释。
- `snapshots.before/after`：完整快照绝对路径。
- `evidenceFiles`：相对于输入文件目录的 `evidence/...` 文件及 SHA-256。每个被引用的证据必须存在且匹配哈希；拒绝越界路径、符号链接和硬链接。

报告入口会核验完整源码、推导实际差异，并将输入与原始证据复制到新目录、独占写入报告与校验值。旧记录不能覆盖；输入中“未修改任何文件”无法隐瞒实际改动。JSON 声明、证据哈希和时间戳本身不等于数据来源可信，仍需受信任执行器和人工 QA。
