# 共享待处理简历：手动与后台分析协调（2026-09-08）

## 本轮解决什么

上一轮实现了受控的服务端后台分析。本轮补上其中一个费用风险：HR 正在从共享待处理箱导入并分析简历时，另一台设备或刚开启的后台任务不能再次处理同一条待处理记录。

范围是**同一企业、同一岗位、同一条共享待处理记录的首次分析**。不是所有上传、岗位和模型的全局去重系统，也不把客户端报告完成当成能力核实或云端结果已保存。

## 可以检查的操作

1. 进入「智能招聘 → 企业共享岗位 → 后台接收简历」，选择完整材料并导入工作台分析。材料权限确认沿用现有工作台授权，不添加新的日常操作步骤。
2. 用另一位已获本岗位权限的同事账号刷新待处理箱。应显示已认领、处理账号、时间和处理状态；再次导入被阻止。此时开启后台分析，也不会重复处理该条记录。
3. 正常完成后，结果仍通过现有候选人档案自动保存流程共享。待处理箱标记“客户端报告已完成”，并提示刷新核对；该标记不能证明共享保存已成功。
4. 断线或客户端退出后，记录不会自动解除认领。超过截止时间，显示结果待核对；先检查原客户端结果、共享保存状态和模型供应商用量。
5. 确有需要时，由岗位创建者或企业管理员打开「重新处理这份材料」，单独确认再次计费风险。未完成的请求必须等截止时间结束；重置绑定当前记录和岗位范围，旧请求不能修改新认领。后台分析已开启时，解除认领可能触发下一轮自动分析，界面明确说明。
6. 保留最多 10 次此前认领记录，不删除已有候选人结果或返还已预留的后台预算。正常补充面试/实战材料的显式分析保留：已有本次认领对应结果时，不要求再次导入待处理记录。

## 实现与失败处理

- 服务器岗位服务新增 claim/start/finish/reset 四个动作，使用现有加密岗位 CAS 更新；手动认领与后台预留竞争同一份岗位记录。不同材料可以分别认领，不覆盖同事的候选人编辑。
- 每次认领绑定企业内账号、岗位、材料、客户端请求、目标候选人、岗位要求及共享范围。认领有效启动窗口为 180 秒，但到期不会自动重新开放付费处理。
- Electron 主进程必须取得认领，再取得一次性的启动许可，才会调用模型。重复启动、旧请求、权限变化、旧岗位、无效响应均拒绝；认领/启动响应丢失时不回退到本地直调模型。
- 模型调用沿用桌面模型配置和短期缓存，增加 90 秒取消信号。中断不保证供应商没有计费；未明确完成就按未知处理，不能自动换执行者重试。
- 完成回报因断网失败时，保留已获得的本地分析，并显示“服务器未确认完成记录”；不为写回状态重跑模型。服务器明确返回权限拒绝、删除、认领冲突或不同岗位要求时，丢弃本次结果，不能把它当作暂时离线。账号切换则丢弃旧响应且不向新账号回报。
- 新客户端要求服务器声明 `recruitment_intake_claims_v1`；旧服务器不支持时停止这条共享分析流程并提示升级。部署需要升级所有相关客户端和 worker，旧客户端或绕过协议的调用不在防重保证内。
- 手动调用不计入后台每日额度；这不是全企业人民币预算上限。认领请求是普通业务接口，不增加模型调用或提示词 Token。

## 验证边界

回归包括多客户端与后台同时竞争、不同材料并行、到期不接替、单次启动许可、岗位/成员变更、未知结果、人工重置、旧回报隔离、无效服务器响应、旧服务器拒绝、独立重置确认、已有结果的后续面试分析。

测试使用合成简历、模拟模型、内存 SQLite 和页面组件测试；没有使用真实候选人、付费模型、Workable 账号或生产数据库。不能据此宣布真实 PostgreSQL 跨实例验收、招聘质量评测或生产上线完成。

本轮验证：服务端招聘模块 28 个文件 / 253 项，桌面招聘 27 个文件 / 172 项；另有 SQLite HTTP 招聘接口 3 项、集群健康能力声明 1 项通过。服务端及桌面类型检查、目标文件 ESLint、服务端构建和桌面完整构建通过；最后的权限拒绝处理修改另行通过桌面主进程构建。doctor、code-map 检查和 diff 空白检查通过。集群测试使用模拟基础设施，不是生产 PostgreSQL 验收。
