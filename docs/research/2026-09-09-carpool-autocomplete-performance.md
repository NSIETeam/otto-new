# 拼车地点联想响应优化

## 修改

- 高德完整地点搜索改为输入提示 API，限定 POI，仅接受具有 ID、名称和有效坐标的地点。API 依据：https://lbs.amap.com/api/webservice/guide/api-advanced/inputtips
- 每个地图适配器实例最多缓存 64 组公共地点建议，成功后有效期 30 秒；关键词和城市共同作为键。在途重复请求合并，失败立即移除，允许重试。不缓存路线和账号数据，权限检查仍在服务层执行。
- 客户端输入防抖从 300ms 缩短为 150ms，保留中文组合输入、明确选择地点和过期响应保护。

## 真实请求测量

2026-09-09，本机直接请求高德，关键词“北京宏创”，未限制城市：

| 请求 | 耗时 |
| --- | --- |
| 原 place/text 第一次 | 3656ms |
| 原 place/text 第二次 | 2442ms |
| inputtips 第一次 | 2419ms |
| inputtips 第二次 | 2389ms |
| 修改后适配器冷请求 | 3598ms，10 个有效地点 |
| 修改后适配器重复请求两次 | 均四舍五入为 0ms，10 个有效地点 |

这些是少量真实样本，不是百分位性能指标，也不是 App 端到端耗时。当前网络下冷请求仍需约 2–4 秒，不能声称已达到首次输入一秒内出结果。相同查询复用和并发请求合并已验证。没有用虚拟地点替代接口结果。

## 验证

- 地图适配器 15 项、拼车服务 13 项、拼车界面 9 项测试通过。
- 覆盖城市隔离、并发合并、失败重试、缓存容量与过期、无坐标候选过滤；界面中文输入、过期结果保护及发布回归通过。
- 未进行 App 人工视觉验收；未重新启动用户正在使用的 App 或本地服务。运行中的服务需重启才能使用新适配器。
