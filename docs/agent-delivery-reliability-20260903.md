# Otto 交付可靠性第二轮改进（2026-09-03）

本轮仅修改本地源码和测试，未提交、推送、发布安装包或操作生产服务器。工作区同时有政策智能相关改动，本轮不覆盖该部分。

## 已实现的行为

1. **需求不串项**：Markdown 表格保留完整行作为原文锚点，同时记录模块、行为和条件。登录与支付的“支持重试”不再合并。行为意图继承到并列名词；以“不要”开始的禁止列表不会将后半截变成待办。仍是保守的结构解析，不是完整自然语言理解。
2. **用例级验收**：行为要求必须绑定命名测试用例及 normal/error/boundary 场景，或者保留为人工验收。显式出现的异常和边界要求不能仅绑定正常场景。不同要求不能拿同一命令的同一用例冒充独立覆盖；同一个测试进程可提供多个不同用例的证据。原生读取完整 TAP 或 Vitest/Jest JSON 报告；跳过、重复命名、截断报告、其他用例和模型自报成功不能满足命名验收。普通构建/静态检查进程回执仍保留，但不替代行为测试。变更和产物任务不能通过省略任务计划绕过这项检查。
3. **受控修复复验**：在原执行预算内，原生检查失败后可重新读取本轮已写过的文件，再进行最多两次局部补丁。仅允许 replace/write_file；新文件、新范围、shell 修复和外部操作不在自动修复范围内。使用真实路径、文件身份及内容指纹检查读取是否过期，权限确认返回后再次核对；仍经过原有策略、确认和审计。修复后的旧测试证据失效，必须复验。超过 2 MB 的文件、链接和未知文件身份不进入自动修复范围。
4. **受控重规划**：正常增加验收项后，可以根据原生新增覆盖/通过证据判断进展，不只看缺项编号是否减少；仍最多两次自动收尾。检查命令本身不可用时，允许替换执行命令，但须保持目标、引用、目录、用例名称和场景不变，具有变更理由、原命令不可用回执及新命令通过相同用例的回执。真实断言失败不能被这种替换掩盖。变更历史记录前后命令及回执 ID；旧失败范围仅在替代验收当前有效时被取代，不能从存档直接恢复这种资格。
5. **保留部分交付**：收尾继续时保存有内容的草稿；最终未完成时保留工作说明、来源和文件链接，明确区分“尚未通过整体验收”和具体缺项。区分权限拒绝、用户取消、人工验收、后台未结束、结果未知等停止原因。只去除独立的笼统完成宣告，不用统一空泛提示覆盖全部成果，也不无依据宣称已经保存文件。

实现入口：`taskRequirements.ts`、`taskContract.ts`、`testCaseEvidence.ts`、`deliveryRepair.ts`、`deliveryClosure.ts`、`incompleteDelivery.ts`、`agentTurnTracker.ts`、`runtime.ts`。

## 评测与 PPT：仅部分完成

报告格式兼容：原检查成功、但输出不可解析时，可以只调整已知报告格式参数（TAP/JSON 等），不能改变执行程序、测试筛选条件、目录或其他参数。新报告仍须提供同一个命名用例的通过回执，并保留变更原因。

- 评测增加错误交付计数、已测量的用户介入次数及无催促成功率。未知数据不当作零。真实模型入口仍默认关闭；本轮没有使用现有用户凭据或发出付费模型请求。
- 原有脱敏数据基线继续使用完整结果的固定 oracle，按需求/场景给出命名报告。各命名检查重复核对完整 JSON 结果，不等同于独立 UI、重启或业务场景测试，不能把报告条目数当作测试充分性的证明。
- 新增真实本地文件的运行链路回归：失败检查 → 重新读取 → 修改 → 再检查 → 交付。模型响应和检查进程回执在这条单元集成测试中由夹具提供，因此不是实际模型的修复能力成绩。
- **尚缺**：真实模型优化前后成绩，以及完整 GUI、应用重启和隔离代码修复任务基线。需要明确模型、费用上限，以及执行生成代码的隔离环境；不能把现有 19 项场景回归称为已完成这些评测。
- PPT 图片预览增加过期和部分页保护：PPT 比图片新、图片集合不完整、超过页数限制或读取期间 PPT 改变时，不将该图片集作为完整当前预览。未绑定的图片明确提示“未校验与当前 PPT 一致”。内容提取预览仍注明不保证字体、版式、图表和动画。
- **尚缺**：PPT 原版式渲染和视觉验收引擎。未自动安装渲染软件、未启动 WPS、未上传文件。已询问是否允许由用户确认后按需下载额外组件，避免默认增大安装包。

## 安全与能力边界

命名用例、场景和真实进程回执证明的是检查执行与绑定，不证明测试断言足够好，也不证明模型完整理解需求。不能据此声称所有任务都能自主完成或达到其他产品的效果。

自动补丁不会自动重放部署、发送、支付等外部动作。权限拒绝、取消、结果未知和人工判断仍会阻止自动收尾。初始检查目录/验收语义的变化不属于自动等效命令替换，需要重新核对范围。

TAP 目前仅接收完整的顶层命名用例；不支持的报告格式会保守地不通过，模型须换用受支持的输出格式，不能用自然语言“通过”替代。
